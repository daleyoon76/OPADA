## 5. 권고를 반영한 뒤 최종 커밋에서 확인할 종료 조건 1개

팀장이 기계적으로 실행할 명령. **세 축을 한 번에 본다** — 정상 실행의 수치 · P0 원장 노출 · 축 소실 감지.

```bash
cd /Users/user/Documents/Dev/Hometest_op && \
npx playwright test tests/screen.spec.js 2>&1 | tee /tmp/gate-full.log >/dev/null; \
npx playwright test tests/screen.spec.js --grep-invert "N4" 2>&1 | tee /tmp/gate-minus-n4.log >/dev/null; \
grep -qE '^10/15 통과' /tmp/gate-full.log \
  && grep -q 'P0-5' /tmp/gate-full.log \
  && grep -q 'P0-6' /tmp/gate-full.log \
  && grep -qE '축에 테스트가 없다.*N4' /tmp/gate-minus-n4.log \
  && echo "GATE-OK" || echo "GATE-FAIL"
```

- `GATE-OK` 조건 넷의 뜻
  1. 정상 실행 요약 줄이 여전히 `10/15 통과` 다 — 붉은 축 5개를 초록으로 «만들지 않았다».
  2. 배너가 `P0-5` 를 이름으로 찍는다 — 축 없는 P0 가 숨지 않는다(P0-1).
  3. 배너가 `P0-6` 을 이름으로 찍는다 — 같은 이유.
  4. **축을 하나 뺀 실행이 붉은 경고를 낸다** — 「커버 Y」가 이제 실측이다(P0-2). 킬러 변이를 종료 조건에 박은 것이다.
- ⚠️ `10/15` 는 이 워킹트리 시점의 값이다. 커밋 전후로 test 를 더하거나 빼면 이 숫자를 함께 갱신해야 한다.
- ⚠️ 요약 줄(`grep -qE '^10/15 통과'`)이 **없으면** 그 실행은 크래시이고 뒤 축은 돌지도 않은 것이다 — `GATE-FAIL` 로 떨어진다.
