## 2. 반드시 답할 질문에 대한 답

### Q1. 처음 여는 사용자의 눈이 가장 먼저 닿는 것은? 체크리스트인가?

**아닙니다. 체크리스트는 네 번째입니다.**

- 캡처 20에서 y좌표 근사: 공고 제목 ≈339 → AI 코치 ≈480 → 상태 카드 ≈600 → **체크리스트 headline ≈733 → 첫 서류명(`인감증명서`) ≈858** `[관측 · 캡처]`.
- 1280×800 노트북 뷰포트라면 fold(800px) 위에 들어오는 것은 headline 한 줄까지이고, **서류명은 한 건도 보이지 않습니다** `[추론 — 전체 페이지 캡처의 좌표를 800px fold에 대입]`.
- 900px 이하에서는 `board-status`·`coach-checks`·`board-layout` 이 전부 1열로 접히므로(`styles.css:1308-1318`) 체크리스트가 더 아래로 밀립니다 `[추론]`.
- 눈이 처음 잡는 것은 히어로 제목(20px) 옆의 **주황 `목적 불일치` 배지**입니다 `[관측 · 캡처]`. 제품의 핵심 전달물이 아니라 「이 공고 안 맞을 수 있음」 경고가 첫 신호입니다.

### Q2. 한 항목의 시각 단위는 몇 겹인가?

**4겹 · 최대 9개 텍스트 조각입니다.** 근거 `app.js:998-1007`.

1. 서류명 `strong`(block, 14px) — `app.js:999`
2. 칩 줄 — `docExtraChips()` 가 `stage · copy · count · validity · method · due` **최대 6개**를 같은 크기·같은 색(soft-blue/blue 12px)으로 나열(`app.js:954-966`, `styles.css:1253-1258`). 캡처 20의 `인감증명서` 행에 실제로 6개가 붙어 한 줄을 가득 채웁니다 `[관측 · 캡처]`
3. 발급처 줄(12px muted, `app.js:1002-1005`, `styles.css:1261-1266`)
4. `원문 근거` details(`app.js:1006`)

**줄일 수 있습니다.** 6개 칩이 전부 동급 무채도라 「기한」과 「부수」가 같은 무게로 읽힙니다. 실제 준비 행동을 가르는 축은 **기한**과 **원본/사본**뿐이고, 나머지 4개는 항목 펼침으로 내려도 손실이 없습니다 `[추론]`.

추가로, 그룹 제목 `h4` 도 **14px bold**(`styles.css:1225-1228`)라 **서류명과 완전히 동급**입니다. 캡처 20에서 `미성년자`(그룹)와 `인감증명서`(서류)가 같은 크기·같은 굵기로 나옵니다 `[관측 · 캡처]`. 계층이 굵기가 아니라 들여쓰기 9px(`styles.css:1239`)로만 표현돼 있어, 스캔할 때 **무엇이 서류명인지 즉시 구분되지 않습니다** `[추론]`.

### Q3. 「미준비 / 준비중 / 완료」 상태 표현이 참고용 성격을 지키면서 진행도를 주는가?

**체크리스트에는 상태 표현 자체가 없습니다.** `[관측 · 코드]`

- `renderDocChecklist()`(`app.js:979-1039`)에는 체크박스도, 상태 배지도, 항목별 상태 클래스도 없습니다. **「체크리스트」라는 이름의 블록에 체크 어포던스가 0개**입니다.
- 체크박스는 전부 `다음 액션`(`task-list`)에 있습니다(`app.js:1252`, `styles.css:765-769`).
- 진행률 `0/1 완료`(캡처 20 `[관측 · 캡처]`)는 `getTaskSummary()` 기준(`app.js:1229, 750`)이라 **서류 건수와 무관**합니다. 화면에는 「서류 5건」과 「0/1 완료」가 동시에 떠 있습니다.
- `sampleNotice.prepItems` 에 `미준비 / 확인 필요 / 공고 확인 / 문의 필요` 4상태가 정의돼 있지만(`app.js:277-378`), `prepItems` 를 참조하는 코드는 **정의부 1곳뿐**입니다. **렌더되지 않는 죽은 데이터**입니다 `[관측 · 코드]`.

참고용 성격 자체는 문구로는 잘 지켜집니다 — headline `…확인하셨습니까?`(`server.py:519`), `이 목록은 참고용입니다…`(`server.py:550`). 「자격이 됩니다」류 표현은 발견하지 못했습니다 `[관측 · 코드]`.

### Q4. 항목이 0개일 때(C형) 화면은 빈칸인가, 안내인가, 거짓 채움인가?

**거짓 채움은 아닙니다. 안내입니다. 그러나 안내가 가리키는 곳이 화면에서 가장 멉니다.**

- `groupsHtml` 이 비면 대체 문장이 나옵니다(`app.js:1023`) + `profile.label` + `profile.detail` + `notes` + `reference`. 캡처 21(B형)에서 문장 5줄이 나온 것을 확인했습니다 `[관측 · 캡처]`.
- 못 뽑은 것을 뽑은 것처럼 보이는 처리는 없습니다. `docChecklistStatusBadge` 가 `attachment_only / not_in_notice / not_found` 를 전부 `warn` 으로 처리합니다(`app.js:947-952`) `[관측 · 코드]`. 이 부분은 pitfall 기준을 통과합니다.
- 문제는 **지시와 대상의 거리**입니다. 화면은 「첨부 공고문을 확인하십시오」라고 말하는데(`server.py:525`), `공고 첨부파일` 은 `support-grid` 안의 **접힌 details**(`index.html:119-122`)이고 캡처 21 기준 y≈1415, 즉 안내 문장에서 **약 680px 아래에 닫힌 채로** 있습니다 `[관측 · 캡처]`.

## 3. 문제 목록

### P0

**P0-1. 「체크리스트」라는 단어가 화면에서 두 대상을 가리킨다**
- 증상: AI 코치 패널이 「아래 체크리스트에서 AI 우선 확인 표시가 붙은 항목부터 처리하세요」라고 말합니다(`app.js:899`). 그 바로 아래에 있는 것은 `#doc-checklist` 인데, **AI 우선 확인 배지는 `task-list` 에만 붙습니다**(`app.js:1258`, `renderTaskAiNudge` `app.js:926-938`). `#doc-checklist` 에는 AI 배지를 붙이는 코드가 없습니다 `[관측 · 코드]`.
- 근거: `src/app.js:899` vs `src/app.js:1258`; `src/index.html:95`(체크리스트) vs `src/index.html:100`(다음 액션).
- 사용자 손해: 지시를 따라 바로 아래 블록을 훑지만 그 표시가 없습니다. 핵심 산출물이 「지시가 빗나간 블록」이 되고, 사용자는 실제 체크 대상을 `다음 액션` 으로 학습합니다.

**P0-2. 서류 항목이 사용자 유형과 연결되지 않아 무관한 조건이 최상단에 온다**
- 증상: 캡처 20에서 사용자 유형이 `개인사업자`인데 첫 그룹 제목이 **`미성년자`**, 그 안이 `인감증명서` 입니다 `[관측 · 캡처]`.
- 근거: `renderDocChecklist()`(`app.js:979-1039`)는 `userType` 을 전혀 읽지 않습니다. 그룹은 추출된 조건 문자열 순서 그대로입니다(`server.py:511-515`). 정렬·필터·강조 로직 없음 `[관측 · 코드]`.
- 사용자 손해: 「간단하게 잘 보인다」의 정반대입니다. 사용자가 첫 줄에서 자기와 무관한 조건을 읽고, 이 목록이 자기 것이 아니라고 판단할 근거를 얻습니다.

**P0-3. B형(표본 13/23)에서 화면이 지시하는 다음 행동이 화면에서 가장 접근하기 어렵다**
- 증상: 「첨부 공고문을 확인하십시오」 문장과 실제 첨부 목록 사이 거리 ≈680px, 대상은 **닫힌 details** `[관측 · 캡처 21]`.
- 근거: `src/index.html:119-122`, `src/styles.css:904-911`, `src/server.py:525`.
- 사용자 손해: 표본 다수(B형 57%)에서 화면의 유일한 유효 행동이 스크롤+펼치기 2단계 뒤에 숨습니다.

**P0-4. 출처 배지의 초록이 추출 결과가 아니라 재산유형만으로 결정된다**
- 증상: `badge(..., profile.code === "A" ? "safe" : "warn")` — **A형이면 추출 실패여도 초록**입니다(`app.js:1017`, `app.js:973` 동일 규칙).
- 근거: `src/app.js:1017`; 초록 정의 `styles.css:1089-1092`.
- 사용자 손해: 「초록 배지 + 못 찾았습니다」 조합이 만들어질 수 있습니다 `[추론 — A형이면서 items 0인 케이스를 실제 공고로 재현하지 못함]`. 초록은 이 제품에서 **금지된 「됐다」 신호**에 가장 가까운 색이고, 참고용 경계를 시각으로 침범합니다.

**P0-5. headline 건수와 화면에 렌더된 항목 수가 어긋난 캡처가 있다**
- 증상: 캡처 20의 headline 은 「서류 **5건**을 찾았습니다」인데, 화면에 렌더된 `li` 는 `인감증명서`·`대리입찰신청서` **2건**입니다 `[관측 · 캡처]`.
- 근거: headline 은 `len(items)` 로 만들고(`server.py:519`), 그룹은 같은 `items` 에서 만들어지므로(`server.py:511-515`) 코드상 5건이면 `li` 5개여야 합니다 `[관측 · 코드]`. 따라서 캡처와 코드가 불일치합니다.

## 4. to-be 시각 구조 1안 — 「체크리스트가 첫 화면의 주인공」

기존 팔레트·토큰·컴포넌트를 그대로 씁니다. 색 팔레트 개편이나 브랜드 변경은 포함하지 않습니다.

### 4.1 순서: 체크리스트를 2층으로 올린다

| 현재 | to-be |
|---|---|
| ① report-hero(5줄) → ② board-coach → ③ board-status → ④ **doc-checklist** → ⑤ 다음 액션/공고 요약 → ⑥ support-grid | ① report-hero(**1줄로 축약**) → ② **doc-checklist** → ③ board-status(진행률) → ④ 다음 액션/공고 요약 → ⑤ board-coach(**여기로 내림**) → ⑥ support-grid |

- 히어로는 「공고 제목 + `마감 D-2`」 한 줄만 남기고, 5줄(`app.js:1207-1215`)은 `공고 요약` 사이드로 흡수합니다. 절감분 약 110px 만으로 첫 서류명이 fold 위로 올라옵니다 `[추론 — 858 → 약 590]`.
- AI 코치를 체크리스트 아래로 내리면 P0-1의 「아래 체크리스트」 지시가 빗나가지 않게 됩니다.

### 4.2 타이포: `.doc-*` 에 16px 계층을 넣는다

| 대상 | 현재 | to-be | 이유 |
|---|---|---|---|
| 패널 headline (`app.js:1019`) | 14px bold(상속) | **20px / 700** | 이 화면의 주 제목 |
| 서류명 (`styles.css:1242`) | 14px bold | **16px / 700** | 사용자가 실제로 찾는 유일한 문자열 |
| 그룹 조건 (`styles.css:1225`) | 14px bold | **12px / 600 / `var(--muted)`** | 서류명 위 라벨로 강등 |
| 칩 (`styles.css:1253`) | 12px, 최대 6개 | 12px, **기본 2개(`기한`·`원본/사본`)만**, 나머지는 항목 펼침 안 | `docExtraChips` 를 기본/상세로 분리 |
| 발급처 (`styles.css:1261`) | 12px 별도 줄 | 12px 유지, **기한 칩과 같은 줄 우측** | 세로 높이 절감 |
| 패널 배경 (`styles.css:1199-1205`) | `#ffffff` / 1px / radius 6px | **`#fbfcfb` + `border-left: 3px solid var(--line)`**, radius 제거 | 히어로·코치와 같은 「주 블록」 형식으로 통일. 새 색 없음 |
| 항목 레일 (`styles.css:1237`) | `2px solid #e5f2ec` | **제거**, 대신 항목 사이 `1px solid var(--line)` | 초록 제거 + 목록 리듬 |

결과: 한 항목의 시각 단위가 **4겹 → 2겹**.

```
[ ] 인감증명서                    기한 입찰마감 전 · 원본     발급처 정부24 ↗
    ▸ 부수·유효기간·제출방법·원문 근거
```

### 4.3 상태: 체크리스트에 「확인함」 체크를 준다

- 항목마다 체크박스. 스타일은 `.task-check input`(`styles.css:765-769`)을 재사용합니다.
- **라벨은 `완료` 가 아니라 `확인함`.** 「준비됨」·「충족」·「자격」 어휘를 쓰지 않습니다.
- 진행률 카드(`app.js:1227-1242`)를 **서류 기준으로** — `서류 5건 중 2건 확인함`. `다음 액션` 진행도와 섞지 않습니다(P1-4).
- 진행바 채움색은 초록(`styles.css:697`) 대신 **중립**. 100%가 되어도 「자격 충족」으로 읽히지 않게.
- 배지는 **패널당 1개**. 출처 배지는 텍스트로 강등하고, 남는 배지 색은 **재산유형이 아니라 `status` 로 결정**합니다(P0-4).
  - `extracted` → 중립 / `attachment_only`·`not_in_notice`·`not_found` → `warn`
  - **`safe`(초록)는 체크리스트 어디에도 쓰지 않습니다.**

### 4.4 A / B / C 세 상태의 표시안

세 형이 **같은 패널 프레임**을 쓰고 본문 슬롯만 바뀝니다.

**A형 — 본문에서 목록 확보 (표본 8/23)**
```

내 유형(개인사업자)에 해당           ← userType 매칭 그룹을 위로
  [ ] 사업자등록증명      기한 …  원본  발급처 홈택스 ↗
  [ ] 인감증명서          기한 …  원본  발급처 정부24 ↗
그 밖의 조건                         ← 미성년자·대리입찰 등은 아래로
  [ ] 대리입찰신청서 …
```
- P0-2 해결: `userType` 으로 그룹을 **정렬**만 합니다(숨기지 않습니다 — 참고용 목록에서 항목을 감추는 것은 위험합니다).

**B형 — 첨부 안에 있음 (표본 13/23 · 가장 흔한 경우)**

  입찰공고문.hwp                내려받기 ↗     이 자리로 인라인 렌더
  물건명세서.pdf                내려받기 ↗

담당기관에 물어볼 문장 복사                  ← 부차 액션
```
- **지시와 대상을 같은 블록에 둡니다.** `#attachment-list`(`index.html:121`)를 이 슬롯에서 함께 렌더.
- **「첨부에 목록이 있을 것」을 항목처럼 렌더하지 않습니다.** 빈 체크박스 자리표시자·스켈레톤 금지(거짓 채움).

**C형 — 원문 어디에도 없음 (표본 2/23)**
```

  담당기관  ○○○ / 전화 ○○○
  [ 물어볼 문장 복사 ]  [ 온비드 원문 열기 ]

- 패널 높이가 A형보다 낮아지는 것 자체가 정직한 신호입니다 — 억지로 높이를 맞추지 않습니다.
