# 2. P0 / P1 / P2

## P0 — 체크리스트 도달을 막거나 거짓으로 말한다

**P0-1. 「8건을 찾았습니다」가 사실이 아니다 (중복·비요구 문장 계수)**
- 증상: 샘플 국유재산 공고 실호출에서 `items=8`, headline 「공고 원문에서 서류 8건을 찾았습니다」.
  실제 원문 요구는 조건당 2종(신청서 1 + 인감증명서 **또는** 본인서명사실확인서 1)이다.
- 근거 [관측] — 실호출 `evidence` 원문:
  - `- 공동입찰자의 인감증명서 또는 본인서명사실확인서` → **2건으로 분리 계수**
  - `※ … 인감증명서(또는 본인서명사실확인서)와 신청서상 날인된 도장의 일치 여부를 확인` → 이 **유의문구**가 세 번째 그룹 `대리입찰 · 공동입찰` 2건을 만든다. 서류를 요구하는 문장이 아닌데 `DOC_REQUEST_RE`(`server.py:302`)의 「제출」에 걸렸다(문장 안 「서류 제출 방식에 의한」).
- 손해: 사용자가 8종을 준비물로 읽는다. 「인감증명서 **또는** 본인서명사실확인서」의 **또는**이 사라져 둘 다 떼러 간다. 발급 비용·이동이 실제로 발생한다.

**P0-2. 단독입찰자에게 필요 없는 8건만 보여준다**
- 증상: 그룹이 `공동입찰` / `대리입찰` / `대리입찰 · 공동입찰` 3개뿐이다. 단독 전자입찰자에게 해당하는 그룹은 0개인데 화면은 8건을 나열한다 [관측].
- 근거: `build_doc_checklist()` 는 조건 축(`conditionKeys`)을 붙여만 두고 필터를 걸지 않는다(`server.py:511-516`). 프론트도 그대로 전부 그린다(`app.js:991-1013`).
- 손해: 「나는 혼자 입찰하는데 이게 다 필요한가」에서 판단이 멈춘다. 목록이 커 보일수록 시작이 늦어진다.

**P0-3. 입력 화면에서 물은 사용자 유형이 서류 목록에 반영되지 않는다**
- 증상: 개인/법인/개인사업자/예비창업자를 첫 화면에서 고르게 해 놓고, 서류 체크리스트는 그 값을 쓰지 않는다.
- 근거 [관측]: `getApplicableTasks()`(`app.js:693-704`)만 `userTypes` 로 거른다. `renderDocChecklist()`(`app.js:979-1039`)에는 `getSelectedUserType()` 호출이 없다. 서버는 `corp`·`person` 조건 축을 이미 갖고 있다(`server.py:320-321`).
- 손해: 사용자는 「내가 법인이라고 답했으니 법인용 목록이 나오겠지」로 읽는다. 실제로는 안 나온다. 답한 것이 버려졌다는 사실을 화면이 말하지 않는다.

**P0-4. 시연에 쓰는 두 공고 모두 서류 0건이다**
- 증상: `to-do.md` 의 시연 URL 2건(비타민스테이션 임대 / 사회복지법인 소해원 매각)을 실호출한 결과 **둘 다 `items: 0`, `status: attachment_only`** [관측].
- 근거: 첨부 6건·1건이 있고 그 안에 목록이 있으나(표본조사 §2 [인용]), 서버는 **첨부를 열지 않는다**. `extract_doc_items()` 는 HTML 섹션 `공고문`·`제출서류`만 본다(`server.py:131`, `412`). `urlopen` 3곳은 공공데이터 API·Gemini·Vertex뿐이고 첨부 다운로드 호출은 없다(`server.py:878/1440/1523`) [관측].
- 손해: 「결국 체크리스트가 잘 보여야 한다」의 그 체크리스트가 **주 시연 경로에서 비어 있다.** 표본 기준 57%가 이 경로다 [인용].

**P0-5. A형에서 「본문에서 찾을 수 있음」 초록 배지가 완결감을 준다**
- 증상: `profile.code == "A"` 이면 배지가 `safe`(초록)로 뜨고(`app.js:1017`, `973`), 「첨부도 확인하십시오」 주석은 **B형에만** 붙는다(`server.py:537`).
- 근거: 표본조사 §2 — 국유재산 5건은 「미성년자 입찰」 서류가 본문에 없고 첨부 PDF에만 있다 [인용].
- 손해: A형 사용자는 첨부를 열지 않고 끝낸다. 미성년자 응찰 건에서 서류 2건을 놓친다.

**P0-6. 재산유형 파싱이 공고상세 URL에서 깨져 A/B/C 안내가 무력화된다**
- 증상: 공고상세 URL 실호출 결과 `assetType: "중메뉴 펼치기 임대"`, `profile: unknown` → 「재산유형으로는 어디에 서류 목록이 있는지 미리 알 수 없습니다」 [관측].
- 근거: `to-do.md` P0-3 은 이 결함을 2026-09-02 수정 완료로 적었으나, 수정은 hidden input `scrnCltrPrptDivNm` 우선 참조이고 그 값이 없는 공고상세 페이지에서는 좌측 내비 라벨을 다시 집는다 [관측 + 추론].
- 손해: 이 앱이 가진 **가장 값싼 정직함**(「이 유형은 첨부를 봐야 합니다」를 첨부 열기 전에 미리 말해 주는 것)이 꺼진다. 화면 hero 에도 「중메뉴 펼치기 임대」가 그대로 나온다(`app.js:1209`).

## P1 — 도달은 하지만 늦거나 흐려진다

**P1-1. 체크리스트가 보드의 4번째 블록이다.** hero → AI 코치 → 상태 카드 → 체크리스트 (`index.html:92-95`). 목적이 하나뿐인 제품에서 목적물이 4번째다. [관측]

**P1-2. 「체크리스트」가 두 개다.** 체크박스가 붙은 것은 서류가 아니라 확인 항목 5건(`server.py:1085-1148`)이고, 서류 목록은 체크가 안 된다(`app.js:991-1013`). 진행률 `0/5` 도 서류 준비율이 아니다(`app.js:740-747`). 사용자는 서류를 하나씩 지워 나갈 곳이 없다. [관측]

**P1-3. 「준비 보드 만들기」 버튼과 「준비 보드」 탭이 같은 문이다.** `setView("report")` 가 조건 충족 시 `boardGenerated` 를 세우므로 버튼은 필수가 아니다(`app.js:464-468` vs `1545-1553`). 분석 성공 후 자동 이동도 하지 않고 결과 패널로 스크롤만 한다(`app.js:1505`). 클릭 1회가 순수 손실이다. [관측]

**P1-4. 첨부파일이 접힌 서랍의 6개 중 1번째다.** B형에서 정답이 있는 자리인데 `공고 첨부파일 / 공고문 항목 보기 / 용어 안내 / 마감·비용 요약 / 질문 모음 / 근거와 안전 경계` 와 같은 계층이다(`index.html:118-143`). 「첨부 공고문을 확인하십시오」라고 말해 놓고 그 첨부를 접어 둔다. [관측]

**P1-5. 「AI가 빈칸을 찾았다」가 여전히 4곳이다.** 입력화면 `renderAiReadySummary`(`app.js:914`) · 보드 코치 패널(`app.js:874`) · 상태 카드 「AI 우선 액션」(`app.js:1228`) · 항목별 `task-ai-nudge`(`app.js:926`). 2026-08-08 감사 P1-2 **미해소 승계**. [관측]

**P1-6. 공고 유형이 3곳에서 반복된다.** `preview-grid`(`app.js:857`) · `report-hero`(`app.js:1209`) · `quick-facts`(`app.js:1283`). 2026-08-08 P0-2 **미해소 승계**. [관측]

**P1-7. 체크 상태가 공고 단위가 아니다.** `taskStorageKey` 는 전역 키 1개이고(`app.js:430`), 분석할 때마다 `removeItem` 으로 지운다(`app.js:1502`). 공고 두 건을 번갈아 보면 앞 건의 진행이 사라진다. [관측]

**P1-8. 관심 공고에서 그 공고로 되돌아올 수 없다.** 카드의 링크는 온비드 원문뿐이고 앱 내부로 다시 여는 동작이 없다(`app.js:1402-1420`). 저장의 값이 회수되지 않는다. [관측]

## 3-3. 무엇을 앞으로 당긴다

1. **A/B/C 출처 문장을 결과 최상단 한 줄로.** 지금도 있으나(`renderDocSourceNotice`) 입력 화면 안쪽에 있다. 여기가 **정직함의 자리**다.
2. **첨부파일을 B형에서 체크리스트와 같은 층으로.** 목록 자리에 「이 공고의 서류는 이 파일 안에 있습니다」 + 다운로드 버튼을 직접 놓는다. `downloadUrl` 은 이미 서버가 만든다(`server.py:564-593`) — 표본조사 §5 의 「파일을 열 수단이 없다」는 **해소됨** [관측].
3. **서류 항목에 체크박스를.** 체크 단위를 확인 항목 5건에서 **서류 1건**으로 옮긴다. 진행률도 그 분모로 바꾼다.
4. **조건 칩 기본값은 「단독 · 개인」.** 8건짜리 목록이 2건으로 시작한다.
