# UX 전면 재설계 3단계 — 준비 보드 2단계(서류준비) 내부 로직 2026-10-12

솔로 작업(서브에이전트 병렬 호출 없이 직접 설계·구현·검증 수행). `agentic-journey` 브랜치, 워크트리 `Hometest_op-agentic`.

## 범위

준비 보드 2단계(서류준비) 카드 내부 로직만. 3단계(입찰참여) 내부 로직과 1단계·마법사 화면은 이번에 손대지 않았다.

## 구현 방식

- 서버(`src/server.py`)가 이미 서류를 "조건별 그룹"(`docChecklist.groups`, 그룹 라벨이 "공동입찰"·"대리입찰"·"대리입찰 · 공동입찰"·"공통" 등)으로 추출해 보내고 있었다. 이번 작업은 그 데이터를 새로 만들지 않고, 화면에서 공동입찰/대리입찰 질문 답에 맞춰 **어느 그룹을 보여줄지**만 걸렀다.
- `getDocConditionAnswers()`/`setDocConditionAnswer()`(`src/app.js`) — 공고별로(`noticeKey` 기준) localStorage에 저장한다. 기본값은 둘 다 "아니오"다(사용자 지시의 "더 단순한 쪽"을 선택 — 질문에 답하기 전에도 "공통" 서류 리스트를 먼저 보여주고, 답에 따라 갱신).
- `getVisibleDocGroups()` — `docChecklist.groups`에서 라벨에 "공동입찰"이 들어간 그룹은 답이 "예"일 때만, "대리입찰"이 들어간 그룹은 답이 "예"일 때만 남긴다. 그 외(공통·미성년자·법인 등 이번 질문과 무관한 조건)는 그대로 둔다.
- `DOC_CONDITION_SUPPLEMENT` — 공동입찰·대리입찰에 "예"로 답했을 때 추가로 안내하는 서류다. 이 공고 원문에서 추출한 것이 아니라 `src/server.py`의 `DOC_HOWTO`가 이미 쓰는 공식 서식명("공동입찰참가신청서"·"대리입찰신청서"·"위임장")을 그대로 재사용했다. "대리인 신분증"은 공식 서식명이 정해진 게 없어 "대리인 신분증 등 본인 확인 서류 (확인 필요)"로 표시해 확정된 서류명처럼 보이지 않게 했다 — 지어내지 않는다는 안전 경계를 서류 목록에도 적용했다. 이미 추출된 그룹에 같은 이름이 있으면 중복으로 추가하지 않는다(실제 테스트 공고에서 "대리입찰신청서"는 이미 "공통" 그룹에 있어 추가되지 않았고, "위임장"·"대리인 신분증…"만 "대리입찰 추가 안내" 그룹으로 추가됐다).
- `getUniqueDocNames()`(체크 상태·진행률의 기준)도 `getVisibleDocGroups()`를 쓰도록 바꿔, "N/M개 서류 준비 완료" 진행률이 화면에 실제로 보이는 "최종 리스트" 기준으로 집계되게 했다.
- `renderDocConditionQuestions()` — "공동입찰인가요?"/"대리입찰인가요?" 질문 두 개를 "예/아니오" 버튼(기존 `.coach-experience-options` 패턴을 재사용)으로 렌더링한다. `renderDocChecklist()`의 "제출서류 리스트입니다." 안내 바로 아래에 배치했다.
- "내 보관함으로 보내기" — 완전히 새로운 저장 체계를 만들지 않고 기존 "관심 공고" 구조(`recentNoticeStorageKey`·`favoriteNoticeStorageKey`·`renderWatchlist()`)를 그대로 재사용했다. `saveNoticeToLocker()`가 ⑴ 핵심 정보(공고명·URL·입찰기간·최저입찰가격·공동입찰/대리입찰 답·확정 서류 리스트)를 새 저장소(`onbid-public-asset-doc-agent-locker-v1`)에 묶어 저장하고 ⑵ `saveRecentNotice()`로 "최근 살펴본 공고"에 남기고 ⑶ 즐겨찾기에 추가해 "관심 공고" 화면에서도 바로 보이게 한다.

## 되돌아본 것

- 실제 테스트 공고(`onbidPbancNo=887390`, phase2에서 쓴 것과 같은 샘플 — 입찰기간이 이미 지나 있다)는 조건별 그룹을 셋 다 가지고 있었다(`공동입찰`·`대리입찰`·`대리입찰 · 공동입찰`). 다만 조건이 붙은 서류 이름(공동입찰참가신청서·대리입찰신청서·본인서명사실확인서·인감증명서)이 전부 "공통" 그룹에도 중복으로 들어 있어서, 질문에 "예"로 답해도 **고유 서류 개수(진행률의 분모)는 바뀌지 않는다** — 대신 "공동입찰"/"대리입찰" 그룹 자체가 나타나거나 사라지는 것으로 리스트가 달라진다. 이것은 server.py의 추출 로직이 조건부 언급과 일반 언급을 각각 별도 항목으로 뽑기 때문이다(기존 동작, 이번에 손대지 않았다). 다음 phase에서 비슷한 조건 필터를 다룰 때 참고할 것.
- `DOC_CONDITION_SUPPLEMENT`는 공고 원문에서 추출한 문장이 아니라는 점을 "원문 근거" 칸에 그대로 적어 뒀다(원문 인용처럼 보이지 않게).

## 검증

- 단위 테스트 `tests/test_docs_extraction.py`: 275/275 통과(변경 전후 동일, `src/server.py`는 손대지 않았다)
- 금지 문구 검사 `tests/test_screen_strings.py`: 20/20 통과
- 전용 포트 19003에 직접 서버를 띄우고, 실제 온비드 공고(`onbidPbancNo=887390`)를 분석해 1단계를 완료 처리한 뒤 2단계 체크리스트를 열어 실제 브라우저(OpenClaw browser 도구)로 확인했다.
  - **공동입찰 "예"**: `.doc-group h4` 목록이 `["공통"]` → `["공동입찰", "공통"]`로 바뀌는 것을 DOM에서 직접 확인했다.
  - **대리입찰도 "예"(둘 다 예)**: `["공동입찰", "대리입찰", "대리입찰 · 공동입찰", "공통", "대리입찰 추가 안내"]`로 늘어나는 것을 확인했다. "대리입찰 추가 안내"에는 "위임장"·"대리인 신분증 등 본인 확인 서류 (확인 필요)"만 들어있다(이미 있는 "대리입찰신청서"는 중복 추가되지 않음을 확인).
  - **둘 다 "아니오"로 되돌림**: `["공통"]` 하나로 돌아오는 것을 확인했다 — 세 가지 조합에서 서류 리스트(그룹 구성)가 실제로 달라진다.
  - **보관함 저장**: "내 보관함으로 보내기" 클릭 → 피드백 "보관함에 저장되었습니다." 표시 확인 → `localStorage.getItem('onbid-public-asset-doc-agent-locker-v1')`를 직접 조회해 공고명·URL·입찰기간("2026-06-01 10:00 ~ 2026-06-04 17:00")·최저입찰가격("660000")·jointBid("yes")·proxyBid("no")·docList(8건)가 실제로 저장된 것을 확인했다.
  - **새로고침 후 유지**: 페이지를 `#watchlist`로 전체 새로고침(모듈 상태 완전 리셋)한 뒤에도 `localStorage`의 보관함 레코드가 그대로 남아 있었고, 기존 "관심 공고" 화면에도 "관심 공고 1건"으로 해당 공고가 보이는 것을 확인했다(즐겨찾기 연동이 실제로 작동).
  - 콘솔 오류는 `favicon.ico` 404(기존부터 있던 무관한 것) 외 0건.
  - 작업 중 생성된 임시 파일 없음(`git status --short`로 확인, `src/app.js`·`src/styles.css` 수정만 남음).

## 다음 phase(3단계 입찰참여: 담당기관 질문 제거·정보 리스트업 재구성·AI 질문창)에 넘길 메모

- `getVisibleDocGroups()`는 그룹 라벨 문자열에 "공동입찰"/"대리입찰"이 포함되는지로 필터한다. 서버의 `CONDITION_AXES`에는 이 둘 외에도 미성년자·컨소시엄·사용인감·지역 제한·업종·자격·법인·개인·외국인 축이 있다 — 이번 phase는 이 둘만 질문으로 올렸고 나머지 조건은 그대로 항상 표시된다. 3단계에서 비슷한 조건부 질문을 더 늘리려면 이 필터 함수를 조건 키 배열 방식으로 일반화하는 것을 검토할 것.
- "내 보관함으로 보내기"는 버튼을 누를 때마다 그 공고의 최신 답·서류 리스트로 **덮어쓴다**(`id` 기준으로 기존 레코드를 지우고 새로 추가). "저장 시점 스냅샷을 여러 개 남기기"가 필요해지면 이 동작을 바꿔야 한다.
- 모바일 화면(390px)에서 공동입찰/대리입찰 질문 버튼의 줄바꿈은 이번에 직접 확인하지 않았다(완료 조건에 없었음) — 3단계 작업 때 함께 확인하는 것을 권한다.
