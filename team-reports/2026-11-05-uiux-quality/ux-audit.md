# UX 흐름 감사 — 캠코 정인기 차장 데모 핵심 플로우 (2026-11-05)

목적: 캠코 온비드사업처 정인기 차장에게 "한번 써 보시라" 메일을 보내기 전, 그가 처음 열어 볼
핵심 플로우(1. 공고 URL 입력 → 2. 분석 결과 → 3. 준비 보드 Step 1-2/2-1~2-4 → 4. AI 코치 질문)의
UI/UX를 직접 타고 가며 막힘·혼란 지점을 찾는다.

## 검증 방법
- 로컬 서버 포트 **8981**(라이브 서비스 중인 8975·18982와 분리된 별도 인스턴스, `main` HEAD `d54635e`)을
  새로 띄우고, `mcp__openclaw__browser`로 실제 화면을 열어 데스크톱(1280px)·모바일(390px) 두 폭에서
  직접 조작했다.
- 코드만 읽고 추론한 것과 화면으로 직접 확인한 것을 아래에서 구분해 적는다.

## 발견 — P1 (바로 고칠 것)

### 1. 정적 자원 캐시버스터가 10-30 app.js 수정 4건 이후 갱신되지 않았다 [관측 · 코드+서버로그 확인]
- `src/index.html`의 `app.js`·`styles.css` 쿼리 문자열이 `?v=20261029-item-search-r2`로,
  마지막 갱신 커밋은 10-29(`f649311`)이다.
- 그런데 그 뒤 **10-30에 app.js를 수정한 커밋이 4개** 더 있다(`c2a0fd0`·`eee2ac8`·`81cdb76`·`93084eb`,
  `git show --stat` 로 각각 `src/app.js` 변경 확인). 검색 시한(AbortController)·캐시 비었을 때 오류
  문구 구분·혼합 처분방식 칩·라우트 정렬 단정 등이 여기 포함된다.
- 캐시버스터 문자열이 그대로라, 이전에 이 서비스를 한 번이라도 열어 본 브라우저(사전 공유 자료를
  보낸 뒤 정인기 차장이 미리 한 번 열어볼 수도 있다)는 캐시된 구버전 app.js를 계속 쓸 수 있다.
- 처방: `index.html`의 두 `?v=` 문자열을 현재 HEAD 커밋에 맞춰 올린다.

### 2. `#report-hero`가 빈 채로 렌더링돼 "유령 박스"가 보인다 [화면 직접 확인 · 390px·1280px 공통]
- 준비 보드(`준비 보드` 탭)를 공고 분석 전에 열면 `#report-hero`가 `innerHTML = ""`로 비워지는데
  (`app.js:3199`), `.report-hero`(styles.css:951)에는 `.board-top-stepper:empty { display:none }`
  같은 숨김 규칙이 없다. `border-left`·`background`·`padding`이 있는 328×30px 빈 박스가 "STEP 2 /
  내 준비 보드" 패널 바로 위에 보인다(`getBoundingClientRect` 실측).
- 정인기 차장이 "관심 공고" 전에 "준비 보드" 탭을 먼저 눌러 볼 가능성이 있고, 그때 내용 없는
  테두리 박스가 바로 보이면 "미완성"으로 읽힐 수 있다.
- 처방: `.report-hero:empty { display: none; }` 한 줄 추가(기존 `.board-top-stepper:empty` 패턴과 동일).

### 3. 낙찰 후(2-4) "함께 확인" 경고 박스가 뒤 규칙에 덮여 강조를 잃었다(2026-10-19 회귀) [코드+computed style 확인]
- `src/app.js` 주석(1750행 근처)은 "머리 안내는 단계 판정 오분류의 안전망이라 묻히면 안 된다 —
  본문 small-text와 다른 비중으로 둔다"고 명시한다. 원래 `.post-award-caution`(styles.css:828-834)은
  `background: var(--soft-blue)`(연한 살구탄색) · `border-left: 3px solid #c9a08f`(장미빛 강조선) ·
  `font-weight: 700`으로 눈에 띄게 설계됐다.
- 그런데 10-19 커밋 `ee2ca95`("준비 보드 1-3 템플릿 통일")이 `.post-award-caution, .post-award-process`를
  묶어 `border: 1px solid var(--line); background: var(--panel); font-weight: 400`로 **덮어썼다**
  (styles.css:2738-2747, 같은 특이도·뒤에 위치해 캐스케이드에서 이긴다).
- `getComputedStyle` 실측: `.post-award-caution`의 실제 배경은 `rgb(255,250,245)`(일반 패널색),
  `font-weight: 400`, 테두리 1px — 바로 아래 평범한 정보 박스(`.post-award-process`)와 **시각적으로
  구분이 안 된다**. "입찰 전에 내야 하는 서류가 여기 섞여 있을 수 있습니다" 경고가 일반 안내문과
  똑같이 보인다.
- 처방: 뒤 규칙(2738-2747)에서 `.post-award-caution`을 빼고 `.post-award-process`에만 적용해,
  caution 박스는 원래의 강조 스타일로 되돌린다.

## 관찰 — 수정하지 않음(범위 밖·백엔드·운영)

- **AI 물건 검색(Step 1-2)이 이 세션 환경에서 4분 넘게 응답하지 않아 120초 클라이언트 시한이
  정상 작동했다**(`/api/search` POST가 120초 뒤 AbortController로 끊겼고, 서버는 그 뒤에도 계속
  처리하다 `BrokenPipeError`로 끝났다 · 서버 로그 실측). 라이브 포트(8975·18982)가 이미 같은
  개발계정 API 일일 한도(1,000건)를 쓰고 있어 내 테스트 인스턴스가 경합했을 가능성이 있다
  [추론, 미확정]. 프런트엔드 반응(시한 뒤 재시도 가능한 상태로 복귀)은 의도대로 동작했다 — **UI
  버그가 아니라 백엔드/API 쿼터 영역**이라 이번 범위에서 손대지 않는다.
- **샘플 공고 URL이 이미 입찰 마감 지난 물건을 가리킨다**(2026-10-29 15:00 마감, 오늘은 11-05).
  "입찰 마감 지남" 배지·확인 배너는 의도대로 정확히 작동했다. 다만 데모 첫인상에서 "이미 끝난
  공고"로 보일 수 있다 — 이건 UI 결함이 아니라 **샘플 URL 갱신(운영) 과제**이므로 to-do에 새로
   등록은 하지 않고 기존 known-pitfalls "시연용 샘플 URL은 입찰기간 종료 후 변경될 수 있다" 항목을
   다시 확인하라고만 남긴다.
