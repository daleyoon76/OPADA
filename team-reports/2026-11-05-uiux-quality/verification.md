# 수정 검증 — 캠코 데모 핵심 플로우 UI 다듬기 (2026-11-05)

visual-reviewer 역할. 구현 직후 로컬 서버(8981)를 재기동하고, 수정한 세 화면을 실제로 다시 열어
의도대로 됐는지, 새로 깨진 것은 없는지 확인했다. 전부 **실제 서버·브라우저로 라이브 확인**했고
(코드만 읽고 추론한 것은 없음), 각 항목에 관측 근거를 남긴다.

## 1. 캐시버스터 갱신 — 실측 확인
- 서버 재기동 후 브라우저 네트워크 로그(`requests`)에서 `styles.css?v=20261105-uiux-fix`·
  `app.js?v=20261105-uiux-fix`가 실제로 요청·200 응답됨을 확인했다(기존 `?v=20261029-item-search-r2`
  캐시를 쓰지 않고 새 쿼리로 다시 받음).

## 2. `#report-hero` 빈 박스 제거 — 실측 확인
- 분석 전 "준비 보드" 탭에서 `getComputedStyle(#report-hero).display === "none"`을 확인했고,
  스크린샷으로도 이전에 있던 빈 테두리 박스가 사라진 것을 확인했다. "아직 가져온 공고가 없습니다"
  카드만 남아 비어 보이지 않는다.
- 머리글의 "커밋하지 않은 변경이 있습니다" 표기는 `/api/version`의 `dirty: true`를 그대로 보여주는
  기존 동작이다(테스트 서버가 미커밋 변경을 반영 중이라 뜨는 정상 상태). 커밋하면 사라진다 — 버그
  아님.

## 3. 2-4단계 "함께 확인" 경고 박스 강조 복원 — 실측 확인(1차 시도 불완전 → 추가 수정 → 재확인)
- **1차 수정**(10-19 커밋이 덮어쓴 `.post-award-caution, .post-award-process` 통합 규칙에서
  `.post-award-caution`을 뺌) 뒤 실측했더니 `font-weight`는 700으로 돌아왔지만 `background`·
  `border-left`는 여전히 일반 박스와 같았다 — **예상과 다른 결과였다.**
- 원인을 다시 찾았다: 이 요소는 `class="info-row post-award-caution"`으로 **`.info-row` 기본
  스타일(2382행)도 같이 받는데**, `.info-row`가 파일에서 `.post-award-caution`(828행)보다 **뒤에**
  있어 같은 특이도에서 `.info-row`의 `background: var(--panel)`·`border: 1px solid var(--line)`가
  이겼다. 10-19 커밋이 범인의 전부가 아니라, `.info-row` 공통 스타일과의 충돌이 더 근본 원인이었다.
- **2차 수정**: 선택자를 `.info-row.post-award-caution`(복합 클래스, 특이도 0-0-2-0)으로 올려
  파일 순서와 무관하게 이기도록 했다. `border: 0` 뒤 `border-left: 3px solid #c9a08f`를 둬 위·오른쪽
  ·아래 테두리는 없애고 왼쪽 강조선만 남겼다(10-19 이전 원래 디자인의 의도대로).
- 재실측(`getComputedStyle`, 체크리스트를 실제로 눌러 2-4단계까지 도달한 뒤):
  - `.post-award-caution`: 배경 `rgb(243,231,226)`(`--soft-blue` = `#f3e7e2`) · 왼쪽 테두리
    3px `rgb(201,160,143)`(`#c9a08f`) · 위 테두리 0px · `font-weight: 700` — **의도한 값과 일치**.
  - `.post-award-process`: 배경 `rgb(255,250,245)`(`--panel`) · 테두리 1px `rgb(240,213,192)`
    (`--line`) · `font-weight: 400` — 그대로 유지(의도대로 중립 박스).
  - 스크린샷으로 "함께 확인"(짙은 베이지 배경·장미빛 강조선)과 "순서"(흰 패널·얇은 테두리) 두 박스가
    시각적으로 뚜렷이 구분됨을 확인했다.
