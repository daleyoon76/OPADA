- 작성: 2026-10-01
- 담당: ux-flow-auditor (읽기 전용 진단, 소집=3팀 팀장)
- 대상: `docs/60_본선준비/19_AI가이드형_UX_재설계_플로우_20261001.md`, `docs/60_본선준비/mockups/20_AI가이드형_준비보드_초안_20261001.html`

## 현재 코드 기준 핵심 플로우

1. `#input` 공고 가져오기 → 분석 실행 → `#report` 준비 보드 진입.
2. 보드 내부: `report-hero`(요약) → `board-coach`(AI 코치 패널, 질문-답변 위젯이 이미 내부에 중첩) → `board-status`(진행률) → `board-layout`(다음 액션 + 공고 요약 사이드바) → `support-grid`(접힌 패널 **7개** — 문서·초안이 적은 "6개"와 다름).
3. 다음 액션 목록(`getApplicableTasks()`, app.js:758~765)은 **이미 `aiMatch` 점수순 정렬**이고, 최대 3개 항목에 `task-ai-nudge` 박스를 붙이며, 1순위 항목은 관련 `<details>`를 자동으로 펼친다(`shouldOpenDetails`, app.js:1511).

## 네 가지 제안 진단

### 1. 코치 패널 1인칭 톤 교체 — 이렇게 수정해서 구현
방향 자체는 문제없으나, 초안의 배지 `AI 안내`는 고정 문자열인 반면 실제 코드(`renderCoachPanel`, app.js:950~951)는 `llmConnected` 여부로 "AI 누락 점검" / "규칙 기반 누락 점검"을 분기한다. 이 분기를 지우고 고정 문구로 바꾸면 LLM 미연결 상태에서도 AI가 안내한 것처럼 보인다 — 아래 P0 참조. 새 1인칭 문구도 연결/미연결 두 버전을 만들어야 한다.

### 2. 다음 액션 AI 우선순위 강조 — 이렇게 수정해서 구현 (범위 재설정 필요)
기획 문서는 "지금은 다른 항목과 나란히 있어 안 띈다"고 전제하지만 **실측 결과 사실과 다르다** — 점수순 정렬·`task-ai-nudge` 박스·자동 펼침이 이미 구현돼 있다. 남은 것은 시각적 비중 강화뿐(visual-designer 영역). 구현 범위를 "이미 있는 강조를 더 키운다"로 정정해서 넘길 것.

- 🟡 **이번 조사에서 발견한 기존 결함**: `task-ai-nudge`는 `is-done` 여부와 무관하게 렌더링된다(app.js:1521·1529, styles.css에 `.is-done .task-ai-nudge` 숨김 규칙 없음). 사용자가 AI 추천 1순위 항목을 체크 완료해도 "확인 필요 항목" 박스가 그대로 남는다. 강조를 키우면 이 모순이 더 커지므로 강조 작업과 함께 고쳐야 함.
- 체크 순서 충돌 우려는 성립하지 않음: 목록이 원래 "순서대로"가 아니라 "AI 점수순" 동적 정렬이라 고정 순서 자체가 없음.

### 3. 질문-답변 위젯 독립 카드 승격 — 이렇게 수정해서 구현
팀장이 packet에 적은 우려("AI 코치가 말하는 것"과 "내가 질문하는 것"이 별개 기능처럼 보일 위험)는 **실제로 존재**한다. 초안의 `.mock-ask-promoted` 카드는 코치 배지·정체성 표식이 전혀 없는 독립 박스다. 물리적 거리는 가깝지만(코치 패널 바로 아래, 사이에 다른 콘텐츠 없음) 시각적 연결 고리(코치 배지·"AI" 라벨)가 빠져 다른 기능으로 읽힐 수 있다.

- 수정 방향: 승격 카드에도 코치와 같은 라벨("AI 코치에게 물어보기" 등)을 넣어 같은 화자임을 유지. 문구 결정은 positioning-copywriter 영역.
- 구현 난이도: `renderCoachAsk()`는 현재 `renderCoachPanel()` 내부에서 `options.board`일 때만 호출되는 구조(app.js:1000)라, 독립시키려면 `renderReport()`(app.js:1480~1483 부근)에 별도 렌더 지점을 새로 만들어야 한다 — 단순 CSS 이동이 아니라 렌더 함수 분리.

### 4. 접힌 패널 딥링크 힌트 — 구현하지 않는다 (현재 형태로는)
기획 문서 자체가 모순된다 — 3절 다이어그램은 실제 점프를 그리지만 4절 서술은 "코드·구조는 그대로 두고 안내 링크만 추가"라고 적는다. 초안 HTML도 `<summary>` 옆에 정적 텍스트("← AI 코치가 추천")만 붙였을 뿐 실제 앵커 링크는 없다.

- 실제 `support-grid` 순서(7개: 첨부파일 → 공고문 항목 → 용어 안내 → 참고자료 → 마감·비용 요약 → 담당기관에 물어볼 문장 모음 → 근거와 안전 경계)에서 추천 대상(마감·비용, 질문모음)은 5·6번째다. 문서 4절의 "구조는 그대로 둔다"를 지키면 사용자는 여전히 4개 패널을 지나쳐야 추천 패널에 도달 — 라벨만으로는 클릭 수가 줄지 않고 "추천인데 맨 아래"라는 인지 부조화만 늘어난다.
- 재검토 제안: (a) 순서 재배치 + 기본 열림, 또는 (b) 코치 패널에 실제 스크롤 점프/앵커 링크 중 하나로 범위를 명확히 정해 다시 제안받을 것.

## 🔴 P0 — 다음 단계 전 반드시 결정할 사항

초안의 고정 "AI 안내" 배지가 `tests/screen.spec.js` N5("LLM에 붙지 않았으면 「AI가 했다」는 문구를 세우지 않는다")가 지키는 요건과 충돌할 소지가 있다. 실제 코드는 `llmConnected` 분기를 쓰는데 초안은 이를 드러내지 않는 정적 스냅샷이라, 구현 시 분기를 빠뜨리면 N5 원칙 위반으로 이어진다. 구현 전 연결/미연결 두 상태 모두에 대해 "AI가 했다"고 말하지 않는 문구 두 벌을 확정해야 한다.

## 초안 ↔ 실제 코드 불일치 (구현 단계 주의)

- 접힌 패널 개수: 문서·초안 "6개" vs 실제 코드 **7개**(`근거와 안전 경계` 누락).
- 패널 DOM 순서: 초안은 추천 대상 2개를 맨 앞으로 재배치했지만 실제 코드 순서는 다름.
- 코치 패널 배지: 초안은 고정 "AI 안내", 실제 코드는 `llmConnected` 동적 분기 — 위 P0와 동일 건.
- AI 우선순위 강조 현황: 문서는 "지금은 강조가 없다"고 전제하나 실제로는 정렬·배지·자동펼침이 이미 존재 — 구현 범위 재설정 필요.

## 검증할 사용자 행동 (다음 단계 참고)

- AI 추천 1순위 항목 체크 완료 후에도 "확인 필요 항목" 표시가 남는지 — 현 코드 기준 재현 확인됨.
- 질문-답변 카드 독립화 후 사용자가 "AI 코치와 대화"로 인지하는지(사용자 테스트 필요, 이번 조사는 추정만 가능).
- 접힌 패널 힌트 적용 전/후 추천 패널 도달 클릭 수·스크롤 거리 변화(현재 설계안은 변화 없음으로 추정).
- 새 1인칭 안내 문구가 `tests/screen.spec.js` N5 시나리오(연결/규칙기반 양쪽)에서 통과하는지 — 문구 확정 후 **새 게이트 항목 필요**로 표시.

## 역할 간 판정 차이와 채택 근거 (팀장 종합)

4번 제안에서 `visual-designer`(시각 축: 폰트 크기 11→12~13px 권고, "이렇게 수정해서 구현")와 본 역할(흐름 축: "구현하지 않는다")이 갈렸다. 팀장은 ux-flow-auditor의 판정을 채택한다 — 폰트 크기 조정은 "이 요소를 지금 형태로 만들지" 자체가 정해진 뒤에나 의미가 있는 2차 문제이고, 문서 자체의 모순(3절·4절 불일치)과 "라벨만으로는 클릭 수 불변"이라는 더 근본적 지적이 먼저 해소돼야 하기 때문이다.
