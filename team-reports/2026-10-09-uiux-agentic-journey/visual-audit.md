# OPADA 준비 보드 — 단계 전환 시각 설계

> 반환자: visual-designer (3팀 UIUX품질팀). 읽기 전용 진단. 코드 변경 없음.
> 참고: `team-reports/2026-10-09-uiux-agentic-journey/ux-audit.md`, `src/index.html`(90~119행), `src/app.js`(993~1013행, 1407~1560행), `src/styles.css`(1~24행, 476~520행, 526~560행, 655~790행, 815~852행, 1098~1140행, 1434~1459행, 1507~1600행)

## 시각 품질 판단

현재 `board-status`(진행률 카드 하나)와 평평한 `task-item` 5개 나열 구조는 "지금 몇 단계인지"라는 새 요구사항을 전혀 표현하지 못한다. 기존 코드에는 이미 거의 같은 문제를 푼 전례(`.pipeline li.done`/`.pipeline li.active`, Step1 분석 파이프라인)가 있어, 새 색상·변수를 만들 필요 없이 그 시각 언어를 재사용할 수 있다. 아래 명세는 신규 CSS 변수를 하나도 요구하지 않는다.

## 문제 위치

- `src/app.js` 1494행 `board-status` 렌더 블록 — 진행률 카드 1개뿐, 단계 정보 없음.
- `src/app.js` 1510행 `task-list` 렌더 블록 — 5개 task가 단계 구분 없이 평평하게 나열.
- `src/app.js` 993행 `renderBoardCoach` — 온보딩 질문 A를 얹을 자리가 없음(지금은 질문 B 입력창만 있음).

## 우선순위

- P0: 전체 진행률 스테퍼(⑴), 단계 카드 3상태(⑵) — 이게 없으면 단계화 자체가 안 보임.
- P1: 온보딩 질문 A 배치(⑶) — ux-audit P1에서 카드 수 증가 금지가 걸림.
- P2: 접힌 완료 단계 디테일, 안내 수준 토글 위치 — ux-audit도 P2로 분류.

## ⑴ 전체 진행률 표시 명세

`board-status`를 "상태 카드 1개"에서 "3단계 스테퍼 1개"로 교체한다. 기존 `.status-card`(진행률 숫자+바)는 스테퍼 **안**에 흡수시키지 않고, 스테퍼 **아래에 한 줄로 유지**한다 — "N/5 완료"라는 전체 숫자는 단계와 별개로 계속 필요한 정보다.

### 데스크톱 (901px~)

```
┌───────────────────────────────────────────────────────────┐
│ ① ✅ 공고 확인      — ② ▶ 서류 준비      — ③ 🔒 입찰 참여 │   ← 스테퍼
├───────────────────────────────────────────────────────────┤
│ 진행률          3/5 완료  [██████░░░░]                     │   ← 기존 status-card 유지
└───────────────────────────────────────────────────────────┘
```

- 가로 3열 그리드(`grid-template-columns: repeat(3, 1fr)`), 열 사이에 `.pipeline li`와 같은 톤의 연결선(1px `var(--line)`)을 `::after`로 긋는다. 숫자 뱃지(①②③)는 `.pipeline .state`와 같은 작은 보조 라벨 취급 — 본문은 단계명이다.
- 각 칸은 `role="listitem"`을 쓰는 `<li>`, 전체는 `<ol aria-label="준비 단계" role="list">`로 마크업. 단 id/class 이름은 `currentStage`/`pipelineSteps`와 겹치지 않게 `prep-stage-stepper` 계열로 둔다(ux-audit §⑸ 제약).
- `aria-current="step"`을 진행중 칸에 부여.

### 모바일 (900px 이하)

기존 `@media (max-width: 900px)` 블록이 `.board-status`를 `grid-template-columns: 1fr`로 이미 바꾸고 있으므로, 그 규칙을 **스테퍼에도 그대로 적용**한다.

```
┌─────────────────────────────┐
│ ✅ ① 공고 확인               │
│ ▶  ② 서류 준비  (지금 단계)  │
│ 🔒 ③ 입찰 참여               │
├─────────────────────────────┤
│ 진행률   3/5 완료 [██████░░] │
└─────────────────────────────┘
```

세로 1열로 쌓이고, 각 행은 기존 `.task-item` 높이(패딩 10px 14px)와 맞춰 터치 타겟을 확보한다. 연결선은 세로 방향(`border-left`)으로 바뀐다.

## ⑵ 단계 카드 상태 3종 시각 명세

스테퍼 칸(①②③)과 `task-list` 안의 **단계 그룹 헤더**(각 단계 소속 task들을 감싸는 섹션 타이틀) 양쪽에 같은 상태 톤을 적용한다. `task-list`는 지금처럼 `.task-item` 평면 리스트를 유지하되, 단계 경계마다 `<h4 class="stage-group-heading">` 구분선을 넣는 구조를 권장한다(task-item 자체 구조는 바꾸지 않아 구현 범위를 최소화).

### 진행중 (active)

- 색: `.pipeline li.active`와 동일한 배색 재사용 — 배경 `var(--soft-blue)`, 테두리 `#c9a08f`.
- 레이아웃: 스테퍼 칸 테두리를 2px로 두껍게(다른 두 상태는 1px) — 색만으로 구분하지 않기 위한 굵기 신호.
- 아이콘: `▶`(`aria-hidden="true"`) + "진행중" 텍스트. 배지는 `.badge.neutral` + 텍스트 "진행중"으로 — 의미는 텍스트가 전달하고 배지 색은 장식으로만 쓴다.
- 단계 그룹 헤딩: `border-left: 3px solid #c9a08f`(활성), 배경은 흰색 유지.

### 잠김 (locked)

- 카드 전체를 일괄로 흐리게 처리하지 않는다. 완전한 불투명도 처리는 그 안의 "항상 클릭 가능" 요소(원문 링크·문의 문구)까지 흐려 모순을 시각적으로도 감춘다.
- **구체 처리**: 잠긴 단계의 체크박스 행(`.task-row`, `.task-check`)에만 `opacity: 0.55` + `cursor: not-allowed`를 걸고, 그 아래 `<details>`(자세히)·`task-action-value`(원문에서 확인된 값)·`task-precheck`(문의 문구) 블록은 **별도 클래스를 주지 않고 기존 스타일 그대로** 남긴다. 흐림 처리는 카드 단위가 아니라 **체크 행 단위**로 좁힌다.
- 체크박스 자체: `disabled` + `aria-disabled="true"` + `cursor: not-allowed`.
- 아이콘: `🔒`(`aria-hidden="true"`) + 단계 그룹 헤딩 옆 텍스트 "1단계를 마치면 열립니다" 한 줄(`.small-text`, `color: var(--muted)`, 12px). 이 문장이 1차 전달 수단이고 자물쇠는 보조.
- 단계 그룹 헤딩: `border-left: 3px solid var(--line)`(연한 색).
- 미리보기 task 제목 글자색만 `var(--muted)`로 눌러 "지금은 못 누른다" 신호를 주고, 그 아래 원문 링크·문의 문구는 원래 색으로 대비를 둔다 — "체크는 잠기지만 정보는 열린다"는 의도를 그대로 시각적으로 번역한다.

### 완료 (done)

- 색: `.pipeline li.done`과 동일 — 배경 `var(--soft-green)`, 테두리 `#c8d1a0`. 기존 `.task-item.is-done`(#f5f7ec)과는 미세하게 다르나, "task-item 개별 완료"와 "단계 그룹 전체 완료"를 구분하려는 의도적 선택이다. 혼동 우려가 있으면 `#f5f7ec`로 통일해도 무방.
- 아이콘: `✅`(`aria-hidden="true"`) + "완료" — 기존 배지 어휘 그대로 재사용.
- 단계 그룹 헤딩: `border-left: 3px solid #c8d1a0`.

### 완료된 단계 표시 — 접을지 펼칠지

**계속 펼쳐 둔다. 접지 않는다.**
- `documents`(2단계)는 체크 완료 후에도 "서류 체크리스트 N/M 남음" 비차단 리마인더를 계속 보여줘야 한다. 접으면 이 리마인더가 숨어 역할을 못 한다.
- 완료된 1단계의 "온비드 원문 열기" 링크·확인된 값은 3단계까지도 재확인 수요가 있다(상단 고지 "원문 확인 우선" 전역 약속).
- 대신 완료 단계는 시각적 밀도만 낮춘다: `<details>`(자세히) 블록만 기본 닫힘으로 둔다. 체크박스·배지·링크는 그대로 다 보인다.

## ⑶ 질문-답변 온보딩 시각 배치

`board-coach` 영역(`#board-coach`, `.coach-ask-card`)을 재구성한다. 새 카드를 만들지 않고, 기존 `.coach-ask-card` 안에 상단 블록을 추가한다.

```
┌─ coach-ask-card ──────────────────────────────┐
│ [AI 코치에게 물어보기]                         │
│                                                 │
│ 온비드 공매·입찰, 해 보신 적 있으신가요?        │ ← 신규: 질문 A
│ [처음이에요]  [몇 번 해봤어요]   건너뛰기       │
│ ─────────────────────────────────────────────  │ ← 1px var(--line) 구분선
│ 지금 궁금한 점이 있으면 먼저 물어보세요.         │ ← 기존 질문 B, 문구만 선두 배치
│ [________________________] [질문하기]          │
└─────────────────────────────────────────────────┘
```

- 질문 A 선택지 버튼 2개는 기존 `.secondary` 버튼 스타일 그대로. "건너뛰기"는 버튼이 아니라 `.small-text` 링크 톤의 텍스트 버튼으로 — 시각적 무게를 낮춘다.
- 질문 A는 응답 후 또는 한 번 노출된 후에는 이 자리에서 사라지고 질문 B만 남는다. `display: none`으로 접히면서 질문 B가 카드 맨 위로 올라오는 구조(질문 B의 `margin-top`을 0으로).
- 안내 수준 재변경 토글("안내 수준: 자세히 ⇄ 간단히")은 질문 A가 사라진 뒤에도 흔적이 남아야 하므로, `coach-ask-card` 머리글(`coach-ask-head`) 우측에 작은 토글 버튼으로 상시 노출한다. `.small-button`(기존 "초기화" 버튼과 같은 크기) 재사용.
- `board-coach`는 `board-status`(스테퍼) 위에 그대로 유지(현재 DOM 순서 `report-hero → board-coach → board-status`와 동일). 질문 A 노출 중에도 `coach-ask-card`의 `padding`은 기존 13px 15px를 유지한다.

## ⑷ 접근성 체크

- 색만으로 상태를 구분하지 않는다: 세 상태 모두 아이콘(`✅`/`▶`/`🔒`) + 텍스트 라벨("완료"/"진행중"/"잠김, 1단계를 마치면 열립니다")을 함께 둔다. 아이콘은 `aria-hidden="true"`, 텍스트가 실제 전달 수단.
- 스테퍼: `<ol role="list" aria-label="준비 단계">` + 각 `<li>`에 `aria-current="step"`(진행중 칸만).
- 기존 `role="progressbar"` 패턴 유지 — `.status-card` 안 진행률 바는 그대로.
- 잠긴 체크박스: `disabled` + `aria-disabled="true"`. 체크박스를 감싸는 `<label>`에 `aria-describedby`로 "1단계를 마치면 열립니다" 문구 id를 연결한다.
- 질문 A 선택지 버튼은 `role="radiogroup"` + `aria-label`로 그룹 의미를 전달.
- 대비: `.badge.neutral` 대비비는 [추론]이며 실측은 responsive-tester/visual-reviewer의 스크린샷 검증이 필요하다.

## ⑸ 기존 CSS 변수·클래스 재사용 매핑

| 용도 | 재사용 대상 | 신규 필요 여부 |
|---|---|---|
| 완료 상태 배색 | `.pipeline li.done`(배경 `var(--soft-green)`, 테두리 `#c8d1a0`) | 불필요 |
| 진행중 상태 배색 | `.pipeline li.active`(배경 `var(--soft-blue)`, 테두리 `#c9a08f`) | 불필요 |
| 잠김 상태 글자색 | `var(--muted)` | 불필요 |
| 단계 보조 숫자 라벨 | `.pipeline .state`(12px, 700, `var(--muted)`) | 불필요 |
| 상태 카드 틀 | `.status-card` / `.status-card.is-inline` | 불필요 |
| 진행률 바 | `.progress` / `.progress i` | 불필요 |
| 상태 어휘 배지 | `.badge` / `.badge.safe` / `.badge.warn` / `.badge.neutral` | "진행중" 전용 배지는 `.badge.neutral` 의미 재사용(새 색 없음), 텍스트가 1차 전달 수단 |
| 질문 온보딩 카드 틀 | `.coach-ask-card` 그대로 확장 | 불필요 |
| 자세히 블록 | `.task-item details` / `details[open]` | 불필요 |
| 모바일 1열 전환 | 기존 `@media (max-width: 900px) { .board-status { grid-template-columns: 1fr } }` | 스테퍼에도 같은 브레이크포인트·규칙 적용, 신규 미디어쿼리 불필요 |

**신규로 꼭 필요한 것 1건**: 단계 연결선(스테퍼 칸 사이 가로/세로 선)을 그릴 `::before`/`::after` 선택자 — 색 변수가 아니라 기존 `var(--line)`을 그대로 쓰는 구조적 선 추가다. 그 외에는 신규 CSS 변수 추가를 권고하지 않는다.

## 스크린샷 검증 필요 항목

- `.badge.neutral`을 "진행중" 의미로 오버로드했을 때 warn(주의)과 혼동되는지.
- 잠긴 단계에서 "체크 행만 흐리고 상세 블록은 선명"한 처리가 실제 화면에서 버그처럼 보이는지.
- 모바일 900px 이하에서 스테퍼 세로 1열 + 연결선(`border-left`)이 `.task-item` 레이아웃과 겹치지 않는지.
- 완료 단계의 `<details>` 기본 닫힘 텍스트색과 `.task-item.is-done` 배경 위 대비가 유지되는지.
- 질문 A가 사라진 뒤 질문 B가 카드 맨 위로 올라오는 전환이 레이아웃 점프를 일으키는지.
