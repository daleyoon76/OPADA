### 2-3. 근본 원인 — 표(tbody) 자체가 서버 HTML에 비어 있다 [관측, 강한 근거]

23건 전건에서 회차 데이터가 들어가야 할 `<tbody id="pbancDtlBidTtdoPlcVO"></tbody>`가 **빈 태그**였다.
이건 정적 스냅샷만의 문제가 아니다 — **이번 조사 중 직접 실행한 라이브 재현**으로 재확인했다:

```
$ python3 -c "... S.fetch_onbid(idx1_url) ..."
tbody content length: 0
values_after_label(입찰기간): ''
values_after_label(공매예정가격(원)): ''
minimum_bid_value: ''
```

- 대상 URL: idx1(전북본부 압류재산 공매, `pbctNo=10060291`), 2026-09-22 12시경 실측. 이 공고는 이미 마감이
  지났지만(`handoff.md`의 기존 기록과 일치) 온비드 원문 자체는 여전히 열린다.
- HTML 안에서 이 표를 채우는 JS 함수명(`fn_pbancDtlBidTtdoPlc`, `pbancDtlBidInfVO.pbancDtlBidTtdoPlcVO`)을
  찾았다 — 온비드가 이 표를 **클라이언트 사이드 AJAX**로 채우는 구조라는 뜻이다. `fetch_onbid()`(`src/server.py:847-864`)는
  `urllib`로 최초 HTML만 받고 JS를 실행하지 않으므로, 이 AJAX 호출은 절대 일어나지 않는다.
- **대조(다른 페이지 유형은 실패하지 않는다)**: 같은 방식으로 물건상세(`CltrDtlController`) URL 1건(부산 금정구,
  `docs/80_사용자여정테스트/00_사용자여정_재현가이드_20260920.md:116`)을 라이브로 재확인했다.
  이쪽은 `pbctBgngDt`/`pbctLastDdlnDt` hidden input이 **채워져 있어** ① 단계에서 성공한다
  (`pbctBgngDt: '2026-05-15 17:00'`, `pbctLastDdlnDt: '2027-05-12 17:00'`). 물건상세는 애초에 이 회차표 자체가 없다.

**결론(관측 기반)**: 실패는 "회차 여러 개"가 아니라 **"공고상세(PbancDtlInqController) 페이지 유형" 전체**의
문제로 보인다. 표본 23건이 전부 공고상세이고 전부 hidden input도 비어 있었다(§2-2). 다만 공고상세 페이지 중
이 표 구조를 쓰지 않는 예외가 있는지는 **미확인**이다 — 표본 23건이 전부 같은 구조였을 뿐, "모든 공고상세가
항상 이렇다"는 전수 조사가 아니다.

## 4. `<th>/<td>` 파서를 별도 함수로 추가할 수 있는가 — "가능하다"와 "효과 없다"는 별개다

- **코드 구조만 보면 가능하다** [관측]. `values_after_label()`은 `class="tit01"` span 전용 정규식이고,
  다른 필드 14개가 공유한다(`known-pitfalls.md` 기존 기록과 일치). 기존 함수를 고치지 않고
  `schedule_table_rounds(text)` 같은 새 함수를 `class_text()`·`block_text()` 옆에 독립적으로 추가하는 데
  구조적 장애물은 없다. `split_sections()`가 이미 "입찰일정 및 장소" 절을 통째로 떼어 주므로
  (`sections.get("입찰일정 및 장소")`), 새 파서는 그 조각 안에서 `<th>`/`<td>`를 읽으면 된다.
- **그러나 §2-3의 근본 원인 때문에, 이 새 파서를 어떻게 잘 만들어도 표본 23건에서 값을 하나도 못 뽑는다.**
  파싱 대상 `<tbody>`가 애초에 비어 있기 때문이다. 표 마크업 인식 문제(known-pitfalls.md의 설명)를 고치는 것과
  "값이 서버 HTML에 존재하는가"는 다른 문제이고, 지금 병목은 후자다.
- 이 결함을 실제로 고치려면 아래 중 하나가 필요해 보인다(**미확인·설계 미검토** — 이 조사 범위 밖):
  1. 헤드리스 브라우저로 JS 실행 후 DOM을 읽는다(의존성 추가, 현재 스택과 이질적).
  2. `fn_pbancDtlBidTtdoPlc`가 호출하는 실제 AJAX 엔드포인트를 찾아 별도로 호출한다(엔드포인트 URL·파라미터 미확인 — 이번 조사에서 여기까지는 시도하지 않았다. 범위 밖으로 남긴다).
  3. hidden input이 채워지는 물건상세(`CltrDtlController`) URL로 안내를 유도한다(단, 공고상세만 있고 물건상세 링크가 없는 공고엔 적용 불가 — 이번 표본 23건 전부 물건상세 링크 보유 여부는 미확인).
- 즉 항목 4의 답: **"별도 함수로 분리하는 것은 쉽다. 다만 그 함수를 아무리 잘 만들어도 지금 확인된 23개 표본에서는 고쳐지지 않는다."**

## 5. `"round"` 필드(`src/server.py:2180`)의 실사용처 [관측]

```python
"round": values_after_label(text, "회차") or "",
```

- `app.js` 전체에서 참조 0건(§3). API 응답에는 실리지만 화면 어디에도 쓰이지 않는다.
- 표본 23건 전건에서 이 필드 값이 **동일한 문자열**로 나왔다: `"회차 전체 검색어 삭제 메시지입니다. --> 메세지 입니다."`
  이건 실제 회차 데이터가 아니라, 페이지 어딘가의 검색/필터 UI 문구를 `values_after_label()`이 잘못 집은 것으로 보인다
  (known-pitfalls.md의 "메뉴 문구를 먼저 집습니다" 함정과 같은 패턴). 이 필드는 **현재 상태로는 신뢰할 수 없고,
  회차별 데이터를 전혀 들고 있지 않다** — "이미 회차별 데이터를 어느 정도 들고 있는지" 질문의 답은 **"들고 있지 않다, 0건"**이다.
