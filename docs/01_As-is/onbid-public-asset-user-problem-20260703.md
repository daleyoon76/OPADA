# 온비드 공공자산 공고 사용자 문제정의

작성시각: 2026-07-04 00:26 KST

## As-is

온비드는 공공자산 공고와 물건정보를 제공하지만, 실제 사용자는 다음 단계를 직접 수행해야 한다.

1. 관심 공고 검색
2. 공고문과 첨부문서 열람
3. 물건정보, 입찰정보, 공고 본문 비교
4. 입찰 전 제출서류와 마감 확인
5. 입찰보증금, 사용료, 부가세, 보험료, 잔대금 등 비용 확인
6. 낙찰 후 의무와 기한 확인
7. 현장조사, 인허가, 권리관계, 수익성 등 별도 확인

## 사용자 병목

| 병목 | 설명 | 서비스 기회 |
| --- | --- | --- |
| 정보 분산 | 공고목록, 물건정보, 입찰정보, 첨부문서가 나뉘어 있음 | 공고별 단일 리포트 |
| 문서 난이도 | 공고문은 법령·계약·입찰 용어가 많음 | 온비드 용어사전 기반 쉬운 설명 |
| 일정 착오 | 입찰서 제출, 보증금 납부, 서류 제출, 낙찰 후 신청 기한이 다름 | 일정표와 마감 리스크 카드 |
| 서류 누락 | 개인/법인/사업자 유형별 준비서류가 다름 | 사용자 유형별 체크리스트 |
| 비용 오해 | 사용료 외 부가세, 보험료, 보증보험, 물품대부료 등이 존재 | 비용 후보 표 |
| 책임 범위 오해 | 현장설명 생략, 영업수익 미보장, 인허가 책임이 공고에 숨어 있음 | 확인 질문 자동 생성 |

## To-be

`OnBid Public Asset Doc Agent`는 사용자가 공고를 찾은 뒤 직접 해야 하는 해석 작업을 다음 형태로 줄인다.

- 공고 핵심 1문장
- 일정표
- 제출서류 체크리스트
- 비용 후보
- 낙찰 후 의무
- 사용자 확인 질문
- 원문 근거 링크
- 용어 설명

## 핵심 설계 원칙

| 원칙 | 설명 |
| --- | --- |
| 원문 우선 | 공공데이터와 AI 요약보다 공고 원문과 첨부문서 확인을 우선한다. |
| 근거 표시 | 모든 리스크와 체크리스트에 원문 근거 또는 API 출처를 표시한다. |
| 판단 제한 | 낙찰 가능성, 수익률, 법률·권리관계 판단은 하지 않는다. |
| 사용자 자기결정 | 사용자가 담당기관·전문가에게 물어볼 질문을 생성한다. |
| 공공데이터 활용 | KAMCO/온비드 API와 용어사전을 리포트 품질의 근거로 삼는다. |
