## 2. 배경 및 목적

### 해결하려는 문제

* 초보자·소상공인이 온비드 공고문 해석에 막혀 ‘일정, 필수 서류, 납부 비용, 주요 리스크’를 정확히 파악하기 어려움  
* 수십 페이지에 파편화된 정보로 인해 핵심 의무와 절차를 놓치거나, 해석 실수·정보 과부하로 입찰 자체를 포기하게 됨  
* 전문가 컨설팅은 비용 부담이 크고, 기존 ChatGPT 등 AI 요약툴은 온비드 특화 데이터 및 신뢰성 근거가 부족함

### 제품 목표

* 온비드 공고 URL/번호 입력만으로 공고문과 KAMCO 공공데이터 API를 AI가 동시 분석
* 일정표, 제출서류 체크리스트, 비용 후보, 리스크 카드 및 확인 질문을 원문 근거와 함께 구조화 리포트 형태로 실시간 제공  
* 사용자 유형별(개인·사업자·법인·예비창업자) 맞춤 체크리스트 및 준비 순서 제시  
* 공고 해석에 걸리던 시간을 ‘수 시간 → 수 분’으로 단축, 분석 비용도 전문가 컨설팅 대비 1% 미만으로 절감 기대

## 3. 대상 사용자

* **주 사용층:**
  * 온비드 공공자산(부동산/동산 등) 입찰에 관심 있으나 경험이 부족한 개인 및 소상공인
  * 반복적으로 여러 공고를 검토해야 하는 부동산 컨설턴트, 예비창업자, 창업지원기관 담당자

* **사용 환경:** 반응형 웹 기반 (데스크톱/모바일/태블릿)

* **기술 숙련도:** 비개발자 및 일반 사용자 중심(법률지식·공공입찰 경험이 부족한 고객 포함)

## 4. 핵심 요구사항

### 사용자 스토리 (User Stories)

* [입찰 초보자]는 공고문 해석이 복잡해서 포기하지 않도록, ‘공고 URL만 입력하면’ 입찰 일정과 절차를 자동 정리된 리포트로 확인할 수 있어야 한다.
* [소상공인/예비 창업자]는 놓치기 쉬운 제출서류와 비용, 리스크 항목을 명확히 파악하고, 입찰 실수를 사전에 방지할 수 있어야 한다.
* [컨설턴트/기관 실무자]는 다수의 공고를 효율적으로 비교·분석하여 반복 작업 시간을 단축할 수 있어야 한다.

### 기능적 요구사항 (Functional Requirements)

* **FR-01:** 사용자는 온비드 공고 URL 또는 번호를 입력할 수 있어야 하며, 시스템은 KAMCO 공공데이터 API 및 공고문(첨부파일 포함)을 파싱하여 표준 JSON 구조로 분석한다.
* **FR-02:** AI는 입찰 일정, 제출서류, 보증금 및 추가 비용, 유의사항/리스크 등 핵심 정보를 추출하여 ‘원문 근거’와 함께 구조화 리포트로 제공해야 한다.
* **FR-03:** 사용자 유형(개인/개인사업자/법인/예비창업자)에 따라 별도의 준비 체크리스트와 D-Day 기반 준비 순서를 자동 안내한다.
* **FR-04:** 사용자는 리포트를 PDF로 저장·다운로드할 수 있어야 한다.
* **FR-05:** 회원별 분석 이력(공고/리포트)을 안전하게 저장/조회할 수 있어야 한다.

### 비기능적 요구사항 (Non-Functional Requirements)

* **NFR-01 (성능):** 공고 리포트 생성 요청 후 60초 이내 결과 제공
* **NFR-02 (보안):** OAuth2 기반 인증, 개인정보 암호화 저장, LLM API 전송 시 개인정보 마스킹
* **NFR-03 (가용성):** 서비스 월간 업타임 99.5% 이상
* **NFR-04 (확장성):** 동시 500명의 리포트 분석 요청 지원, 자동 스케일링

## 5. 인수 조건 (Acceptance Criteria)

**AC-01 (FR-01 기준):**
* Given: 사용자가 로그인 후 메인화면에 진입해 있다.
* When: 온비드 공고 URL 또는 번호 및 사용자 유형을 입력 후 ‘분석하기’ 버튼을 누르면
* Then: 시스템은 해당 공고 정보를 API 및 원문 파싱으로 분석하여, 60초 이내에 표준화된 구조화 리포트 화면을 표시해야 한다.

**AC-02 (FR-02 기준):**
* Given: 공고 분석 결과 화면(리포트 대시보드)에 진입한 경우
* When: 사용자가 ‘입찰 일정’, ‘제출서류’, ‘비용 후보’, ‘리스크’ 각 항목을 클릭하면
* Then: 해당 항목의 추출값과 ‘원문 근거(페이지/조항 링크)’가 함께 표시되어야 한다.

**AC-03 (FR-03 기준):**
* Given: 사용자가 회원가입 시 ‘예비창업자’ 유형을 선택한 상태
* When: 새로운 공고를 분석 요청하면
* Then: 리포트의 체크리스트 및 준비 순서가 ‘예비창업자’에 적합하도록 분기되어 제시되어야 한다.

## 6. 제외 범위 (Out of Scope)

* 나라장터(G2B), 법원경매 등 온비드 외 다른 플랫폼 연동 기능(Phase 2 이후)
* Slack, 이메일 알림 연동 등 커뮤니케이션 기능
* 다수 공고·고급 대시보드 등 기관·전문가용 B2B 기능 (Phase 3)
* 낙찰가율/경쟁률 예측, 투자 추천·수익률 산정 등 자문/자동 의사결정 기능 전체
* HWPX 리포트 출력, 전문가 매칭 및 심화 커뮤니티 기능

## 7. 사용자 플로우 (User Flow)

**메인 플로우:**

1. 랜딩 페이지 접속 – 서비스 소개 및 샘플 리포트 확인
2. 회원가입 및 로그인(선택)
3. 온비드 공고 URL 또는 번호·사용자 유형 입력
4. 분석 진행 프로그레스 바(데이터 조회→파싱→정합성 체크→리포트 생성)
5. 구조화 리포트(요약/일정/서류/비용/리스크/Q&A) 대시보드 제시
6. PDF 다운로드(선택)
7. 분석 이력 저장 및 마이페이지에서 조회

**엣지 케이스:**

* API 호출 실패, 공고문 파싱 오류 발생 시: “해당 공고는 자동 분석이 불가합니다. 원문 확인 후 문의 바랍니다” 안내 후 메인으로 이동
* 빈 상태(처음 접속 시): “분석할 온비드 공고 URL/번호를 입력해 주세요” 안내, 샘플 리포트 버튼 제공

## 8. 데이터 모델 (Data Model)

**Report (리포트)**
| 필드명         | 타입    | 설명                           |
|----------------|---------|--------------------------------|
| id             | string  | 리포트 고유 ID                 |
| user_id        | string  | 사용자 고유 ID                 |
| public_notice_id| string  | 온비드 공고(고유번호)          |
| parsed_data    | object  | 공고문 및 API 분석 결과(JSON)   |
| analysis_date  | date    | 분석 일시                      |
| status         | string  | 분석 상태 (완료/실패)          |

**User (회원)**
| 필드명     | 타입    | 설명                     |
|------------|---------|--------------------------|
| id         | string  | 고유 ID                  |
| email      | string  | 이메일                   |
| password   | string  | 암호(해시)               |
| user_type  | string  | 사용자 유형(개인/사업자 등) |
| created_at | date    | 생성일                   |

**RawDocument (공고 원문)**
| 필드명     | 타입    | 설명                    |
|------------|---------|-------------------------|
| id         | string  | 고유 ID                 |
| url        | string  | 공고/첨부파일 URL       |
| type       | string  | 파일 유형(pdf/hwp 등)   |
| content    | text    | 추출 텍스트             |
| report_id  | string  | 연관 리포트 ID          |

## 11. 성공 지표 (Metrics & KPI)

* **KPI-01:** 출시 1개월 내 가입자 500명, 3개월 내 3,000명 확보
* **KPI-02:** 리포트 분석 후 PDF 다운로드율 60% 이상
* **KPI-03:** 결제 전환율 10% 이상(첫 리포트 후 구독 또는 유료 구매)
* **KPI-04:** 1개월 내 사용자 NPS +30 이상

## 12. 기술 스택 제안

* **프론트엔드:** Next.js (SSR·반응형 및 빠른 UI 개발에 적합, 사업계획서 명시)
* **백엔드:** Node.js (빠른 API 개발, 다양한 AI/파싱 모듈과 연계 용이)
* **데이터베이스:** PostgreSQL(관계형, 구조적 데이터 저장 및 확장성)
* **인프라:** AWS(EC2/Lambda/S3) or Vercel(Next.js 기준) – 자동 배포, 스케일링 지원
* **외부 API:** KAMCO 온비드 Open API(공고/물건/입찰/용어사전), OpenAI/Claude 등 LLM API
