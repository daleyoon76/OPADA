## 1. 물건관리번호 하이픈 — **에러가 아니라 규격이다**

### 우리 질문

부동산 물건상세 조회서비스(`OnbidRlstDtlSrvc2` / `getRlstDtlInf2`) 호출 시 물건관리번호에 하이픈이 없으면 데이터가 조회되지 않는다.

### 캠코 답변

- OpenAPI 서비스를 받으려면 **하이픈을 붙여야 한다.**
- 이는 오류가 아니라 **API 규격**이다.
- 확인 경로: 공공데이터포털 **마이페이지 > 오픈 API 활용 현황** → 각 OpenAPI 서비스정보의 **참고문서 내려받기**.
- 참고문서에 **샘플데이터가 명시**되어 있다. 각 API별 참고문서를 재확인하라는 요청을 함께 받았다.

### 우리에게 미치는 영향

- **코드 수정 불필요.** 2026-09-07 에 이미 `api_cltr_mng_no()`(4-4-6 변환)를 넣어 하이픈을 붙여 호출하고 있다(`src/server.py:900`).
- 다만 그때는 「온비드 측 형식 불일치 결함」으로 보고 신고했는데, **규격이므로 신고 건이 아니다.**
  - 온비드 물건상세 페이지 hidden input 이 하이픈 없이(`20260800045167`) 주는 것과 API 가 하이픈을 요구하는 것은 서로 다른 계층이다.
  - 「API 가 하이픈 없는 입력도 받게 해 달라」는 우리 요청 2번(초안 76행)은 **철회 대상**이다.
- 규격 문서를 우리가 읽지 않은 것이 원인이다 — 참고문서 `OpenAPI활용가이드_NN_….docx` 26개는 아직 다운로드하지 않았다(`docs/90_MVP개발/08_온비드자료실_오픈API28종_조사_20260907.md` 부록 B).

### 후속

- [ ] 참고문서 다운로드 후 6종의 파라미터 형식 규격을 대조한다 — **상위 세션이 브라우저로 별도 진행**한다.
  - 특히 `pbancMngNo`(공고관리번호)·`pbctCdtnNo`(회차 조건번호)의 규격 형식 확인. 현재 코드는 페이지가 준 문자열을 그대로 넘긴다.

## 2. 트래픽 — **100,000건은 운영계정 기준이다**

### 우리 질문

6개 서비스 일 허용 건수를 100,000건으로 회신받았으나(2026-09-02), 포털 각 서비스 페이지에는 개발계정 1,000 / 운영계정은 활용사례 등록 시 신청하면 증가 가능으로 표시된다. 우리 계정은 개발계정이다. 100,000건이 운영계정 기준인지, 운영계정 전환 조건은 무엇인지.

### 캠코 답변

- **100,000건은 운영계정 기준이다.**
- 공공데이터포털 **마이페이지 > 오픈 API 활용 현황** 에 **API별 「운영계정 신청하기」 버튼**이 있다.

### 확정된 값

| 계정 | 일 허용 건수 | 조건 |
| --- | --- | --- |
| 개발계정 (현재 우리) | **1,000** | 자동승인 |
| 운영계정 | **100,000** | 활용사례 등록 후 API별 「운영계정 신청하기」 |

- 2026-09-07 포털 실측(26종 전부 1,000)과 캠코 회신(100,000)의 불일치는 **계정 등급 차이**로 해소됐다.
- 우리가 지금 쓸 수 있는 한도는 **6종 각 일 1,000건**이다.

### 후속

- [ ] 운영계정 전환 신청 — **상위 세션이 브라우저로 별도 진행**한다.
  - 전제: 활용사례 등록. 결선 시연 전 필요 여부는 별도 판단(시연은 공고 3건 분석이라 1,000건으로 충분).
