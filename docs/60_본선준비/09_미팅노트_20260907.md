| 출처 | 물건관리번호 |

| 온비드 물건상세 페이지의 hidden input | `20260800045167` |

| 코드 | 재산유형 | 건수 |

전부 담겨 있다. "임대나 위탁 물건은 API에 없을 것"이라던 어제 추측은 틀렸다.

**물으려던 것 하나는 API 안에 답이 있었다**

```

```

화면에 0으로 나오던 그 값이다. 0원이 아니라 온비드가 「비공개」로 다루는 값이었다.

### 말할 것

> 원인은 번호 형식이었습니다.
> 온비드 물건상세 페이지의 숨은 입력값은 물건관리번호를 하이픈 없이 `20260800045167`로 줍니다.
> 그런데 공공데이터 API는 `2026-0800-045167` 형식만 받습니다.
>
> 하이픈이 없으면 오류가 아니라 200 응답에 `NODATA_ERROR`가 옵니다.
> 인증이나 권한 문제로 보여서 저희가 두 달 동안 다른 데를 찾고 있었습니다.
>
> 같은 기관의 두 창구가 같은 번호를 다른 형식으로 다루는 것이라,
> 다른 이용자도 같은 데서 막힐 수 있어 보입니다. 개선을 검토해 주실 만한 사안인지 여쭙고 싶습니다.
>
> 참고로 저희가 여쭙려던 것 하나는 API 안에 답이 있었습니다.
> 최저입찰가격이 없는 공고는 「비공개」라고 API가 명시해 줍니다. 화면에 그대로 반영하겠습니다.

## 4. 질문 3개

### ① 공개 화면을 읽는 방식이 괜찮은가

**배경**: API가 되더라도 크롤링이 완전히 없어지지 않는다.
사용자가 붙여 넣는 주소에는 `onbidCltrno` 같은 내부 일련번호만 있고 관리번호가 없다.
관리번호를 얻으려면 페이지를 먼저 열어야 한다. 이 구조는 남는다.

> API 연결이 됐으니 값은 API로 옮기겠습니다.
> 그런데 사용자가 붙여 넣는 주소에는 물건관리번호가 없어서, 그 번호를 얻으려면 페이지를 한 번 열어야 합니다.
> 이렇게 공개 화면을 읽는 것이 괜찮은지 여쭙고 싶습니다.
