# ONBID_API_SERVICE_KEY 발급 안내

- 작성: 2026-09-02
- 대상: `src/server.py`의 `PUBLIC_DATA_ENDPOINTS` 6종
- 성격: **보조 경로**입니다. 키가 없어도 온비드 공개 원문 분석은 그대로 동작합니다.

## 발급 절차

1. 공공데이터포털에 회원가입·로그인합니다 — https://www.data.go.kr/
2. 아래 6종을 각각 열어 `활용신청`을 누릅니다.
3. 신청 목적을 적고 제출합니다. 오픈API는 대부분 자동 승인됩니다.
4. `마이페이지 > 인증키 발급현황`에서 일반 인증키를 확인합니다 — https://www.data.go.kr/iim/api/selectAPIAcountView.do
5. 발급받은 키를 환경변수로 넣고 서버를 다시 띄웁니다.
   ```
   export ONBID_API_SERVICE_KEY='<발급받은 키>'
   python3 src/server.py
   ```

## 트래픽 허용 건수

| 계정 | 일 허용 건수 | 조건 |
| --- | --- | --- |
| **개발계정 (현재 우리)** | **1,000** | 자동승인 |
| 운영계정 | **100,000** | 활용사례 등록 후 API별 「운영계정 신청하기」 |

- 근거: 캠코 정인기 차장 회신 2026-09-08. 원문 `15_캠코_회신_API형식_트래픽_20260908.md`
- ⚠️ 2026-09-02 기재는 「6종 각각 일 100,000건」이었으나 그 값은 **운영계정 기준**입니다. 우리 계정은 개발계정이라 실제 한도는 6종 각 1,000건입니다.
- 발급 후 실제 값은 `마이페이지 > 오픈API 활용현황(승인) > 오픈API 선택 > 활용신청 상세기능정보`에서 확인합니다.
- 운영계정 신청 버튼은 `마이페이지 > 활용신청 현황`에 API별로 있습니다. **미신청이며 배포 시점까지 보류입니다.**

## 운영계정 신청 절차 (2026-09-08 폼 실물 확인)

- 경로: 공공데이터포털 > 마이페이지 > **활용신청 현황**(`/iim/api/selectAcountList.do`) > `[승인]` 해당 API > **「운영계정 신청하기」**
- 신청 단위는 **API별**입니다. 6종이면 같은 폼을 6번 채웁니다.
- 활용사례 등록은 별도 절차가 아니라 **이 폼 안에 통합**되어 있습니다.
- 폼의 일일 트래픽 칸은 `100000` 으로 표시됩니다.
- 필수 입력 11개입니다.
  - 활용사례명(50자) · 분류체계 · **서비스 URL** · 서비스 설명(4000B) · 기능 및 서비스 화면(4000B)
  - 대표 이미지 썸네일(파일 · 248x93px 권장) · 개발자 유형 · 개발자 소재지 · 서비스 개시일
  - 자동등록방지(캡차) · 이용허락범위 동의
- 🔴 **보류 사유는 「서비스 URL」입니다.** 「활용된 서비스를 확인할 수 있는 URL」을 요구하는데 지금은 로컬 실행뿐입니다.
- **재개 조건: 서비스를 배포해 공개 접속 URL이 생겼을 때.** 출시 전 베타 배포라도 URL이 있으면 그때 신청합니다.
- 활용사례는 포털에 **공개 게시**됩니다. 작성 시 `CLAUDE.md` 금지표현 가드레일을 적용합니다.
- 재개 시 쓸 확정값 — 개발자 유형 `1인 창업 기업` · 소재지 `경기도` · 분류체계 `재정금융` · 개발유형 `웹사이트` · 국내외 `국내`.
- 심의여부는 **자동승인**으로 표시되나, 그것이 활용사례 등록 심사까지 포함하는지는 **미확인**입니다.

## 키를 넣으면 달라지는 것

- 화면 하단 출처 영역의 문구가 `보조 데이터: ...`에서 연결 상태 문구로 바뀝니다.
- `tests/public-data-status.spec.js`의 API 상태 단언이 의미를 갖게 됩니다. 다만 그 단언은 `#report-hero`를 보는데 문구는 `#source-notes`로 옮겨졌으므로, 키를 넣어도 셀렉터 수정이 함께 필요합니다.
