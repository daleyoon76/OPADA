## 2단계. 실제 서비스 화면 직접 조작

`Hometest_op-agentic`(별도 워크트리, `agentic-journey` 브랜치)의 `src/server.py`를 포트 19200으로 띄워(`python3 server.py 19200`) OpenClaw 브라우저 도구로 처음부터 끝까지 직접 조작했다.

1. 1p(유형·목적 선택, "내 유형과 목적을 입력해주세요") → 2p(온비드 URL 입력, "샘플 불러오기" 버튼으로 샘플 공고 사용) → 3p(분석 결과: "일치" 배지 + 핵심 정보 · 확인 사항 · 온비드 연결 세 묶음) 확인.
2. 준비 보드 1단계(공고 확인: "공고 유형 확인" · "입찰기간 확인" 체크박스, "확인 필요" 경고와 "처음으로 돌아가시겠어요?" 재시작 분기) 체크.
3. 2단계(서류 준비: "공동입찰인가요?" · "대리입찰인가요?" 질문에 "예"를 누르면 서류 그룹이 "공통 8개 서류"에 "공동입찰 3개 서류"가 추가되는 변화를 직접 확인, "내 보관함으로 보내기" 버튼 확인) 체크.
4. 3단계(입찰 참여: "최저입찰가격 확인" + 입찰기간·입찰 장소·최저입찰가격 정보 리스트 + "입찰 참여, 궁금한 점을 물어보세요" AI 코치 질문창) 진입.
5. AI 코치 질문창에 실제 질문 2건을 입력해 실제 응답을 확인했다.
   - "입찰보증금은 얼마를 내야 하나요?" → 배지 **공매 절차 일반 안내** → "입찰보증금은 예정가격의 100분의 5 이상이어야 합니다. 다만, 공고에서 별도로 정한 경우에는 그에 따릅니다."
   - "이 공고의 최저입찰가격은 얼마인가요?" → 배지 **공고 원문 기반 답변** → "이 공고의 최저입찰가격은 660,000원입니다."
6. 각 화면을 스크린샷으로 남겼다. 이 스크린샷을 슬라이드 내용·용어의 근거로 썼다.

실제 화면에 쓰인 라벨(예: "공고 원문 기반 답변", "공매 절차 일반 안내", "AI 코치에게 물어보기", "내 보관함으로 보내기")을 발표노트의 요약 표현보다 우선해 슬라이드에 그대로 반영했다. 다만 발표노트의 세 번째 배지 "담당기관 문의 필요"는 이번 조작에서는 실제로 띄워 보지 못했다(안전 경계상 낙찰 가능성·적정가 질문을 일부러 넣지 않았다). 2절 슬라이드의 배지 목록에는 발표노트 원문대로 세 가지를 모두 표기했다.

## 품질 검증

1. **엠대시 0건.** `grep -c "—" index.html` 실행 결과 **0**. 작성 직후 직접 실행해 확인했다.
2. **overflow 0건.** 로컬 정적 서버(`python3 -m http.server`)로 띄우고 OpenClaw 브라우저 도구로 9장 전체를 스크린샷 대조했다. `document.querySelectorAll('.slide')`를 순회해 `scrollHeight - clientHeight`가 9장 모두 `0`임을 코드로 확인했다(텍스트 겹침·박스 탈출 없음의 근거).
3. **데모 슬라이드 스크린샷 가독성.** 처음 삽입한 전체 페이지 스크린샷은 `object-fit: cover`로 좌우가 잘려 제목·질문 문구가 보이지 않는 문제가 있었다. Pillow로 핵심 카드 영역만 정밀하게 크롭하고 `object-fit: contain`으로 바꿔 전체 내용이 보이도록 수정한 뒤 재확인했다.
4. **PDF 변환 확인.** `/Applications/Google Chrome.app/.../Google Chrome --headless=new --print-to-pdf`로 변환해 `mdls -name kMDItemNumberOfPages`로 9페이지, `sips -g pixelWidth -g pixelHeight`로 960×540(16:9 비율) 정확히 들어감을 확인했다. Read 도구로 1페이지와 4페이지(스크린샷 포함 슬라이드)를 직접 열어 잘림·겹침이 없음을 육안으로도 대조했다. 검증에 쓴 `deck_check.pdf`는 삭제했다.

## v01과 달라진 점

- **실제 화면 반영.** v01은 발표노트 요약 텍스트를 그대로 옮긴 느낌이었다. v02는 실제 서비스를 포트 19200에서 직접 띄워 1~3단계 전체(공동입찰 질문에 따른 서류 리스트 변화, AI 코치 질문창 실제 응답 2건 포함)를 조작한 뒤, 그 화면에 쓰인 라벨을 그대로 슬라이드에 반영했다.
- **데모 슬라이드에 실제 화면 스크린샷 2장 삽입.** "분석 결과를 확인해주세요" 카드와 "공고 원문 기반 답변" 배지가 뜬 AI 코치 응답 화면을 크롭해 넣었다. v01은 텍스트 설명만 있었다.
- **엠대시 완전 제거.** v01은 4·6·8번 슬라이드에 엠대시가 8곳 있었다. v02는 전부 마침표·콜론·접속사로 바꿔 0건이다.
- **AI 코치 라벨을 실제 화면 문구로 교체.** v01은 "AI 질문창"이라는 발표노트 요약 표현을 그대로 썼다. v02는 실제 화면 라벨 "AI 코치에게 물어보기", 배지 "공고 원문 기반 답변" · "공매 절차 일반 안내" · "담당기관 문의 필요"를 그대로 썼다.

처음에는 v02 파일을 그 자리에서 직접 고쳤다. 그런데 사용자가 "v02는 그대로 두고 v03을 새로 만들어 달라"고 명시적으로 다시 요청했다. 그래서 수정 전 v02(`05_발표슬라이드_v02_20261015/`, `03_발표평가_10분피치_초안_v02_20261014.md`)는 git 이력(커밋 `ac381d9`·`bac80e1`)에서 그대로 복원했고, 이 디렉터리(`06_발표슬라이드_v03_20261015/`)와 새 발표노트 파일(`07_발표평가_10분피치_초안_v03_20261015.md`)에 아래 수정 다섯 가지를 담았다. v01·v02는 수정 전 상태로 보존돼 있다.

수정 다섯 가지는 다음과 같다.

1. **1번 슬라이드(문제, 2/9)**: "공고에서 챙길 항목이 흩어져 있다"는 캠코를 깎아내리는 느낌의 표현을 뺐다. 제목을 "공매에 익숙하지 않은 사람에게는 친절한 AI 가이드가 필요합니다"로 바꾸고, "온비드 공고를 처음 보는 분들은 대체로 두 가지 부담을 느낍니다"로 부드럽게 시작한 뒤 절차 생소함(1겹)·챙길 항목을 한눈에 알아보기 어려움(2겹)의 흐름으로 재구성했다.
2. **2번 슬라이드(해결, 3/9)**: 제목을 "나만의 AI 공매 가이드가 있다면?"으로 바꿨다. 본문은 그대로 뒀다.
3. **4페이지(데모)**: 제목을 "백문이 불여일견, 직접 보여드립니다"에서 "데모 시연"으로 단순화했다. 발표노트 3절 제목도 맞춰서 "데모 시연"으로 바꿨다.
4. **5페이지(시스템 구조)**: `Hometest_op-agentic/src/server.py`를 다시 읽고(`PUBLIC_DATA_ENDPOINTS`, `do_POST`의 `/api/ask` 처리, 첨부 다운로드 경로 등) 서비스 여정 중심이던 수직 4단(클라이언트→서버→AI계층→저장) 구조를 실제 시스템 객체 중심으로 바꿨다. 데이터 출처 3개(온비드 공개 원문 HTML, 온비드 내부 JSON 엔드포인트, 공공데이터포털 온비드 API)를 독립된 외부 시스템 박스로 올리고, AI 계층(`/api/ask`)은 서버 상자 내부 하위 요소로, localStorage는 클라이언트 상자 내부 하위 요소로 내렸다. 화살표는 "세 출처에서 데이터 수집", "공고 URL 요청·분석 결과·AI 응답"이라는 흐름 설명만 보조로 붙였다.
