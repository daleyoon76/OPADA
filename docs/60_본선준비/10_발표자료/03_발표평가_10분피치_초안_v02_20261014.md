## 1. 문제 (70초)

- "공매에 익숙하지 않은 분들에게도 친절한 AI 가이드가 있으면 좋겠습니다."
- 온비드 공고를 처음 보는 사람은 대체로 두 가지 부담을 느낀다
  - 1겹: 공매·입찰 **절차 자체가 아직 낯섦**. 전자입찰이 뭔지, 서류를 언제 어디에 내는지, 다음에 뭘 해야 하는지 감이 잘 서지 않음
  - 2겹: **무엇을 챙겨야 하는지 한눈에 알아보기 어려움**. 공고문·첨부문서·물건정보·입찰정보·보증금·제출서류를 하나씩 찾아 확인해야 함
- 두 가지 부담이 겹치면 중도 포기로 이어지기 쉬움
  - 절차를 모르는 채로 서류를 준비하다 일정 착오·서류 누락·비용 오해 발생
  - 더 큰 문제는 무엇을 모르는지조차 모르는 상태로 마감을 맞는 것

## 2. 해결. 나만의 AI 공매 가이드가 있다면? (150초)

- 핵심 전환: 요약 도구에서 **공매를 몰라도 끝까지 같이 가는 가이드**로
  - 절차를 모르는 사람(문제 1겹)은 순차 가이드가, 이 공고 정보가 흩어진 문제(문제 2겹)는 자동 정리가 각각 받는다
- 입력 단계(마법사형 3단계)
  1. 내 유형·검토 목적 선택(초보/경험자, 임대/매각 등)
  2. 온비드 공고 URL 입력
  3. 분석 결과 확인(핵심 정보·확인 사항·온비드 연결, 세 묶음으로 정리)
- 준비 보드(순차 3단계, 앞 단계를 끝내야 다음이 열림)
  1. **공고 확인** — 입찰기간 만료·목적 불일치를 감지해 경고, "처음으로" 재시작 분기
  2. **서류 준비** — 공동입찰·대리입찰 여부를 질문으로 받아 서류 리스트를 자동 조건화, "내 보관함" 저장
  3. **입찰 참여** — 입찰기간·장소·최저입찰가격 등 참여 전 챙길 정보 리스트, **AI 질문창**
- AI 질문창
  - 이 공고에 대한 사실 질문 → 공고 원문 기반 답변
  - 공매 절차 일반 질문(전자입찰 진행 방식 등, 이 공고에 매이지 않은 것) → 일반 절차 지식으로 답변
  - 안전 경계 그대로 유지: 낙찰 가능성·적정가·법적 판단에는 답하지 않고 원문·담당기관 확인 안내

## 3. 데모 시연 (240초, 4분)

- "백문이 불여일견입니다. 직접 보여드리겠습니다."
- 라이브 링크: `https://suzuki-suse-bush-dictionaries.trycloudflare.com`
- 시연 순서(동원님 시뮬레이션 기준)
  1. 유형·목적 선택 → URL 입력 → 분석 결과 확인
  2. 준비 보드 1단계(공고 확인) → 2단계(서류 준비, 공동입찰/대리입찰 질문 → 서류 리스트 변화) → 3단계(입찰 참여)
  3. AI 질문창에 실제 질문 1~2개(공고 사실 질문 + 공매 절차 일반 질문)
- ⚠️ 링크는 무료 cloudflare 임시 터널. 발표 당일 접속 가능 상태인지 사전 재확인 필요(아래 "발표 전 운영 리스크" 참고)

## 4. 시스템 구조 (60초)

- "방금 보신 기능을 구현하기 위해 서비스 구조는 이렇게 만들었습니다"
- 실제 시스템 객체를 중심으로 구성하고, 그 위에 서비스·데이터 흐름을 화살표로 보조 표시(슬라이드에서는 다이어그램으로 시각화)
  - **데이터 출처 3개**(독립된 외부 시스템): 온비드 공개 원문 HTML(기본 경로), 온비드 내부 JSON 엔드포인트(회차별 입찰기간 등 공식 문서화 API로는 못 받는 값), 공공데이터포털 온비드 API(보조 경로, 원문과 교차 대조)
  - **서버**: 세 출처에서 데이터를 받아 교차 대조한다. 내부에 **AI 계층**(`/api/ask`)을 둔다. AI 계층은 공고 사실·준비 보드 상태·공매 절차 일반 지식 세 근거를 받아 안전 경계가 박힌 프롬프트로 Gemini/Vertex 모델을 호출
  - **클라이언트**: 브라우저에서 동작하는 단일 페이지 앱. 마법사·준비 보드·AI 질문창 전부 하나의 화면 안에서 상태 전환한다. 내부에 **localStorage**를 둬 로그인 체계 없이 "내 보관함"·"관심 공고"를 보관
  - 화살표는 세 출처에서 서버로 데이터가 모이는 흐름과, 서버·클라이언트 사이에 공고 URL 요청과 분석 결과·AI 응답이 오가는 흐름을 보조로 표시
- 차별점: 단순 LLM 요약이 아니라 원문 파싱, 공공데이터, 내부 API 세 소스를 교차 대조한 뒤에만 AI가 답한다

## 5. 사업화 (70초)

- ⚠️ 가격은 기존 사업계획서(2026-07-04 작성, Bizketch 생성분 포함)의 가격 범위 안에서 확정한 제안이다. SAM·SOM은 이 가격을 기준으로 다시 계산한 값이다. 실제 고객 대상 실증 검증은 아직 안 됨. 발표 시 "실증 검증 전 제안"임을 명시할 것
- 타깃 고객
  - 온비드 입찰 경험이 적은 개인
  - 공공자산을 사업 기회로 검토하는 소상공인·자영업자
  - 공공자산 활용 예비·초기 창업자
  - 창업지원기관·컨설턴트·액셀러레이터(기관용 반복 수요)
- 가격 체계(확정 제안)
  - 건별 리포트: 9,900원(1건, 전체 체크리스트·비용 후보·PDF 저장 포함). 무료 샘플은 요약과 리스크 3개까지만 제공하므로, 완전한 리포트는 가격 범위의 상단으로 정함
  - 월 구독: 베이직 19,000원(월 5건), 프로 49,000원(월 15건). 무제한이 아니고 건수 제한을 둠. AI 모델 호출 비용이 드는 서비스라 운영 비용을 관리하고, 구독 건당 단가(베이직 3,800원, 프로 3,267원)를 건별 단가보다 낮게 둬 반복 사용자에게 구독 전환 유인을 만듦
  - 전문가/기관용 패키지: 월 99,000원부터(월 50건). 여러 공고 비교, 상담용 리포트 관리
- 시장 규모(가격 기준 재계산)
  - SOM(초기 3년 목표): 건별 리포트 3만 건 × 9,900원 = 2억 9,700만 원. 구독자 500명(베이직 350명, 프로 150명 가정)의 연 매출 = (350×19,000원 + 150×49,000원)×12개월 = 1억 6,800만 원. 합계 연 매출 약 4억 6,500만 원으로 기존 추정 범위(3억~5억 원) 안에 들어옴
  - SAM(유효 시장): SOM이 SAM의 약 5% 전환율이라고 가정하면 SAM은 4억 6,500만 원 ÷ 0.05로 약 93억 원이 되어, 기존 추정치(연간 약 50억~100억 원)와 범위가 합치함. 전환율 가정 자체도 실증 검증 전이라는 점을 함께 밝힘

## 6. 향후 계획 (40초)

- 현재 범위: 사용자가 온비드에서 직접 물건을 찾아 **링크를 복사해 와야** 시작됨(입력부터 시작하는 범위로 의도적으로 좁힘)
- 다음 단계: **AI 챗봇 기반 물건 검색**으로 확장
  - 사용자가 조건(지역·가격대·재산유형)을 자연어로 말하면 AI가 온비드에서 후보 물건을 찾아 바로 이 가이드로 연결
  - 지금은 "가져온 공고를 해석"하는 도구, 다음은 "원하는 공고를 찾아주는" 도구로
- 그 외 백로그
  - "내 보관함" 저장 데이터의 재방문 복원(현재는 저장만 되고 불러오기 미구현)
  - 서류 체크리스트 조건 축 확장(현재는 공동입찰·대리입찰 두 가지만 질문)
