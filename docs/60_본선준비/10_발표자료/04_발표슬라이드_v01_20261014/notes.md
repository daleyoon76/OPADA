- 폰트는 `"Outfit", "Pretendard Variable", "Noto Sans KR", sans-serif` — 외부 CDN 링크 없이 시스템 설치 폰트에만 의존하므로 인터넷 연결 없는 발표장에서도 깨지지 않음.

## 실제로 확인한 것

1. **렌더링 확인**: 저장소 안에서 `python3 -m http.server 8743`으로 디렉터리를 띄우고(`file://` 프로토콜은 브라우저 보안 정책상 차단되어 정적 서버로 대체), OpenClaw 브라우저 도구로 9장 전체를 스크린샷해 직접 대조.
2. **1차 확인에서 발견한 문제와 수정**
   - 4번(시스템 구조) 슬라이드: 콘텐츠가 720px 슬라이드 높이를 11px 초과해 하단 "차별점" 박스가 페이지 번호·다음 슬라이드와 겹침. `.arch` 간격(14px→10px), 박스 패딩, `diff-box` 여백을 줄여 overflow를 0으로 만듦 — `scrollHeight - clientHeight` 측정으로 0 확인.
   - 1/3/5/6/7번 슬라이드: 콘텐츠가 슬라이드 상단에 몰리고 하단에 빈 공간이 크게 남음(레이아웃 불균형). `.body`에 `justify-content: center`를 적용하는 `.center` 클래스를 추가해 콘텐츠 블록을 세로 중앙에 배치. 단, 내부에 `flex:1`이 걸린 래퍼(`.layer-grid`, `.demo-wrap`)가 있으면 중앙 정렬이 먹히지 않아 해당 `flex:1`을 제거.
   - 수정 후 재스크린샷으로 1/3/4/5/6/7번 모두 상하 여백 균형과 겹침 해소를 재확인.
3. **9장 전체 overflow 일괄 점검**: `document.querySelectorAll('.slide')`를 순회해 `scrollHeight - clientHeight`가 전부 `0`임을 코드로 확인(텍스트 겹침·박스 탈출 없음의 근거).
4. **인쇄/PDF 변환 확인**
   - OpenClaw 브라우저 도구의 `pdf` 액션(CDP `Page.printToPDF`)은 `@page` 규칙을 무시하고 Letter 용지로 변환해, 슬라이드가 좌우로 잘림을 확인(2회 재현 — width/height 파라미터를 직접 줘도 동일).
   - `@page { size: 1280px 720px landscape; }`의 **px 단위**가 원인으로 추정되어, 96px=1in 환산값인 `13.333in 7.5in`로 교체.
   - `/Applications/Google Chrome.app/.../Google Chrome --headless=new --print-to-pdf`로 재검증 — 9장 전부 16:9 비율로 한 페이지씩, 잘림·겹침 없이 정확히 들어감을 PDF 페이지 이미지로 직접 대조.

## 남은 보완점 / 제출 시 유의사항

- **PDF 변환 방법에 주의할 것.** 위 실측대로, `@page { size: 13.333in 7.5in; margin: 0; }` 설정은 Chrome 헤드리스 CLI(`--print-to-pdf`)에서는 정확히 반영됨을 확인했다. 다만 OpenClaw 내장 브라우저 도구의 `pdf` 액션(CDP 직접 호출)에서는 반영되지 않았던 전례가 있으므로, 실제 제출본을 만들 때는 **Chrome 브라우저에서 직접 Cmd+P(인쇄) → "PDF로 저장"**을 사용하고, 미리보기에서 슬라이드 한 장이 한 페이지에 정확히 들어가는지(잘림 없음) 반드시 재확인할 것. 다른 PDF 변환 도구(예: 온라인 변환기, 타 브라우저)를 쓰면 같은 문제가 재발할 수 있다.
- 데모 라이브 링크(`suzuki-suse-bush-dictionaries.trycloudflare.com`)는 무료 cloudflare 임시 터널이라 발표 당일 접속 가능 여부를 별도로 재확인해야 한다(8번 슬라이드에 이미 경고로 포함).
- 5절(사업화) 수치는 모두 기존 사업계획서(2026-07-04)의 추정치이며 실제 고객 실증 검증 전이라는 점을 슬라이드 하단 각주로 명시했다.
