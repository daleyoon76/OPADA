## 2. 서비스 소개

### 2-1. 한 문장

- 서비스명: OnBid Public Asset Doc Agent (데일컴퍼니 윤동원)

### 2-2. 누구의 어떤 문제를 다루는가

대상은 온비드를 처음 이용하는 일반 이용자, 소상공인, 공공자산을 활용하려는 창업자입니다.

- 온비드 공고는 이미 공개되어 있습니다. 문제는 접근이 아니라 **준비**입니다.
- 처음 입찰하는 사람은 공고문, 첨부문서, 물건정보, 입찰정보, 보증금, 제출서류를 각각 따로 확인해야 하고, 그 과정에서 일정 착오·서류 누락·비용 오해가 생깁니다.
- 더 큰 문제는 **공고가 말하지 않는 항목**입니다. 무엇을 모르는지조차 모르는 상태로 마감을 맞습니다.

### 2-3. 동작 방식

주소를 입력하면 세 단계가 이어집니다.

1. **공고 가져오기** — 온비드 공개 원문에서 공고/물건명, 재산유형과 처분방식, 입찰기간, 가격/보증금, 공고기관, 입찰방식을 추출해 한 화면에 모읍니다. 이용자가 고른 검토 목적(임대/대부 · 매각/공매 · 창업 공간 탐색)과 공고 유형이 맞는지 함께 표시합니다.
2. **준비 보드** — 일정, 제출서류, 비용 항목을 체크리스트로 만들고, 이용자 유형(개인 · 개인사업자 · 법인 · 예비창업자)에 따라 우선순위를 정합니다.
3. **누락 점검** — 공고에 값이 없어 확인이 필요한 항목과, 담당기관에 물어볼 질문 문장을 따로 뽑아 보여 줍니다. 요약이 아니라 **빈칸을 지목**하는 것이 이 서비스의 핵심입니다.

추출한 값은 규칙 기반으로 정리하고, 그 위에 AI가 쉬운 말 설명과 다음 행동 제안을 보조로 붙입니다. AI 연결이 끊겨도 규칙 기반 결과만으로 같은 화면 구성이 유지됩니다.

### 2-5. 데이터 출처와 처리 방식

- 기본 경로는 **온비드 공개 페이지 원문**입니다. 이용자가 붙여 넣은 물건상세 주소의 공개 화면에서 값을 읽습니다.
- 보조 경로는 **공공데이터포털의 온비드 OpenAPI 6종**(공고 목록·공고 상세·공고 입찰 상세·부동산 물건 목록·부동산 물건 상세·물건 입찰 상세)입니다. 인증키가 있을 때만 호출하며, 원문과 대조하는 용도로 씁니다.
- 화면에 표시하는 값은 온비드 값을 그대로 쓰고 임의로 바꾸지 않습니다. 원문에 없는 값은 추정하지 않고 「확인 필요」로 남깁니다.
- 조회한 데이터를 가공해 자사 화면에 표시하는 방식에 별도 제약이 없다는 점은 2026-09-02 회신으로 확인했습니다.

## 5. 확인 요청 사항

회신에서 수락해 주신 "데이터 항목 해석의 정확성 확인"에 해당하는 부분입니다. 화면에 쓰는 용어와 설명 문구가 온비드 실제 기준과 어긋나지 않는지 짚어 주시면 됩니다.

화면에 표시하는 항목은 다음과 같습니다.

- 분석 미리보기: 공고/물건명, 유형(재산유형 / 처분방식), 입찰기간, 가격/보증금
- 공고 요약: 공고번호, 공고기관, 입찰방식, 가격/보증금
- 준비 보드: 일정 알림, 비용 항목, 제출서류, 담당기관 확인 질문

특히 아래 세 가지를 여쭙고자 합니다.

1. **재산유형과 처분방식의 표기** — 화면에는 "기타일반재산 / 임대"처럼 온비드 값을 그대로 씁니다. 일반 이용자에게 이 표기가 통하는지, 풀어 써야 하는 용어가 있는지 확인 부탁드립니다.
2. **가격 항목의 명칭** — 화면에서는 "가격/보증금"으로 묶어 표시합니다. 매각과 임대에서 이 항목이 가리키는 값이 다른데, 구분해서 불러야 할 명칭이 있는지 확인 부탁드립니다.
3. **최저입찰가격이 제공되지 않는 경우** — 회차 선택형 공고는 원문에 단일 최저입찰가격이 없습니다. 이때 화면에 어떻게 표시하는 것이 적절한지 의견을 구하고자 합니다.
