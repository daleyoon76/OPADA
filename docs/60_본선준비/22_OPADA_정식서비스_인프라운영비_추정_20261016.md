# OPADA 정식 서비스 전환 시 인프라 운영비 추정

- 작성: 2026-10-16
- 배경: 지금까지 OPADA는 맥미니 로컬 서버(launchd, `Hometest_op/src/server.py`)에서 cloudflare 임시 터널로만 노출되는 데모 단계다. 이 문서는 "정식 서비스로 출시한다면"이라는 가정 아래, 20번 문서(`20_OPADA_리포트_건당원가_실측_20261016.md`)가 실측한 LLM API 변동비에 인프라 고정비·가변비를 더해 전체 운영비 그림을 만든다.
- 조사 범위: 호스팅(프론트+API 서버), 데이터베이스, 도메인, 모니터링/로그 비용. 인건비·마케팅비는 기존 사업계획서 수치를 그대로 인용해 비교만 한다.
- 표기 규칙: 20번 문서와 동일하게 `[관측]`(직접 확인) · `[추론]`(관측에서 논리적으로 도출, 1차 확인 안 됨) · `[인용]`(2차 소스) · `[제안]`(이번 문서가 새로 제시하는 미확정 안)을 구분한다.

## 1. 레포에 확정된 배포 계획이 있는가 — 없다 `[관측]`

## 2. 지금 서비스 특성 — 로그인·DB 없음, 전부 클라이언트 상태 `[관측]`

`Hometest_op-agentic/src/server.py`(2,602줄)와 `src/app.js`를 직접 읽고 grep했다.

- **서버 쪽 임포트에 DB 관련 모듈이 없다.** `server.py` 상단 임포트는 `html`·`http.cookiejar`·`json`·`os`·`re`·`subprocess`·`sys`·`threading`·`time`·`urllib.*`·`collections.deque`·`datetime`·`http.server`·`pathlib`뿐이다. `sqlite3`도 임포트하지 않는다. 외부 DB 의존성이 전혀 없다. `[관측]`
- **로그인·회원가입·세션 기능이 없다.** `login`·`signup`·`session`·`auth`·`database` 키워드로 grep한 결과, 서버 쪽에 걸린 것은 Vertex AI 인증 토큰(`auth application-default print-access-token`, `Authorization: Bearer` 헤더)뿐이고 사용자 인증과는 무관하다. `app.js`의 "회원가입"은 온비드 자체 가입 절차를 안내하는 화면 문구(280행)이고, 이 서비스 자신의 회원가입이 아니다. `[관측]`
- **상태 저장은 전부 브라우저 `localStorage`다.** `app.js`의 829~996행에서 체크리스트 진행 상태·경험 수준 등을 `window.localStorage.getItem/setItem`으로 읽고 쓴다. 서버는 요청마다 온비드 원문을 크롤링하고 LLM을 호출해 결과를 반환하는 **무상태(stateless) 요청-응답 구조**이고, 서버 쪽 전역 변수 중 영속 저장소에 해당하는 것은 없다(Vertex 토큰 캐시 `_VERTEX_TOKEN`만 메모리에 있고 재시작하면 사라진다). `[관측]`

**판단**: 지금 당장 이 기능(URL 입력 → 리포트 생성)만 정식 배포해도 DB는 필요 없다. 하지만 사업계획서가 제시하는 가격 모델(건별 결제, 월 구독, 과거 리포트 저장)로 가려면 다음이 서버 쪽에 새로 필요해진다. `[추론]`

- 회원 식별(이메일/비밀번호 또는 소셜 로그인)
- 결제 내역과 구독 상태
- 월 구독 쿼터 집계("이번 달 몇 건 썼는지")
- 과거 리포트 저장(Pro 요금제 공지 사항)
- 개인정보보호법상 수집 항목(이름·이메일·연락처)의 구조화 보관(사업계획서 14.4절이 이미 이 의무를 지적했다)

**즉 "DB가 필요 없다"는 지금의 데모 단계에만 해당하고, 사업계획서가 전제하는 유료화 모델로 가는 순간 DB는 선택이 아니라 필수가 된다.** `[추론]`

## 3. 트래픽 가정 — v04 슬라이드의 SOM 재계산값을 그대로 쓴다 `[인용]`

가정의 출처는 `docs/60_본선준비/10_발표자료/08_발표슬라이드_v04_20261015/`의 실제 슬라이드(`index.html`)와 발표노트(`notes.md`)다. 이 디렉터리는 **읽기만 했고 수정하지 않았다**(사용자 지시).

- 가격(확정 제안, `index.html` 946행 등): 건별 리포트 **4,900원**, 구독 베이직 **9,900원/월**(월 5건), 프로 **19,900원/월**(월 15건), 전문가/기관 **39,900원부터/월**(월 50건).

| 항목 | 금액(만 원) | 비율 |
| --- | ---: | ---: |
| 인건비 | 15,500 | 75.6% |
| 마케팅비 | 2,000 | 9.8% |
| **인프라 비용(서버/API)** | **1,800** | **8.8%** |
| 관리비 | 1,200 | 5.9% |

- 기존 추정 "인프라비용 1,800만 원/년"은 이번 세부 추정(연 약 84만~145만 원, §4.5 + §5)보다 **약 12~21배 크다.**
- 차이가 나는 이유는 다음 세 가지로 추론한다. `[추론]`
  1. 사업계획서가 작성될 때 참고한 PRD 초안(§1)은 "AWS(EC2/Lambda/S3) or Vercel"을 언급하며 더 무거운 클라우드 아키텍처를 염두에 뒀을 가능성이 있다. 지금 레포는 Python 표준 라이브러리만 쓰는 경량 서버이고, 이 전제가 다르면 비용도 다르게 나온다.
  2. 사업계획서 §14.3(재무 함정)이 스스로 적은 LLM 비용 추정은 "GPT-4o 기준 공고 1건당 300~600원, 월 1,000건 처리 시 월 30~60만 원"이다. 지금 실측(20번 문서)은 Gemini Flash-Lite 계열 모델로 건당 1~3원 수준이라, 사업계획서가 가정한 모델보다 원가가 수백 배 낮다. 즉 **모델 선택 자체가 비용 구조를 크게 바꾼다.**
  3. "인프라 비용" 항목이 서버·DB·API 비용 외에 다른 운영 잡비(장애 대응, 개발 도구 구독 등)를 뭉뚱그려 포함했을 가능성이 있다(사업계획서 원문에 세부 내역이 공개돼 있지 않아 확인 불가).
- **결론: 기존 "인프라비용 1,800만 원/년"은 뭉뚱그린 보수적 추정이었고, 지금 구현된 경량 스택과 저가 LLM 모델을 기준으로 다시 계산하면 훨씬 작아진다.** 다만 이 비교는 "사업계획서가 가정한 아키텍처"와 "실제 구현된 아키텍처"가 다를 수 있다는 한계를 안고 있다 — 같은 대상을 비교하는 것이 아닐 수 있다. `[추론, 한계 명시]`

## 7. 월간 총 운영비와 손익분기

### 7.1 월간 총 운영비 (인건비·마케팅비 별도 표기)

| 구분 | 월 비용 |
| --- | --- |
| 인프라 고정비(호스팅+DB+도메인+모니터링) | 약 6.4만~6.7만 원 |
| LLM API 변동비(기본 시나리오, 분석+질문5회) | 약 2.2만 원 |
| LLM API 변동비(최악 시나리오) | 약 5.4만 원 |
| **총 운영비(인프라+LLM, 기본 시나리오)** | **약 8.6만~8.9만 원/월** |
| **총 운영비(인프라+LLM, 최악 시나리오)** | **약 11.8만~12.1만 원/월** |

### 7.2 순수 인프라+LLM 비용 기준 손익분기 (인건비·마케팅비 제외)

- 공헌이익률이 거의 100%에 가깝다. 건별 리포트 가격 4,900원에서 변동비(건당 1~8.25원)를 뺀 공헌이익은 거의 4,900원 그대로다.
- 손익분기 건수 = 월 인프라 고정비(약 67,000원) ÷ 공헌이익(약 4,899원) ≈ **월 약 14건**.
- **월 14건의 건별 리포트만 팔아도 인프라 고정비는 전부 회수된다.** 인프라비용만 떼어 보면 이 사업의 성패에 미치는 영향은 거의 없다.

### 7.3 인건비·마케팅비까지 포함한 전체 손익분기 (사업계획서 틀 재사용, 가격은 v04로 갱신)

- 월 고정비 = 인건비(1,292만 원) + 마케팅비(167만 원) + 이번 추정 인프라(약 6.5만 원) + LLM(기본 시나리오, 약 2.2만 원) ≈ **약 1,467.7만 원/월**.
- 건별 판매만으로 커버: 1,467.7만 원 ÷ 4,900원 ≈ **약 2,995건/월**(연 약 35,940건). §3의 SOM 3년차 목표(연 3만 건 = 월 2,500건)보다 **약 20% 더 많이 팔아야** 손익분기에 도달한다.
- 구독만으로 커버: 혼합 ARPU(베이직 70%·프로 30% 비율 유지, (350×9,900+150×19,900)/500 = 12,900원) 기준, 1,467.7만 원 ÷ 12,900원 ≈ **약 1,138명**. §3의 SOM 3년차 목표(500명)의 **약 2.3배**가 필요하다.

### 7.4 결론

- **인프라비용은 이 사업의 손익분기를 좌우하는 변수가 아니다.** 월 운영비 전체(약 8.6만~12.1만 원)는 월 고정비(약 1,467.7만 원)의 1% 미만이다.
- 손익분기를 실제로 좌우하는 것은 인건비·마케팅비다. 이는 사업계획서 §14.2~14.3이 이미 지적한 내용(CAC 과소추정, 마케팅비 부족)과 같은 방향의 결론이지만, **이번 조사로 "인프라비용이 커서 BEP가 밀린다"는 가능성은 근거 있게 배제할 수 있게 됐다.**
- SOM 3년차 목표(건별 3만 건 + 구독자 500명)만으로는 인건비·마케팅비를 포함한 전체 BEP에 아직 못 미친다(건별 기준 약 20% 부족, 구독 기준 약 2.3배 부족). 이 격차는 인프라가 아니라 **매출 규모 자체**에서 온다.
