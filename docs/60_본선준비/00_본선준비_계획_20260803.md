## 3. P0 — 본선 전 반드시 닫아야 할 항목

### P0-1. 발표자료를 v06 포지션으로 재작성

기존 `20_제출초안/04_발표평가_대비_5분피치_초안_20260704.md`는 2026-07-04 작성본으로 `공고 해석 리포트`, `원문 근거가 붙은 PDF 리포트`를 전면에 내세웁니다. 그러나 실제 제출한 v06 신청서는 포지션을 `AI 우선 준비 보드`로 바꿨고, `MVP_신청서반영_핸드오프_20260705.md` 8절 금지표현 목록에 `PDF 리포트`와 `공고 해석 리포트`가 들어 있습니다. 제출 문서와 발표 문서가 어긋난 상태입니다.

- 완료 기준: 제출한 v06 신청서의 문제 정의·기능·제외 범위와 발표자료의 서술이 일치하고, 금지표현 12종이 발표자료에 0건.
- 검증 방법: 금지표현 목록으로 발표자료 원고 전문 검색, 0건 확인.
- 산출물 위치: `60_본선준비/10_발표자료/`

### P0-2. MVP 라이브 시연 가능 상태 확보

현재 MVP는 `90_MVP개발/app/` 의 Python 표준 라이브러리 기반 로컬 서버(`127.0.0.1:8975`)입니다. 파일 최종 수정은 2026-07-06이고, 실행 확인 기록은 Windows 경로 기준입니다. 현재 macOS 환경에서의 기동·분석·AI 호출은 아직 확인하지 않았습니다.

- 완료 기준: 현재 작업 기기에서 서버 기동 → 온비드 URL 분석 → 준비 보드 생성 → AI 우선 체크리스트 표시까지 한 번에 통과.
- 검증 방법: 기동 후 임대/대부와 매각/공매 각 1건을 실제 URL로 처리하고 응답 값을 기록.
- 확인해야 할 전제:
  - AI 경로는 `GEMINI_API_KEY`/`GOOGLE_API_KEY` 또는 gcloud 토큰 기반 Vertex 호출입니다. 발표 환경에서 인증이 되는지 사전 확인이 필요합니다.
  - 공공데이터 API는 `ONBID_API_SERVICE_KEY` 보조 경로이며, 없어도 공개 원문 분석이 기본 경로입니다.

### P0-3. 시연용 샘플 공고 URL 갱신

핸드오프에 기록된 샘플 2건은 입찰기간이 각각 `2026-07-06 10:00`, `2026-07-08 17:00` 종료입니다. 현재 시점에서는 마감이 지났으므로 시연 중 페이지가 사라지거나 상태가 달라질 수 있습니다.

- 완료 기준: 결선 시점에 진행 중인 임대/대부 1건, 매각/공매 1건의 URL을 확보하고 파서가 정상 추출.
- 검증 방법: 새 URL 2건으로 분석 결과(공고번호, 물건번호, 유형, 입찰기간, 담당기관, AI 상태)를 기록.
- 리스크: 온비드 공개 페이지 HTML 구조가 바뀌면 파서 보강이 필요합니다(핸드오프 10절에 기재된 기존 한계).

### P0-4. 멘토링 안내 메일 수신 및 일정 확보

- 완료 기준: 별도 안내 메일 수신 후 멘토링 참여 여부·일정·제출물 요구사항을 이 문서에 반영.
- 확인 사항: 희망기업 대상이므로 참여 신청이 별도인지, 결선 평가에 반영되는지.
- 증빙서류 재검토가 전 과정에서 진행된다는 문구가 있으므로, 제출한 사업자등록증·신분증·개인정보 동의서와 현재 사실관계가 일치하는지 함께 확인합니다.
