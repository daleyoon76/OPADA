## 기동 — launchd 상시화 (2026-09-08 적용)

서버와 터널 모두 LaunchAgent 로 올라가 있다. 손으로 띄우지 않는다.

| 에이전트 | plist | 하는 일 |
| --- | --- | --- |
| `com.dale.hometest-server` | `~/Library/LaunchAgents/com.dale.hometest-server.plist` | `src/server.py` (127.0.0.1:8975) |
| `com.dale.hometest-ngrok` | `~/Library/LaunchAgents/com.dale.hometest-ngrok.plist` | `ngrok http 8975` |

- 둘 다 `RunAtLoad` · `KeepAlive` 다. 죽으면 자동 재시작되고 로그인 시 자동 기동된다.
- 로그는 `~/Library/Logs/hometest-op/` 에 쌓인다.

### 자주 쓰는 명령

```
launchctl list | grep hometest                          # 상태
launchctl kickstart -k gui/501/com.dale.hometest-server # 서버만 재기동
curl -s http://127.0.0.1:4040/api/tunnels               # 발급 주소 확인
```

- `src/server.py` 를 고쳤으면 **서버 재기동이 필요하다**. 위 `kickstart -k` 한 줄이면 된다.
- `index.html`·`app.js`·`styles.css` 는 **재기동이 필요 없다.** 요청마다 디스크에서 읽는다(`src/server.py:1907` `translate_path`) `[관측]`.
- 어느 쪽이든 **ngrok 은 건드리지 않는다.** 포트 8975 만 유지되면 주소는 그대로다.

### 🔴 TCC 권한 — 이것이 없으면 서버 에이전트가 뜨지 않는다

- `~/Documents` 는 macOS 가 보호한다. LaunchAgent 는 권한 요청을 띄우지 못해 `Errno 1 Operation not permitted` 로 죽는다.
- 2026-09-08 에 **전체 디스크 접근 권한**을 부여해 해소했다.
  - 대상: `/Library/Developer/CommandLineTools/usr/bin/python3`
  - 🔴 **`/usr/bin/python3` 이 아니다.** 그것은 별도 스텁 바이너리이고, 권한을 줘도 통하지 않았다(실측).
  - plist 의 `ProgramArguments[0]` 도 같은 CommandLineTools 경로여야 한다.
- 기기를 옮기거나 권한이 초기화되면 이 절차를 다시 밟는다.

## 유의점

- **브라우저로 열면 ngrok 안내 페이지가 먼저 뜬다.** `Visit Site` 를 눌러야 화면이 나온다.
  - 무료 요금제의 고정 동작이다. curl·API 호출은 그냥 통과한다.
  - 외부인에게 주소를 줄 때는 이 한 단계를 함께 안내한다.
- **서버에 인증이 없다.** 주소를 아는 사람은 누구나 분석을 돌릴 수 있다.
  - 지금은 이 기기에 `ONBID_API_SERVICE_KEY` 가 없어 실질 피해가 없다.
  - 🔴 키를 넣고 공개해 두면 **남이 우리 일 1,000건 한도를 소비한다.** 그때는 접근 제한을 함께 건다.
- SSRF 는 닫혀 있다 — `src/server.py:687` 이 `onbid.co.kr` 외 호스트를 거부한다 `[관측]`.
