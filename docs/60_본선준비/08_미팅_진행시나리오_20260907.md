## 0. 이 회의의 목적을 한 문장으로

캠코 시스템 담당자에게 **우리 화면이 온비드 데이터를 어떻게 읽어서 보여 주는지** 보여 드리고, **그 해석과 용어가 온비드 기준과 어긋나는 곳이 없는지** 짚어 달라고 부탁하는 자리다.

- 투자 설명회도, 사업성 심사도 아니다. 정인기 차장은 온비드 시스템 담당자이고, 본인이 "시스템 담당자 입장에서 답변 가능한 것만 추렸다"고 두 번 밝혔다.
- 그러므로 "이 서비스가 좋아 보이나요"를 묻지 않는다. "이 항목을 이렇게 읽는 게 맞나요"를 묻는다. 질문이 구체적일수록 상대가 답하기 쉽다.
- 서비스가 "공고 URL을 넣으면 준비 항목을 챙겨 준다"는 단순한 구조인 것은 약점이 아니다. 시스템 담당자가 15분 안에 검토할 수 있는 크기라는 뜻이다.

## 2. 시연 대본 (10분)

시연은 「내가 만든 것」을 자랑하는 시간이 아니라, **「온비드 원문에서 이 값을 가져와 이렇게 보여 준다」**를 담당자 눈으로 검증받는 시간이다. 그래서 각 단계마다 온비드 원문 탭을 옆에 두고 대조한다.

### 2-1. 도입 30초

> "온비드를 처음 쓰는 분이 공고를 열었을 때, 입찰 준비에 무엇이 필요한지 한 화면에서 챙기도록 도와주는 도구입니다. 입찰 여부나 법률 판단, 수익성, 낙찰 가능성은 다루지 않고, 원문과 담당기관 확인을 우선하도록 안내합니다. 오늘은 실제 공고 두 건으로 보여 드리고, 화면의 용어와 해석이 온비드 기준과 맞는지 차장님께 확인을 부탁드리겠습니다."

### 2-2. 임대 건 — 서초 비타민스테이션 (예술의전당) · 4분

1. 온비드 원문 탭을 먼저 열어 보여 준다. "이 공고를 그대로 넣겠습니다."
2. 우리 화면으로 돌아와 검토 목적을 `임대/대부 공고 검토`로 두고 URL을 붙여 넣어 분석한다. (약 2초)
3. 분석 결과에서 **원문과 대조**한다. 공고/물건명, 재산유형/처분방식 「기타일반재산 / 임대」, 입찰기간, 담당기관 예술의전당.
   - 말할 것: "화면의 값은 전부 온비드 공개 원문에서 가져온 것이고, 저희가 임의로 바꾸지 않습니다."
4. **가격이 0으로 표시되는 것**을 그 자리에서 짚는다.
   - 말할 것: "이 공고는 회차 선택형이라 원문에 단일 최저입찰가격이 없습니다. 지금은 0으로 나오는데, 이 표시가 적절한지는 뒤에 여쭙겠습니다." (3절 질문 3으로 연결)
5. 준비 보드를 만든다. 체크리스트 5건, 미확인 항목, 담당기관 확인 질문이 나뉘어 표시된다.
   - 말할 것: "공고가 말하지 않는 항목은 저희가 추정하지 않고 「담당기관에 확인할 질문」으로 따로 모읍니다."

### 2-3. 매각 건 — 부산 금정구 교육연구시설 (소해원) · 3분

1. 탭을 `공고 가져오기`로 되돌린다. **이 단계를 빼먹으면 URL 입력란이 없다.**
2. 목적을 임대로 둔 채 매각 URL을 분석한다. 「불일치」가 뜬다.
   - 말할 것: "사용자가 임대를 찾고 있는데 매각 공고를 넣으면 이렇게 알려 줍니다."
3. 목적을 `매각/공매 공고 검토`로 바꾼다. 「일치」로 바뀐다. 최저입찰가격 450,000,000원, 감정가, 유찰 회수가 표시된다.
   - 말할 것: "매각에서는 가격 항목이 최저입찰가격을 가리키고, 임대에서는 다른 값을 가리킵니다. 이 명칭을 어떻게 불러야 맞는지도 여쭙겠습니다." (3절 질문 2로 연결)

### 2-4. 있으면 좋은 한 장면 · 1분

- 차장님이 원하시면 **다른 공고 URL을 채팅으로 받아 즉석에서 넣는다.** 준비한 것만 보여 주는 게 아니라는 인상을 준다.
- 마감된 공고를 넣으면 알림 맨 위에 「입찰 마감 지남」이 뜬다. 옛 주소를 넣어 보셔도 화면이 깨지지 않는다.

### 2-5. 시연 중 하지 않을 것

- AI 코치 문구를 길게 읽지 않는다. 모델명·공급사명을 말하지 않는다. "규칙과 원문 기반 정리에 보조 설명을 붙인 것"으로만 소개한다.
- 사업 모델, 과금, 사용자 수 이야기를 꺼내지 않는다. 차장님 소관이 아니고 회신에서도 선을 그었다.
- 「자동」·「대행」·「예측」·「리포트」라는 단어를 쓰지 않는다 (금지표현).

## 3. 항목 해석 확인 (20분) — 오늘의 본론

사전 자료 5절 질문 3건을 그대로 쓴다. 각 질문은 **화면을 가리키면서** 묻는다.

| 순서 | 화면 위치 | 질문 | 메모할 것 |
| --- | --- | --- | --- |
| 1 | 분석 미리보기 · 유형 | "「기타일반재산 / 임대」처럼 온비드 값을 그대로 쓰는데, 일반 이용자에게 풀어 써야 하는 용어가 있습니까?" | 풀어 쓸 용어 목록, 캠코가 쓰는 공식 표기 |
| 2 | 분석 미리보기 · 가격/보증금 | "매각과 임대에서 이 항목이 가리키는 값이 다른데, 구분해서 불러야 할 명칭이 있습니까?" | 매각/임대 각각의 정식 명칭 |
| 3 | 비타민 건 · 가격 0 | "회차 선택형 공고처럼 단일 최저입찰가격이 없을 때 화면에 어떻게 표시하는 게 적절합니까?" | 권장 표시 문구, 원문 어느 항목을 대신 보여야 하는지 |

질문 3건이 끝나면 준비 보드를 열어 **항목을 위에서부터 하나씩** 읽고 "이 항목을 이렇게 부르고 이렇게 설명하는 게 맞습니까"를 짧게 확인한다. 일정 알림 → 비용 항목 → 제출서류 → 담당기관 확인 질문 순서다.

- 차장님이 "그건 공고마다 다르다"고 하면 그것도 답이다. "공고마다 다르므로 원문 확인 안내를 붙인다"로 정리한다.
- 정정을 받으면 그 자리에서 되풀이해 말하고 메모한다. 마무리에서 낭독한다.

## 4. URL 변경·운영 리스크 (10분) — 듣는 시간

정인기 차장이 9/2 회신에서 "자세한 얘기는 회의 때 말씀드리겠습니다"라고 남긴 유일한 주제다.

- 내용: OpenAPI 조회 항목이 바뀌면 엔드포인트 URL이 반드시 바뀌고(예: `Srvc2` → `Srvc3`), 3개월 병행 유지 후 종료되며, 이용자는 신규 인증키를 다시 발급받아야 한다. 행안부 지침이다.
- 우리에게 의미: 현재 기본 경로는 온비드 공개 페이지 원문이고 API 6종은 보조 경로다. 그래도 API를 쓰는 순간 이 변경 주기를 따라가야 한다.
- 물어볼 것 2가지
  1. 변경 사전 통보는 어떤 채널로 오는가 (공공데이터포털 공지 / 메일 / 기타).
  2. 공개 페이지(원문 크롤링) 쪽도 화면 구조가 바뀌는 주기나 예고가 있는가.
- 하지 않을 것: "그러면 저희는 어떻게 해야 하나요"라고 해법을 요구하지 않는다. 지침 설명을 듣고 우리가 대응 방식을 정한다.

## 5. 자유 논의에서 확인할 것 (12분)

1. **상시 접속 주소가 필요한가.** 회의 중에는 임시 주소(ngrok)를 채팅으로 드린다. 회의 뒤에도 써 보시겠다면 그때 상시 배포를 결정한다. 여기서 약속하지 않고 "필요하시면 준비해 안내드리겠다"까지만 말한다.
2. **인증키 발급 절차**에서 막힐 때 문의할 곳이 있는가 (`06_공공데이터_인증키_발급안내` 기준).
3. **후속 연락 방법.** 정정 사항을 반영한 뒤 화면을 다시 보여 드릴 수 있는지, 메일로 충분한지.
4. 박선호 차장이 들어오셨다면 결선 발표(10월) 관련 안내 일정을 아는지 한 번만 여쭙는다. 모른다고 하면 넘어간다.
