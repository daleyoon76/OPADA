# 첨부파일 정보 추출 템플릿 (1차 초안)

작성: 2026-09-17 · 작성자: 맹민희(비서) — daleyoon76@gmail.com 개인 프로젝트

## 1. 목적

온비드 공고는 본문만 읽으면 정보가 없고, 첨부파일(PDF/HWP/HWPX)에 알맹이가 있는 경우가 흔하다. 2026-09-11 정답 세트 작업에서 176항목 기준 재현율이 본문만 9%, 첨부까지 읽으면 59%로 확인됐다.

이 문서는 "본문은 비어 있고 첨부에만 정보가 있는" 극단 사례 10건을 사람이 직접 읽고, 첨부 안에 어떤 정보가 어떤 형태로 있는지 정리한 것이다. 목표는 서버 배선이 아니라 **다음 단계(자동 추출기 설계)를 위한 재료**다.

## 2. 표본 출처와 선정 방법

- 원천은 2026-09-11 표본조사(`~/Documents/Dev/.opada-survey/`, 이 git 저장소 밖)의 23건이다. 첨부는 이미 다운로드·텍스트화돼 있다(`samples.json`·`manifest.json`·`text/*.txt`).
- **선정 기준**: 공고 본문 텍스트 길이 대비 첨부 텍스트 길이의 배율(첨부자수 ÷ 본문자수)이 큰 순서로 정렬해 상위 10건을 골랐다.
  - 23건 중 3건(idx 1·2·3, 압류재산 공매공고)은 첨부가 아예 없어 배율 계산 대상에서 제외했다.
  - 나머지 20건 중 배율 상위 10건이 아래 표다. 11위(idx 13, 56.1배)와 10위(idx 9, 56.2배) 차이가 0.1배로 근소하지만, 배율 기준을 그대로 적용해 10위까지 끊었다.
  - 첨부가 스캔본이라 텍스트 추출 자체가 실패한 건(idx 17의 등기부등본·건축물대장)은 **그 첨부만** 표본에서 제외했다. 공고 전체는 다른 첨부(공매공고·매매계약서·감정평가서)에 첨부 텍스트가 5만 자 넘게 있어 포함을 유지했다.
- 첨부 텍스트는 기존 스크립트(`.opada-survey/extract_text.py`)가 매직바이트로 PDF·HWP·HWPX를 판별해 이미 뽑아 둔 것을 그대로 썼다. 이번 작업에서 서버 코드나 추출 스크립트를 새로 만들지 않았다.

## 4. 정보 유형별 추출 템플릿

### 4.1 물건/사업 대상 명세 (필지·호실·시설 스펙)

- **원문 인용** (`11_1.txt`): "구분 소재지 지번 지목(용도) 면적(㎡) 비고" (헤더), 뒤이어 "토지 대구시 달성군 가창면 삼산리 795 학교용지 7,329" (값).

- **난이도**: 사람/모델 필요. PDF·HWP를 텍스트로 뽑으면 표의 셀 경계(어느 값이 어느 필지·구분에 속하는지)가 사라지고 "헤더 줄들 → 값 줄들"만 순서대로 남는다. 필지 수가 많을수록(idx 10은 22필지) 행 복원이 더 어렵다.

### 4.2 가격·사용료·임대료 산정방식

- **어디서**: idx 14(사용료), idx 21(임대료=기본+매출연동), idx 23(최소보장액 조정), idx 9·10(대금 회차별 비율).
- **패턴**: 산식이 자연어 수식(`×`, `÷`, `+`)으로 문단에 풀려 있다. 단일 값이 아니라 조건부(1차년도 vs 2차년도 이후 등)로 갈리는 경우가 많다.
- **원문 인용** (`14_1.txt`): "= (입찰에 의해 결정된 첫해의 사용료(부가세 제외)) × (해당 연도의 재산평정가액) ÷ (입찰당시의 재산평정가액)"
- **원문 인용** (`21_4.txt`): "임대료 산정방법 : 기본임대료 + 매출연동임대료 ※ VAT포함"

- **난이도**: 모델 필요. 산식 자체는 문자열로 뽑을 수 있어도, 변수 정의("재산평정가액"이 무엇인지)와 적용 조건(1차년도/2차년도, 증감 상한)까지 함께 읽어야 의미가 완성된다.
- **추천 방식**: 산식 문단 전체를 통째로 캡처한 뒤 모델에게 "변수 정의 + 적용조건"을 구조화하게 하는 방식을 권한다.

- **패턴**: 표지 요약(감정평가액·기준시점)은 단문. 본문은 방법론 설명(보통 표준 문안), 비교 대상 표(구분건물 명세표·인근 거래사례 표), 실비명세표로 구성된다.
- **원문 인용** (`22_11.txt`): "감정평가액 오천칠백칠십구만육천원정 (57,796,000원)"
- **원문 인용** (`22_11.txt`): "보증금 환산금액 산식 : 년간실질임료 / 0.12 (월세전환율 년 12% 적용)"
- **난이도**: 표지 요약값은 규칙기반으로 쉽게 뽑힌다("감정평가액" 라벨 뒤 금액). 반면 비교 대상 표(15·16의 구분건물 10개호 일괄 표, 17의 담보이력 표)는 pdfminer가 열을 세로로 풀어놓아 "이 숫자가 몇 번째 항목의 어느 필드인지"를 순서만으로 복원하기 위험하다 — 3개 조사 에이전트가 공통으로 지적한 문제다.
- **추천 방식**: 표지 요약값(감정평가액·기준시점·산식)만 규칙기반으로 우선 뽑고, 비교표는 이번 단계에서는 추출 대상에서 제외하거나 원본 좌표 기반 재파싱을 별도 과제로 미루는 것을 권한다. 법령 정의 문단(적산법·거래사례비교법 정의)은 모든 감정평가서에 반복되는 표준 문안이라 추출 우선순위가 낮다.

### 4.9 평가기준·배점 (정성평가가 있는 경우)

- **어디서**: idx 21(제안서 배점표), idx 23(사업제안서 평가표 + 신용등급 환산표).
- **패턴**: 표(구분/평가항목/배점) + 다단계 환산 로직("배점 100점 → 80점 환산 → 가격평가 20점과 합산").

- **추천 방식**: "정성평가가 있다/없다"라는 존재 여부만 규칙기반으로 먼저 표시하고(예: idx 22처럼 최고가방식이면 배점표 자체가 없음), 배점 세부 구조화는 모델 + 사람 검증을 권한다.

### 4.10 변경/정정사항 (변경공고에서만 등장하는 특수 유형)

- **어디서**: idx 23(유일). 이번 표본 10건 중 변경공고는 idx 23 하나뿐이다.
- **패턴**: 변경공고문 안의 "□ 정정사항"·"□ 변경일정" 절(구분/당초/변경 3열 표)과, 별도 첨부인 "신구대조표"(페이지+줄번호 단위로 `(기존) … (변경) …` 쌍을 나열).
- **원문 인용** (`23_11.txt`): "온비드 공고 제202608-27890-00호(2026.8.27.)「인천공항 T2 환승호텔/라운지 사업권 운영사업(HL1-2026)」건의 정정사항이 발생함에 따라 제202608-27890-01호로 변경공고 합니다."

- **난이도**: 모델 필요. "(p.NN)"과 "(기존)/(변경)" 마커 자체는 정규식으로 페어링할 수 있지만, 같은 표 행 안에 숫자가 여러 개 뒤섞인 항목(담당 조사 에이전트가 지적한 룸번호 재배치 사례)은 원본 표를 봐야 정확한 매핑을 알 수 있다.
- **추천 방식**: 이 유형은 "변경공고인가"를 먼저 판별한 뒤(공고 제목·본문에 "변경공고"라는 단어 존재로 규칙기반 판별 가능), 있는 경우에만 신구대조표를 모델에게 통째로 넘겨 "무엇이 바뀌었는지" 요약하게 하는 방식을 권한다.

### 4.11 서식류 (빈칸 양식)

- **어디서**: 전 건 공통 (위임장·사용인감계·신청서·제안서접수조서 등).

## 5. 공고 유형별 특이사항

- **idx 9/10 (도시개발사업 용지분양)**: 공고문(_1)만 서로 다르고, 지구단위계획결정도서(_2)·신청서류(_3)·도면자료(_4)는 sha256이 완전히 같은 동일 파일이다. 즉 한 사업의 부속 서류를 여러 공고가 재사용한다 — 첨부 텍스트를 캐싱하면 같은 사업의 다른 공고를 재분석할 때 중복 다운로드·중복 파싱을 줄일 수 있다.
- **idx 14 (지하도상가 광고 사용권)**: 유일하게 `noticeBodyText`(본문)에 실질 정보(예정가격 산정기준·이메일 제출 요건)가 이미 있다. 첨부(14_1)에도 같은 내용이 반복돼, 추출기를 만들 때 본문-첨부 중복 제거 로직이 필요하다.
- **idx 11 (폐교재산 매각)**: `docsTableRows`·`docsSecText`(서버가 본문에서 뽑은 필드)가 완전히 비어 있고 본문 자체도 "첨부파일 공고문 참조"뿐이다. 첨부 없이는 매각 대상·가격·자격이 전부 유실되는 가장 극단적인 사례다.
- **idx 17 (신탁사 공매)**: 15·16(구분상가, "감정평가서 참조"로 위임)과 달리 공매공고 본문 안에 전입세대·임대차·압류 현황을 직접 표로 수록하고, 같은 정보가 매매계약서(17_2)에도 중복 기재된다. 등기부등본·건축물대장(17_3·17_4)은 텍스트 추출이 0자로 실패했다 — 스캔본으로 추정되며 이번 표본에서는 제외했다.

- **idx 21 (`21_7.txt`·`21_8.txt`)**: PDF 2단 컬럼이 좌우 교차로 추출돼 조문 순서 자체가 뒤섞인다(제6조 본문 중간에 제5조 잔여 문장 삽입). 조 경계 정규식만으로는 내용이 잘려 나온다.
