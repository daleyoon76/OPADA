# MVP 개선 루프 기록

작성일: 2026-07-04

## Loop Contract

- Objective: 온비드 URL 입력 후 검증, 준비 전환, AI형 준비 가이드가 사용자에게 명확히 보이도록 MVP 사용자 흐름을 개선한다.
- Scope: `90_MVP개발/app`, `90_MVP개발/tests`, MVP 문서와 검증 스크린샷.
- Forbidden actions: 인증키 파일 저장, 외부 서비스 상태 변경, 브랜치 전환, 사용자 승인 없는 commit/push.
- Stop criteria: P0/P1 사용자 흐름 문제가 로컬 검증에서 더 이상 재현되지 않거나, 외부 API/제품정책 결정이 필요해 막힐 때 중단한다.
- Verification gates: Python/JS 문법 검사, `/api/analyze` smoke, Edge CDP 화면 검증, 스크린샷 육안 확인.
- Commit policy: long-auto-loop 기본은 검증 후 commit이지만, 이 저장소 세션 지시가 “요청 전 커밋 금지”이므로 커밋하지 않는다.
- Next-task rule: 각 라운드 후 남은 P0/P1 또는 작고 명확한 P2를 바로 이어서 처리한다.

## Follow-up Round: Vertex AI 준비 코치 연결

- `Gemini API key` 직접 호출은 현재 키가 유효하지 않아 Vertex AI 경로를 우선 사용한다.

  - 위험 표현 스캔 hit 없음: `입찰 참여를 보장`, `수익률 보장`, `낙찰 가능성`, `추천`, `입찰 금액을 결정`, `권리관계`, `성공적인 입찰`

Remaining risk / next probe:

## Follow-up Round: AI 코치를 AI 누락 점검으로 재설계

Status:
- 완료. 기존 Vertex AI 코치가 이미 화면에 있는 입찰기간/제출서류를 다시 말하거나, 담당기관에 같은 내용을 다시 묻는 문제가 있었다.
- 코치 영역을 `AI 누락 점검`으로 바꾸고, 일반 조언 대신 공고별로 실제 준비 전 비어 있는 항목만 보여주도록 재구성했다.
- 화면 구조:
  - `확정된 값`: 공고 유형, 입찰기간, 가격 기준, 담당기관.
  - `AI가 남긴 빈칸`: 원문만으로 충분하지 않은 확인 포인트.
  - `담당기관에 확인할 빈칸`: 서비스가 이미 아는 값이 아니라 기관 확인이 필요한 질문 초안.
- 임대/대부 공고는 `내 업종으로 실제 사용 가능한지`, `현장 상태와 인수 범위`, `대부료 외 반복 비용`을 우선 빈칸으로 보여준다.
- 매각/공매 공고는 `공동/대리입찰 서류 필요 여부`, `직접제출 서류 마감`, `보증금·잔금·추가비용 납부 순서`를 우선 빈칸으로 보여준다.
- 브라우저 캐시로 이전 `app.js`가 남는 문제가 있어 `index.html`의 CSS/JS 경로에 `?v=20260704-gap-check` 버전 쿼리를 추가했다.
