# MVP 지속 개선 루프 기록

작성일: 2026-07-05

## Loop Contract

- Objective: KAMCO 신청서 스크린샷용 MVP의 코드 안정성, UI/UX 간결성, 사용자 가치, AI 맞춤형 가치 전달력을 지속 개선한다.
- Scope: `90_MVP개발/app`, `90_MVP개발/tests`, `90_MVP개발/screenshots/validation`, `team-reports`, MVP 검증/개선 기록 문서.
- Forbidden actions: 인증키 파일 저장, 외부 서비스 상태 변경, 브랜치 전환, 사용자 승인 없는 push/deploy, 공공데이터/Vertex 키 노출.
- Stop criteria: 사용자가 중단을 요청하거나, 남은 항목이 외부 승인/제품정책 결정/배포 인프라/민감정보 작업으로 막힐 때까지 반복한다.
- Verification gates: Python 문법 검사, JS 문법 검사, `/api/analyze` smoke, Chrome headless CDP UI 검증, 주요 스크린샷 육안 확인.
- Commit policy: long-auto-loop 기본은 검증 후 로컬 커밋이지만, 이 저장소에는 기존 대량 미추적 산출물과 사용자 작업이 많으므로 이번 루프에서는 사용자가 명시하기 전까지 커밋하지 않고 파일 단위 변경과 검증 기록을 남긴다.
- Team policy: 가장 가까운 병목에 맞춰 1~4팀 역할을 순차 소집한다. UI/UX 병목은 3팀, 사용자 가치/활성화 병목은 4팀, 구조/테스트 병목은 2팀, 전체 맥락 정리는 1팀 성격으로 처리한다.
- Next-task rule: 각 라운드 후 남은 P0/P1 또는 작고 명확한 P2를 다음 작업으로 즉시 선택한다.
- Reseed rule: 다음 probe가 비면 기존 loop report, team-reports, 최근 변경 파일을 다시 훑어 안전한 다음 개선 항목을 찾는다.
