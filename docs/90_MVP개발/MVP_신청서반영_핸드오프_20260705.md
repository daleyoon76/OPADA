# MVP 신청서 반영 핸드오프

작성시각: 2026-07-05 14:56 KST  
대상: KAMCO Startup TechBlaze 신청서 및 기획서 v06 반영  
서비스명: OnBid Public Asset Doc Agent  
한글명: 온비드 공공자산 입찰 준비 보드 Agent

## 1. MVP 한 줄 설명

온비드 공고/물건 URL을 붙여넣으면 공개 공고 페이지를 분석하고, AI가 초보자가 놓치기 쉬운 준비 빈칸을 체크리스트 우선순위와 담당기관 문의 문장으로 바꾸어 주는 공공자산 입찰 준비 보드 MVP다.

## 2. 타깃 사용자와 해결 문제

| 타깃 사용자 | 기존 문제 | MVP가 해결하는 방식 |
| --- | --- | --- |
| 온비드 입찰 초보 개인 | 공고문, 물건상세, 입찰조건을 읽어도 무엇부터 확인해야 할지 모름 | URL 분석 후 `다음 액션` 체크리스트와 원문 링크 제공 |
| 개인사업자·소상공인 | 임대/대부 공고에서 사용 가능 업종, 현장 상태, 반복 비용을 놓치기 쉬움 | AI가 `내 업종으로 실제 사용 가능한지`, `현장 상태와 인수 범위`, `대부료 외 반복 비용`을 우선 표시 |
| 공공자산 활용 창업자 | 여러 공고를 살펴본 뒤 준비 상태를 이어서 관리하기 어려움 | 최근 살펴본 공고와 관심 공고에 저장해 다음 확인 항목을 유지 |
| 창업지원기관·컨설턴트 | 초기기업별로 공고 조건과 확인 질문을 수작업 정리해야 함 | 담당기관에 물어볼 문장과 원문 근거를 준비 보드 안에서 제공 |

핵심 문제는 `공고 정보 부족`이 아니라 `공고를 읽은 뒤 사용자가 실행할 준비 행동으로 바꾸기 어렵다`는 점이다. 따라서 본 MVP는 공고 요약이나 일회성 보고서보다, 사용자가 실제로 체크하고 문의하고 저장할 수 있는 준비 보드에 초점을 둔다.

## 3. 사용자가 처음부터 끝까지 따라가는 플로우

1. 사용자는 온비드에서 관심 있는 공고 또는 물건 상세 URL을 복사한다.
2. MVP의 `공고 가져오기` 화면에 URL을 붙여넣는다.
3. 사용자 유형을 선택한다. 예: `개인`, `개인사업자`, `법인`, `예비창업자`.
4. 검토 목적을 선택한다. 예: `임대/대부 공고 검토`, `매각/공매 공고 검토`, `창업 공간 탐색`.
5. `공고 분석`을 누르면 서버가 온비드 short URL 또는 상세 URL을 최종 페이지로 따라가 공개 HTML을 읽는다.
6. 입력 화면에서 공고/물건 연결, 유형, 입찰기간, 담당기관, 원문 링크, AI 분석 완료 상태를 먼저 확인한다.
7. 결과가 유효하면 `준비 보드 만들기`를 눌러 `내 준비 보드`로 이동한다.
8. 준비 보드에서 AI가 우선 연결한 준비 빈칸과 체크리스트를 확인한다.
9. 첫 AI 우선 항목의 `담당기관에 물어볼 문장`을 펼쳐 바로 문의 문장과 근거를 확인한다.
10. 사용자는 체크박스로 진행률을 관리하고, 원문 링크를 열어 공식 공고를 확인한다.
11. 분석한 공고는 `최근 살펴본 공고`에 자동 저장된다.
12. 별표를 누르면 같은 항목이 `관심 공고`에도 표시되어 여러 공고의 준비 상태를 이어서 관리할 수 있다.

## 6. 신청서에 강조해야 할 핵심 기능 3~5개

1. **온비드 URL 분석**
   - 사용자가 공고번호나 물건번호를 따로 입력하지 않아도 온비드 short URL, 공고 상세 URL, 물건 상세 URL을 입력하면 최종 페이지를 따라가 공고·물건 정보를 추출한다.

2. **AI 우선 체크리스트**
   - AI가 원문에 이미 보이는 값을 반복 요약하지 않고, 실제 준비 전에 놓치기 쉬운 빈칸을 체크리스트 상단으로 올린다.
   - 임대/대부와 매각/공매 공고에서 서로 다른 우선 확인 항목을 보여준다.

3. **담당기관 문의 문장**
   - 사용자가 무엇을 물어봐야 할지 모르는 문제를 줄이기 위해, 확인 항목을 담당기관에 바로 문의할 수 있는 문장으로 바꾼다.

4. **원문 우선 근거 연결**
   - 각 준비 항목에 온비드 원문 링크와 근거 위치를 연결한다.
   - AI 결과가 최종 판단이 아니라 원문 및 담당기관 확인을 돕는 보조 도구임을 명확히 한다.

5. **최근/관심 공고 관리**
   - 분석한 공고를 최근 살펴본 공고로 남기고, 별표로 관심 공고에 저장해 여러 물건의 준비 상태를 이어서 볼 수 있다.

## 10. 현재 남은 한계와 다음 개선 계획

### 현재 남은 한계

| 한계 | 설명 |
| --- | --- |
| 브라우저 localStorage 저장 | 관심 공고와 체크 상태가 사용자 계정 기반이 아니라 현재 브라우저에만 저장됨 |
| 공공데이터 API 보조 수준 | 현재 MVP는 공개 원문 분석이 기본이고, API는 응답 가능 시 보강하는 구조 |
| HTML 구조 변경 리스크 | 온비드 공개 페이지 구조가 바뀌면 파서 보강 필요 |
| AI-체크리스트 매칭 한계 | 현재는 AI 누락 점검 결과와 기존 task를 매칭하는 방식. task id까지 생성하는 구조는 후속 고도화 필요 |
| 알림 미구현 | 마감 알림 후보는 화면 가치로 제시했지만 실제 알림 발송은 미구현 |
| 사용자 테스트 부족 | 초보 사용자 3명 이상 검증 전 단계 |
| 공식 DOCX 최종 이관 필요 | 신청서용 v06 원고와 DOCX 검토본은 있으나, 공식 양식 최종본에는 수동 이관과 렌더 검수 필요 |

### 다음 개선 계획

1. **AI task id 직접 생성**
   - AI가 `unresolvedChecks`뿐 아니라 연결할 체크리스트 task id 후보까지 반환하도록 서버 응답 구조를 고도화한다.

2. **계정 기반 관심 공고 관리**
   - localStorage 기반 저장을 사용자 계정 기반 저장으로 전환하고, 여러 기기에서 이어서 볼 수 있게 한다.

3. **마감 알림과 준비 일정**
   - 입찰기간, 직접제출 마감, 전자보증서 신청 마감 등을 알림 후보로만 보여주는 것을 넘어 실제 알림 기능으로 확장한다.

4. **공고 유형 확대**
   - 현재 검증된 임대/대부, 매각/공매 흐름을 차량, 동산, 압류재산 세부 유형, 지자체 공유재산으로 확장한다.

5. **사용자 검증**
   - 온비드 초보 개인, 개인사업자, 창업지원기관 실무자 각 1명 이상에게 화면을 보여주고 첫 행동 이해도, 문의 문장 유용성, 재사용 의향을 확인한다.

6. **배포 인증 구조 정리**
   - 실제 서비스 배포 시 로컬 gcloud나 개인 개발환경 인증이 아니라 서버 서비스 계정과 환경변수 기반 인증으로 전환한다.

7. **신청서 최종 반영**
   - v06 8~10쪽 복붙 우선본과 스크린샷 3장 기본형을 공식 DOCX/HWP 양식에 이관한다.
   - Word/PDF 렌더 기준으로 본문 10쪽 이내, 표 잘림, 이미지 가독성, 캡션 길이, 금지표현 스캔을 확인한다.
