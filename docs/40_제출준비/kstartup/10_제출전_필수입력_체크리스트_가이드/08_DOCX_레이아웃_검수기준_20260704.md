# DOCX 레이아웃 검수 기준

작성시각: 2026-07-04 13:52 KST  
최종갱신: 2026-07-05 KST / v06 MVP 스크린샷 삽입 기준 반영

## 핵심 리스크

원본 HWP에서는 한 페이지에 딱 맞는 표지가 DOCX 변환본에서는 1.5페이지로 밀릴 수 있습니다. 최종 제출본은 HWP 원본 PDF의 시각 구조를 기준으로 맞추고, DOCX/PDF 렌더 결과로 다시 검수합니다.

## 표지 검수 기준

- `[붙임 1]`, 제목 박스, 접수번호, 큰 표 전체가 PDF 1페이지 안에 들어가야 합니다.
- 제목 박스의 `2026 KAMCO Startup TechBlaze`와 `신청서 및 기획서` 두 줄이 잘리지 않아야 합니다.
- `공공데이터 활용여부`, `공공데이터 출처`, `참가 구분`, `신청인`, `팀원`, `아이템명`, `아이템 요약설명`, 제출일/서명, 첨부 행이 모두 보여야 합니다.
- 행 높이를 줄일 때 글자가 위아래로 잘리면 실패입니다.
- 표 전체가 1페이지 안에 들어가더라도 서명/수신기관 줄이 작아서 보이지 않으면 실패입니다.

## 본문 검수 기준

- 공식 작성 범위 `1. 아이템의 소개`부터 `7. 기타사항`까지 10페이지 이내로 유지합니다.
- MVP 반영 후에도 본문 PDF는 8~10쪽을 목표로 합니다.
- 표가 페이지 하단에서 잘리면 표 앞뒤 문단을 줄이거나 행 높이/글자 크기를 조정합니다.
- 공식 안내의 보수적 해석에 맞춰 본문 작성 글씨는 검정색으로 둡니다.
- 내부 메모, placeholder, 이전 공고명, 위험 표현은 `pdftotext`로 다시 스캔합니다.

## v06 스크린샷 검수 기준

- 기본 제출 후보는 스크린샷 3장입니다.
  - `01_url_analysis_ready_crop.png`
  - `02_ai_priority_board_lease_crop.png`
  - `04_watchlist_recent_favorite_crop.png`
- 본문 10쪽 안에 충분히 들어가면 `03_ai_priority_board_sale_crop.png`를 추가합니다.
- 이미지는 원본 전체 캡처보다 `submission-crops/`의 크롭본을 우선 사용합니다.
- 한 페이지에 스크린샷 2장을 무리하게 넣지 않습니다.
- 이미지 폭은 본문 폭의 85~95%를 우선하고, 글자가 작아지면 폭을 늘리거나 캡션을 줄입니다.
- 캡션은 한 줄 또는 두 줄 이내로 유지합니다.
- 실패 조건:
  - 화면 안의 `AI 우선 액션`, `담당기관에 물어볼 문장`, `관심 공고` 핵심 문구가 읽히지 않음.
  - 이미지가 페이지 하단에서 잘림.
  - 브라우저 빈 여백이 본문보다 더 크게 보임.
  - 구버전 문구 `Local MVP`, `로컬 분석 API`, `PDF 저장`, `Vertex AI`, `Gemini AI`, `AI 코치`가 보임.

## 최종 검증 절차

1. DOCX를 Word로 PDF 내보내기합니다.
2. `pdfinfo`로 A4, 비암호화, 페이지 수를 확인합니다.
3. 표지는 `pdftoppm`으로 PNG 렌더 후 실제 눈으로 확인합니다.
4. 본문은 전체 페이지 contact sheet를 만들어 빈 페이지, 표 잘림, 제목 잘림을 확인합니다.
5. 원본 HWP PDF의 표지 페이지와 비교해 큰 구조가 유지되는지 확인합니다.
6. 스크린샷이 들어간 페이지는 개별 PNG로 확대 확인해 텍스트 가독성과 캡션 위치를 확인합니다.
