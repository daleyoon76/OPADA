## 1. 아이템의 소개

### 개발 배경

온비드는 국유재산, 압류재산, 공공기관 보유 자산의 매각·임대 공고를 통합 제공하는 공공 플랫폼이다. 한국자산관리공사는 주요사업 관련 공공데이터를 지속적으로 개방하고 있으며, 온비드 공고목록, 공고상세, 물건정보, 입찰정보, 입찰결과, 용어사전은 본 서비스의 핵심 입력 데이터가 된다.

공고와 물건정보는 공개되어 있지만 실제 입찰 준비자는 공고문, 첨부문서, 물건정보, 입찰방식, 보증금, 제출서류, 낙찰 후 납부·계약 의무를 한 번에 이해해야 한다. 개인, 소상공인, 공공자산 활용 창업자는 공고를 찾은 뒤에도 제출서류, 기한, 비용, 현장확인 책임을 놓치기 쉽다.

특히 현장설명 생략, 영업수익 미보장, 인허가 책임, 낙찰 후 7일 이내 신청과 선납 의무처럼 공고문 안의 짧은 문구가 실제 준비 부담으로 이어진다. 경험이 적은 사용자는 공고를 읽고도 지금 해야 할 일, 담당기관에 물어볼 질문, 입찰 전에 확인해야 할 비용 후보를 구조화하기 어렵다.

### 아이템 내용

온비드 공공자산 공고 해석 리포트 Agent는 온비드 공고와 한국자산관리공사 공공데이터를 기반으로 공공자산 공고를 사용자 준비 문서로 바꾸는 AI 서비스다. 사용자가 공고 URL, 공고번호, 물건번호, 관심 지역·재산유형을 입력하면 공고 요약, 입찰 일정, 제출서류, 비용 후보, 낙찰 후 의무, 사용자 확인 리스크, 용어 설명, 원문 근거가 포함된 PDF 리포트를 생성한다.

본 서비스는 온비드 전자입찰 절차를 대신 수행하거나 결과를 약속하는 도구가 아니다. 공식 공고와 공공데이터를 사용자가 스스로 확인할 수 있도록 구조화하는 준비 보조 Agent다. 사용자는 생성된 리포트를 바탕으로 본인의 자격, 서류 발급 가능일, 현장확인 필요사항, 납부 가능 자금, 담당기관 문의사항을 점검한다.

1차 MVP는 국유재산 임대·매각 공고를 중심으로 시작한다. 공고문과 API 필드를 표준 스키마로 정리하고, 제출서류와 일정, 비용 후보, 리스크 질문을 한 페이지 리포트와 상세 PDF로 출력한다. 이후 차량, 동산, 압류재산, 지역별 공고 모니터링, 유사 공고 비교로 확장한다.

### 사용 시나리오

첫째, 사용자는 온비드에서 관심 공고를 찾거나 서비스 검색 화면에서 지역·재산유형·입찰기간을 입력한다. 둘째, 서비스는 온비드 공고목록과 물건정보를 조회해 후보 공고를 표준 스키마로 정리한다. 셋째, 사용자가 공고를 선택하면 공고상세 입찰정보, 물건정보, 첨부 공고문, 온비드 용어사전을 함께 분석한다.

넷째, AI Agent가 공고 요약, 일정, 제출서류, 비용 후보, 리스크를 생성하되 각 항목에 원문 근거를 붙인다. 다섯째, 사용자는 PDF 리포트와 Q&A를 보며 본인 상황에 맞는 확인 질문을 정리하고, 최종 입찰 여부는 원문과 담당기관 확인 후 결정한다.

## 2. 사업성 및 성장가능성

### 목표 고객

초기 고객은 온비드 입찰 초보 개인, 소상공인·자영업자, 공공자산 활용 창업자, 창업지원기관·컨설턴트다. 이들은 공공기관 임대공간이나 매각물건을 사업기회로 검토하지만 공고 해석, 서류 준비, 비용 확인, 낙찰 후 의무 파악에 반복적인 시간을 쓴다.

온비드 입찰 초보자는 공고문과 전자입찰 절차를 이해하기 어렵고, 소상공인은 공공기관 임대공간을 사업기회로 검토하면서도 제출서류와 조건을 놓치기 쉽다. 창업지원기관과 컨설턴트는 초기기업에게 공공자산 활용 기회를 안내할 수 있지만, 공고별 해석과 체크리스트 작성 시간이 크다.

| 고객군 | 문제 | 제공 가치 |
| --- | --- | --- |
| 온비드 입찰 초보 개인 | 공고문과 전자입찰 절차 이해가 어려움 | 일정·서류·비용·리스크를 한 장 리포트로 확인 |
| 소상공인·자영업자 | 공공기관 임대공간을 검토하지만 조건이 복잡함 | 사업자 기준 준비물과 낙찰 후 의무 체크 |
| 공공자산 활용 창업자 | 지역·용도·면적·가격을 비교하기 어려움 | 후보 탐색과 비교 리포트 제공 |
| 창업지원기관·컨설턴트 | 초기기업 공고 해석 시간이 큼 | 고객별 확인 질문과 요약 리포트 생성 |

### 시장 근거와 진입 전략

KAMCO 공공데이터에는 온비드 월별 입찰참가자 현황이 포함되어 있으며, 2013년 1월부터 2025년 12월까지 156개월의 월별 유효 입찰참가자 수를 제공한다. 이는 온비드 공고 탐색과 입찰 준비가 일회성이 아니라 반복적으로 발생하는 시장임을 보여주는 근거다.

시장진입은 국유재산 임대·매각 공고 3건 샘플 리포트 생성, 소상공인·예비창업자·컨설턴트 각 1명 이상 사용성 검증, 웹 MVP 공개, 창업지원기관/컨설턴트 대상 B2B 검증 순서로 진행한다. 초기 획득 채널은 온비드 초보자 대상 검색 콘텐츠, 소상공인·창업자 커뮤니티, 공공자산 활용 창업 사례 콘텐츠, 창업지원기관·컨설턴트 대상 샘플 리포트 배포로 잡는다.

무료 샘플은 공고 1건 요약과 리스크 3개까지만 제공하고, 전체 체크리스트·비용 후보·확인 질문·PDF 저장 기능에서 유료 전환을 검증한다. 1차 검증은 공고 이해도, 누락 방지 효과, 재사용 의향, 기관용 반복 사용 가능성을 중심으로 진행한다.

| 단계 | 기간 | 목표 | 산출물 |
| --- | --- | --- | --- |
| 1단계 | 1개월 | 국유재산 임대·매각 공고 3건 분석 | 샘플 리포트, 인터뷰 질문지 |
| 2단계 | 2개월 | 소상공인·예비창업자 사용성 검증 | 이해도, 누락 방지, 재사용 의향 |

| 4단계 | 4~6개월 | 기관/컨설턴트 B2B 검증 | 월간 리포트 패키지 |

### 수익모델과 성장전략

초기 가격 가설은 건별 리포트 3,000~9,900원, 월 구독 19,000~49,000원, 기관용 패키지 월 99,000원 이상이다. 건별 리포트는 개인·소상공인 대상, 월 구독은 관심 지역과 재산유형을 반복 탐색하는 사용자 대상, 기관용 패키지는 컨설턴트와 창업지원기관 대상이다.

성장전략은 공고 1건 리포트에서 시작해 관심 조건 월간 모니터링, 유사 물건 비교, 입찰결과 참고 리포트, 기관용 고객별 공고 큐레이션으로 확장하는 방식이다. 장기적으로는 공공기관 공고, 지자체 유휴공간, 공공조달 준비 문서 등 GovTech 문서 Agent로 확장할 수 있다.

| 월 구독 | 관심 지역/재산유형 공고 모니터링 | 반복 탐색 사용자 |

| API/화이트라벨 | 공고 해석 모듈 외부 제공 | 후속 B2B 확장 |

## 3. AI 및 공공데이터 활용성

### 활용 공공데이터

본 서비스는 한국자산관리공사 차세대 온비드 공고목록 조회서비스, 공고상세 조회서비스, 공고상세 입찰정보 조회서비스, 공고상세 물건정보 조회서비스, 입찰결과 조회서비스, 온비드 용어사전, 온비드 월별 입찰참가자 현황을 활용한다.

공고목록 조회서비스는 공고 후보 수집과 마감 임박 표시, 공고상세 조회서비스는 공고문·첨부파일·재산유형·처분방식 확인, 공고상세 입찰정보 조회서비스는 공동입찰, 보증금, 잔대금 납부, 참가신청 여부 확인, 물건정보 조회서비스는 물건명, 소재지, 용도, 유찰횟수, 입찰기간 확인에 활용한다.

온비드 용어사전은 공매·입찰·부동산·법률 관련 용어를 일반 사용자가 이해 가능한 설명으로 바꾸는 데 사용한다. 월별 입찰참가자 현황은 실시간 기능 입력이 아니라 시장성 보조 근거로만 사용한다.

| 공공데이터 | 활용 방법 |
| --- | --- |
| 공고목록 조회서비스 | 공고 후보 수집, 마감 임박 표시 |
| 공고상세 조회서비스 | 공고문, 첨부파일, 재산유형, 처분방식 확인 |
| 공고상세 입찰정보 조회서비스 | 보증금, 잔대금 납부, 참가신청 여부 확인 |
| 공고상세 물건정보 조회서비스 | 물건명, 소재지, 용도, 유찰횟수, 입찰기간 확인 |
| 온비드 용어사전 | 입찰·공매 용어의 쉬운 설명 제공 |

### AI Agent 처리 구조

처리 구조는 Data Collector, Notice Parser, Checklist Agent, Risk Guard Agent, Glossary Agent, Report Agent로 나눈다. Data Collector는 공고번호, 물건번호, 기관, 일정, 재산유형, 입찰방식, 가격 후보를 수집한다. Notice Parser는 공고문과 첨부문서에서 일정, 서류, 보증금, 낙찰 후 의무, 유의사항을 추출한다.

Checklist Agent는 사용자 유형별 제출서류와 준비 순서를 생성한다. Risk Guard Agent는 현장확인, 인허가, 비용, 낙찰 후 기한, 사용자 책임 문구를 표시한다. Glossary Agent는 온비드 용어사전의 Terminology, Glossary 컬럼을 활용해 쉬운 설명을 연결한다. Report Agent는 요약, 일정표, 서류 체크리스트, 비용 후보, 리스크, 다음 액션을 PDF로 생성한다.

| Agent | 역할 | 산출물 |
| --- | --- | --- |
| Data Collector | 공고·물건·입찰정보 수집 | 표준 입력 JSON |
| Notice Parser | 일정, 서류, 보증금, 의무 추출 | 공고 구조화표 |
| Checklist Agent | 사용자 유형별 준비순서 생성 | 제출서류·일정 체크리스트 |
| Risk Guard Agent | 현장확인, 인허가, 비용 리스크 분류 | 리스크 카드 |
| Report Agent | 요약과 근거를 PDF로 구성 | 공고 분석 리포트 |

### 데이터 신뢰성 관리

API 응답 조회시각을 리포트에 표시하고, 공고 원문과 공공데이터 값이 다르면 원문 우선 확인 필요로 표시한다. 개인정보와 사용자의 입찰 희망가격은 기본 저장하지 않고, 리포트 생성 세션 내 처리 또는 사용자 로컬 저장을 우선한다.

입찰가 제안, 수익성 판단, 법률·권리관계 판단은 서비스 범위에서 제외한다. 본 서비스는 원문 근거를 구조화하고 담당기관에 확인할 질문을 생성하는 보조 도구로 제한한다.

## 4. 아이템의 실현 가능성

### 기존 보유 역량

대표자는 기존 문서 Agent PoC에서 공고문 분석, 제출서류 체크리스트, HWPX/PDF 산출, 룰 기반 검증표, 샘플 리포트 작성 경험을 축적했다. 이번 아이템에서는 이 경험을 온비드 공고 해석 리포트로 전환한다.

기존 문서 기반 AI Agent 워크플로우는 공고문 수집·요약·체크리스트·리포트 생성 흐름에 적용할 수 있다. 공고/요건/서류 체크리스트 작성 경험은 온비드 공고의 제출서류·기한·위험 문구 체크에, HWPX/PDF 산출 PoC는 사용자 리포트 출력에 활용할 수 있다.

### 신규 개발 범위와 추진계획

1차 MVP는 4주 단위로 진행한다. 1주차에는 온비드 공고·물건·입찰정보 데이터 필드를 정리하고, 2주차에는 국유재산 임대·매각 공고 파서와 체크리스트를 구현한다. 3주차에는 리스크 카드, 용어 설명, Q&A를 구현하고, 4주차에는 PDF 리포트 MVP와 사용자 테스트를 진행한다. 5~8주차에는 공고 유형 확장과 관심 조건 모니터링을 검증한다.

주요 온비드 API는 공공데이터포털에서 무료 JSON/XML 제공 데이터로 확인된다. 운영 시 공공데이터포털 상세 기준을 기준으로 갱신 주기와 이용 조건을 확인한다. 인증키 발급이나 트래픽 이슈가 있으면 공공데이터포털 명세, 샘플 응답, 온비드 공개 공고 원문, CSV 캐시를 이용해 오프라인 MVP를 먼저 만들고, 운영키 준비 후 실제 API 응답을 연결한다.

| 기간 | 액션 | 산출물 | 검증 기준 |
| --- | --- | --- | --- |
| 1주차 | 공고/물건/입찰정보 필드 정리 | 데이터 매핑표 v1 | 공고 3건 필드 누락 확인 |
| 2주차 | 공고 파서와 체크리스트 구현 | 공고 구조화표 | 수작업 체크와 대조 |
| 3주차 | 리스크 카드, 용어 설명, Q&A 구현 | 리스크 리포트 | 원문 근거 추적 확인 |
| 4주차 | PDF 리포트 MVP와 사용자 테스트 | 샘플 PDF 3건 | 이해도·재사용 의향 확인 |

### 1인기업 수행 리스크 관리

개발 범위 과대 리스크는 전자입찰 절차 수행, 입찰가 제안, 수익성 판단, 법률·권리관계 판단을 제외하고 공고 해석 리포트로 범위를 제한해 통제한다. 공공데이터 API 지연 리스크는 샘플 응답, 공개 공고 원문, CSV 캐시로 오프라인 MVP를 먼저 만든 뒤 운영키 연결로 전환한다.

도메인 전문성 리스크는 필요 시 공매·부동산·행정서류 전문가 자문을 월 2회 이내, 총 50만원 이하 범위에서 확보하는 방식으로 관리한다. 문서 품질은 샘플 공고별 수작업 정답지와 비교하고, 금지표현·근거 누락·일정 누락 체크리스트로 검증한다.

## 5. 아이템의 창의성 및 시장 파급력

### 차별성

본 아이템의 창의성은 단순 요약이 아니라 공공데이터 API, 공고 원문, 첨부문서, 용어사전, 사용자 유형을 결합해 공공자산 공고를 실행 가능한 준비 문서로 바꾸는 흐름에 있다.

온비드 직접 검색은 공고 탐색은 가능하지만 서류·일정·위험 문구를 사용자가 직접 해석해야 한다. 범용 LLM 요약은 최신 공고와 공공데이터 구조를 안정적으로 반영하기 어렵고 근거 표시가 약할 수 있다. 본 서비스는 공공데이터와 원문 링크를 붙인 근거 기반 리포트로 차별화한다.

부동산 투자정보 서비스는 공공자산 입찰 절차와 제출서류 중심이 아니며, 수작업 컨설팅은 비용이 크고 반복 공고 탐색에 시간이 많이 든다. 본 서비스는 건별·월간 리포트로 접근성을 높이고 반복 사용을 가능하게 한다.

| 대체 방식 | 한계 | 본 아이템 차별점 |
| --- | --- | --- |
| 온비드 직접 검색 | 서류·일정·위험 문구를 사용자가 직접 해석 | 공고를 실행 체크리스트로 변환 |
| 범용 LLM 요약 | 최신 공고와 근거 표시가 약할 수 있음 | 공공데이터와 원문 링크 기반 리포트 |
| 부동산 투자정보 서비스 | 공공자산 입찰 절차 중심이 아님 | 온비드 준비와 낙찰 후 의무 특화 |
| 수작업 컨설팅 | 비용이 크고 반복 공고 탐색에 부적합 | 건별·월간 자동 리포트 제공 |

### 사회적 가치와 파급효과

사회적 효과는 정보 접근성 개선, 서류 누락·기한 착오 감소, KAMCO 공공데이터 활용 확대, 공공자산 활용 창업 촉진, GovTech SaaS 확장이다. 공매·입찰 경험이 적은 사용자도 공고 핵심과 준비사항을 이해할 수 있고, 제출서류와 일정 체크리스트를 통해 준비 오류를 줄일 수 있다.

공공자산 공고는 학교, 공공시설, 유휴공간, 국유재산 등 창업 아이디어와 연결될 수 있는 자원이다. 본 서비스가 공고 이해 장벽을 낮추면 개인과 소규모 사업자도 공공자산 활용 기회를 더 쉽게 탐색할 수 있다.

| 효과 | 설명 |
| --- | --- |
| 정보 접근성 개선 | 공매·입찰 경험이 적은 사용자도 핵심 준비사항 이해 |
| 서류 누락·기한 착오 감소 | 제출서류와 일정 체크리스트 제공 |
| 공공데이터 활용 확대 | KAMCO 온비드 API와 용어사전을 실제 서비스 흐름에 연결 |
| 공공자산 활용 창업 촉진 | 공공시설 임대, 국유재산 활용, 소규모 사업 기회 탐색 지원 |

선정 후 필요 범위에 따라 공매·부동산·행정서류 전문가 자문을 확보하고, 리포트 시각화와 사용자 테스트는 단기 외부 보조를 활용한다. 외부 자문은 의사결정 대체가 아니라 리포트 문구의 오해 가능성, 제출서류 누락 가능성, 담당기관 확인 질문의 적절성을 검토하는 역할로 제한한다.

## 7. 기타사항

### 샘플 산출물

제출 패키지에는 과거 공개 온비드 공고를 재현한 샘플 입력과 샘플 분석 리포트를 포함한다. 샘플은 현재 입찰 참여 판단자료가 아니라, 서비스가 공고를 어떻게 구조화하고 사용자 준비 리포트로 바꾸는지 보여주기 위한 작동 예시다.

샘플 입력은 공고명, 공고기관, 재산유형, 입찰방식, 소재지, 면적, 예정가격, 입찰기간, 제출서류, 낙찰 후 의무, 리스크 문구를 표준 JSON으로 정리한다. 샘플 출력은 한 줄 요약, 핵심 조건표, 일정표, 제출서류 체크리스트, 비용 후보, 확인 질문, 서비스 주의문으로 구성한다.
