## 1. 아이템의 소개

### 1-1. 개발 배경

온비드는 국유재산, 공유재산, 압류재산, 공공기관 보유 자산의 매각·임대 공고를 통합 제공하는 공공 플랫폼이다. 한국자산관리공사는 온비드 공고목록, 공고상세, 물건정보, 입찰정보, 입찰결과, 용어사전 등 주요 데이터를 개방하고 있다. 이 데이터는 공공자산 공고를 일반 사용자가 이해하고 준비할 수 있도록 돕는 AI 서비스의 핵심 입력이 된다.

문제는 공고와 데이터가 공개되어 있어도 초보 사용자가 바로 행동으로 옮기기 어렵다는 점이다. 개인, 소상공인, 공공자산 활용 창업자는 공고문을 읽은 뒤에도 입찰기간, 제출서류, 보증금, 현장 확인, 낙찰 후 납부·계약 의무를 다시 해석해야 한다. 특히 임대·대부 공고에서는 `내 업종으로 실제 사용 가능한지`, `현장 상태와 인수 범위`, `대부료 외 반복 비용`을 놓치기 쉽고, 매각·공매 공고에서는 `공동/대리입찰 서류`, `직접제출 마감`, `보증금·잔금·추가 비용` 확인이 늦어질 수 있다.

온비드 초보자가 실제로 원하는 것은 공고 전문을 다시 요약한 문서가 아니라, 이 공고를 검토하려면 무엇을 먼저 확인하고, 어디에서 원문을 보고, 담당기관에 어떤 문장으로 물어봐야 하는지이다. 본 아이템은 이 공백을 해결하기 위해 공공데이터와 AI를 결합해 공고를 실행 가능한 준비 보드로 바꾸는 것을 목표로 한다.

### 1-2. 아이템 내용

`OnBid Public Asset Doc Agent`는 온비드 공개 공고 화면을 기본 원천으로 읽고, 한국자산관리공사 공공데이터 API를 보조 원천으로 연결해 공공자산 공고를 실행 가능한 준비 보드로 바꾸는 AI 서비스다. 사용자가 온비드 공고/물건 URL을 입력하면 공고번호와 물건번호, 재산유형, 처분방식, 입찰기간, 가격/보증금, 제출서류, 담당기관 정보를 자동 추출하고, 사용자의 검토 목적과 비교해 준비 보드를 생성한다.

서비스의 핵심 출력은 `AI 우선 체크리스트`다. AI는 원문에 이미 보이는 값을 반복 요약하는 대신, 초보 사용자가 놓치기 쉬운 빈칸을 분리한다. 예를 들어 임대/대부 공고에서는 `내 업종으로 실제 사용 가능한지`, `현장 상태와 인수 범위`, `대부료 외 반복 비용`을 체크리스트 상단에 올리고, 담당기관에 바로 물어볼 문장으로 바꾼다. 매각/공매 공고에서는 `공동/대리입찰 서류가 나에게 필요한지`, `직접제출 서류의 실제 마감 시각`, `보증금·잔금·추가 비용의 납부 순서`처럼 유형별로 다른 준비 빈칸을 우선 표시한다.

본 서비스는 온비드 전자입찰 절차를 대신 수행하거나 낙찰 가능성, 법률 판단, 투자수익률을 제공하지 않는다. 공식 공고와 공공데이터를 사용자가 스스로 확인할 수 있도록 구조화하는 준비 보조 Agent다. 사용자는 준비 보드에서 본인의 자격, 서류 발급 가능일, 현장확인 필요사항, 납부 가능 자금, 담당기관 문의사항을 체크하며 공고 검토를 이어갈 수 있다.

1차 MVP는 국유재산·공유재산 임대/대부 및 매각 공고를 중심으로 시작한다. 현재 실증 MVP는 온비드 short URL과 공고/물건 상세 URL을 실제로 따라가 공개 페이지를 읽고, 분석 미리보기와 준비 보드를 생성한다. 이후 관심 공고 관리, 유사 공고 비교, 기관/컨설턴트용 다중 공고 관리로 확장한다.

### 1-3. 사용 시나리오

1. 사용자는 온비드에서 관심 공고나 물건 상세 페이지 URL을 복사해 서비스에 붙여넣는다.
2. 서비스는 최종 상세 URL을 따라가 공고번호, 물건번호, 재산유형, 처분방식, 입찰기간, 가격/보증금, 담당기관을 추출한다.
3. 사용자는 `개인사업자`, `개인`, `법인`, `예비창업자` 등 사용자 유형과 `임대/대부`, `매각/공매`, `창업 공간 탐색` 목적을 선택한다.
4. AI는 공고문에 이미 있는 값을 단순 반복하지 않고, 실제 준비 전에 남는 빈칸을 찾는다.
5. 준비 보드는 AI 우선 확인 항목을 체크리스트 상단에 표시하고, 사용자가 담당기관에 물어볼 문장을 접이식 상세에 제공한다.
6. 사용자는 원문 링크를 열어 근거를 확인하고, 체크박스로 준비 진행률을 관리하며, 관심 공고에 저장해 여러 공고의 준비 상태를 이어서 본다.
7. 최종 입찰 여부는 사용자가 원문, 첨부문서, 담당기관 확인 후 결정하며, 서비스는 준비 과정의 누락을 줄이는 보조 도구로 작동한다.

제출 준비 과정에서는 이 흐름을 심사위원이 실제 화면으로 이해할 수 있도록 로컬 실증 MVP를 구성했다. MVP는 온비드 공고/물건 URL과 short URL을 입력받아 서버에서 공개 페이지를 가져오고, 공공데이터 API 응답이 확보되는 경우 온비드 상세 API 값으로 분석 결과를 보강한다. 현재 화면은 `공고 가져오기 -> 분석 미리보기 -> AI 우선 준비 보드 -> 담당기관 문의 문장 -> 관심 공고 관리`까지 이어진다.

### 2-2. 시장진입 전략

시장진입은 `국유재산·공유재산 임대/대부 공고 3건 실증`, `초보 사용자 3명 사용성 검증`, `AI 우선 체크리스트 정확도 개선`, `관심 공고 관리와 알림 확장` 순서로 진행한다. 초기 획득 채널은 온비드 초보자 대상 검색 콘텐츠, 소상공인·창업자 커뮤니티, 공공자산 활용 창업 사례 콘텐츠, 창업지원기관·컨설턴트 대상 샘플 준비 보드 제공으로 잡는다.

무료 사용자는 공고 1건 분석과 AI 우선 확인 3개까지 경험하게 하고, 유료 전환은 다중 공고 저장, 관심 지역 모니터링, 문의 문장/검토 메모 관리, 기관용 공고 비교 기능에서 검증한다.

| 단계 | 기간 | 목표 | 산출물 |

### 2-4. 성장가능성

KAMCO 공공데이터 목록은 공고, 물건, 입찰정보, 입찰결과, 용어사전으로 세분화되어 있다. 이는 공고 1건 분석을 넘어 관심 조건 모니터링, 유사 물건 비교, 입찰결과 참고, 지역별 공고 큐레이션으로 확장 가능한 구조다.

또한 공공기관 공고는 온비드에만 한정되지 않는다. 공공조달, 지자체 유휴공간, 공유재산, 지원사업 공고 등에서도 사용자는 원문을 읽고 준비 항목을 직접 정리해야 한다. 본 서비스는 공공자산 도메인에서 시작해 GovTech 문서 준비 Agent로 확장할 수 있다.

## 3. AI 및 공공데이터 활용성

### 3-1. 활용 공공데이터

본 서비스는 한국자산관리공사 차세대 온비드 공고목록 조회서비스, 공고상세 조회서비스, 공고상세 입찰정보 조회서비스, 공고상세 물건정보 조회서비스, 입찰결과 조회서비스, 온비드 용어사전을 활용한다.

| 공공데이터 | 활용 방법 |
| --- | --- |
| 공고목록 조회서비스 | 관심 조건별 공고 후보 수집, 마감 임박 표시 |
| 공고상세 조회서비스 | 공고명, 공고기관, 재산유형, 처분방식, 공고일 확인 |
| 공고상세 입찰정보 조회서비스 | 공동입찰, 대리입찰, 보증금, 잔대금, 참가신청, 입찰일정 확인 |
| 공고상세 물건정보 조회서비스 | 물건명, 소재지, 용도, 유찰횟수, 입찰기간 확인 |
| 입찰결과 조회서비스 | 향후 유사 공고 참고와 시장성 보조 지표로 활용 |
| 온비드 용어사전 | 공매·입찰 용어를 일반 사용자 언어로 설명 |

### 3-2. AI Agent 처리 구조

AI는 공고 원문을 임의로 판단하지 않고, 구조화된 공고 필드와 사용자 유형을 입력으로 받아 `확인된 사실`, `미해결 빈칸`, `담당기관 문의 문장`, `안전 경계`를 분리한다.

| 단계 | 처리 내용 | 사용자에게 보이는 결과 |
| --- | --- | --- |
| 원문 수집 | 온비드 공고/물건 URL, short URL을 최종 상세 페이지로 변환 | 현재 분석 페이지, 공고보기, 물건상세 링크 |
| 구조화 | 공고번호, 물건번호, 재산유형, 처분방식, 일정, 가격/보증금, 담당기관 추출 | 분석 미리보기와 공고 요약 |
| 목적 비교 | 사용자의 검토 목적과 공고 유형 비교 | 목적 확인 또는 목적 불일치 표시 |
| AI 누락 점검 | 원문에 값이 있어도 실제 준비 전에 확인해야 하는 빈칸 도출 | `AI 우선 액션`, `AI 우선 확인` 배지 |
| 문의 문장화 | 확인 항목을 담당기관에 물어볼 문장으로 변환 | 체크리스트 상세의 문의 문장 |
| 안전 경계 | 입찰 여부, 법률, 수익성 판단은 제외 | 원문 우선 고지와 근거 표시 |

### 3-3. 데이터 신뢰성 관리

온비드 공고는 법적 효력이 있는 원문과 첨부문서가 우선이다. 따라서 서비스는 공공데이터 API 값과 원문 분석값을 함께 사용하되, 사용자 화면에는 항상 `원문 우선` 원칙을 표시한다.

- 공공데이터 API 응답과 원문 표시값이 다르면 원문 및 담당기관 확인을 우선한다.
- 인증키 발급 지연이나 API 보조 데이터 없음 상황에서도 온비드 공개 원문 분석을 유지한다.
- AI는 입찰 참여 권유, 낙찰 가능성, 법률·권리관계 판단, 수익성 판단을 제공하지 않는다.
- AI 출력은 사용자가 담당기관에 확인할 문장으로 제한하고, 원문 근거 링크를 함께 제공한다.

## 5. 아이템의 창의성 및 시장 파급력

### 5-1. 차별성

| 기존 대안 | 한계 | 본 서비스 차별점 |
| --- | --- | --- |
| 온비드 검색 | 공고 탐색은 가능하지만 준비 항목을 사용자가 직접 정리해야 함 | URL 입력 후 준비 체크리스트와 문의 문장 생성 |
| 범용 LLM 요약 | 최신 공고 구조, 원문 근거, 공공데이터 필드와 연결이 약함 | 온비드 데이터 구조와 원문 링크 기반으로 준비 보드 생성 |
| 수작업 컨설팅 | 비용과 시간이 크고 반복 공고 관리가 어려움 | 건별 준비 보드와 관심 공고 관리로 접근성 개선 |
| 일반 문서 자동화 | 공고별 입찰 일정, 보증금, 제출서류 맥락이 부족함 | 공공자산 도메인 특화 빈칸 점검 |

### 5-2. 창의성

본 아이템의 창의성은 AI로 공고를 예쁘게 요약하는 데 있지 않다. 공공데이터 API, 공고 원문, 사용자 유형, 담당기관 문의 흐름을 결합해 `공공자산 공고를 실행 가능한 준비 보드로 바꾸는 것`에 있다.

특히 AI가 모든 것을 판단하는 구조가 아니라, `확인된 사실`과 `사용자가 직접 확인해야 하는 빈칸`을 분리한다는 점이 중요하다. 사용자는 공고를 읽고 막연히 불안해하는 대신, 어느 항목을 먼저 확인하고 어떤 문장으로 담당기관에 문의해야 하는지 알 수 있다.

### 5-3. 사회적 가치와 파급효과

공공자산 공고는 공개되어 있지만 정보 해석 능력과 준비 경험에 따라 접근성이 달라질 수 있다. 본 서비스는 온비드 초보자, 소상공인, 예비창업자가 공공자산 활용 기회를 더 쉽게 검토하도록 돕는다. 또한 창업지원기관이나 컨설턴트가 초기기업에게 공공자산 활용 기회를 안내할 때 공고별 준비 체크리스트를 빠르게 만들 수 있어 상담 효율도 높일 수 있다.

### 7-3. 수상 이력

동일 아이템으로 기존 또는 타 기관 창업경진대회에서 입상한 이력은 없음으로 작성한다. 단, 최종 제출 전 사용자 확인이 필요하다. 기존 Bizketch 관련 제출 이력은 동일 아이템이 아니라 문서 기반 AI Agent 경험으로만 설명하고, 기존 사업명·공고명·수요기업명은 제출 본문 전면에 노출하지 않는다.

### 7-4. 제외 범위

본 서비스는 다음 기능을 1차 MVP 범위에서 제외한다.

- 법률·권리관계 판단, 투자수익률 판단
- 온비드 공식 절차 대체
- 사용자의 입찰가 결정 권유
- 원문 확인 없이 확정적 결론 제공

### 7-5. 최종 요약 문장

`OnBid Public Asset Doc Agent`는 KAMCO와 온비드가 개방한 공공데이터와 공개 공고 원문을 AI Agent와 연결해, 공공자산 공고를 검색 결과가 아니라 사용자가 바로 실행할 수 있는 준비 보드로 바꾸는 GovTech 서비스다. 사용자는 온비드 URL 하나를 붙여넣고, AI는 공고문에서 놓치기 쉬운 준비 빈칸을 체크리스트와 담당기관 문의 문장으로 변환한다. 제출 전 실증 MVP에서는 실제 온비드 임대/대부 및 매각/공매 URL을 기반으로 이 핵심 흐름을 화면화했고, 선정 후에는 샘플 공고 3건 이상과 초보 사용자 검증을 통해 준비 보드 품질과 반복 사용 가치를 높인다.
