## 1. 아이템의 소개

### 1-1. 개발 배경

온비드는 국유재산, 압류재산, 공공기관 보유 자산의 매각·임대 공고를 통합 제공하는 공공 플랫폼이다. KAMCO 사전 설문 양식 기준으로도 한국자산관리공사는 2026년 6월 현재 주요사업 관련 공공데이터 119종을 개방하고 있으며, 인기 오픈API에는 온비드 부동산 물건목록, 물건상세, 공고목록, 공고상세, 입찰결과 조회서비스가 포함된다. 공고와 물건정보는 공개되어 있지만, 실제 입찰 준비자는 공고문, 첨부문서, 물건정보, 입찰방식, 보증금, 제출서류, 낙찰 후 납부·계약 의무를 한 번에 이해해야 한다.

특히 개인, 소상공인, 공공자산을 활용해 창업을 검토하는 예비 사업자는 다음 문제를 겪는다.

- 공고명과 물건정보는 찾았지만, 입찰 전 반드시 준비할 서류와 기한을 놓치기 쉽다.
- 입찰보증금, 부가가치세, 보험료, 물품대부료, 잔대금 납부기한처럼 실제 비용과 일정에 영향을 주는 조항을 공고문 곳곳에서 찾아야 한다.
- `현장설명 생략`, `영업수익 보장 없음`, `유관기관 허가사항은 입찰자 책임` 같은 문구의 실무 의미를 이해하기 어렵다.
- 낙찰 후 7일 이내 신청, 선납, 보증보험증권 제출 같은 후속 의무를 사전에 체크하지 못하면 낙찰 무효나 보증금 귀속 위험이 생길 수 있다.

### 1-2. 아이템 내용

`OnBid Public Asset Doc Agent`는 온비드 공고를 단순 요약하는 서비스가 아니라, 사용자가 공공자산 입찰을 검토할 때 필요한 다음 행동을 정리해 주는 `공공자산 입찰 준비 보드`다.

사용자 입력은 두 가지 경로로 나뉜다.

| 입력 경로 | 사용자가 직접 입력하는 것 | 시스템이 자동으로 가져오는 것 |
| --- | --- | --- |
| 관심 공고 분석 | 온비드 공고 URL 또는 공고번호 1개, 사용자 유형, 내 검토 목적 | URL 안의 공고번호·물건번호, 공고명, 공고기관, 재산유형, 처분방식, 입찰기간, 보증금, 첨부문서, 제출서류 |
| 후보 공고 탐색 | 관심지역, 처분방식(임대/매각/공매), 재산유형, 예산·면적·마감기간, 사용자 유형 | 조건에 맞는 공고 목록, 마감 임박 여부, 유사 물건, 반복 공고 여부 |

따라서 사용자가 온비드 상세 URL을 붙여 넣는 경우 공고번호와 물건번호를 다시 입력할 필요가 없다. 공고번호·물건번호는 URL 또는 공공데이터 응답에서 자동 추출하고, 사용자는 본인의 목적과 상황만 보완 입력한다.

서비스의 출력은 `리스트업된 정보`가 아니라 사용자가 바로 처리할 수 있는 준비 보드다.

| 출력 | 사용자가 가져가는 결과 |
| --- | --- |
| 적합성 판정 | 이 공고가 사용자의 목적과 맞는지, 예를 들어 매각을 찾는 사용자가 임대 공고를 보고 있지는 않은지 먼저 알려준다. |
| 핵심 요약 | 공고명, 재산유형, 처분방식, 입찰방식, 보증금, 마감일, 낙찰 후 의무를 한 화면에서 확인한다. |
| 실행 체크리스트 | 입찰 전 해야 할 일을 `오늘 확인`, `서류 준비`, `마감 전 제출`, `낙찰 후 확인` 순서로 정리한다. |
| 서류 준비 링크 | 사업자등록증명, 인감증명서/본인서명사실확인서, 법인등기사항증명서, 국세·지방세 증명, 전자보증서 등 준비처와 공식 링크를 연결한다. |
| 담당기관 확인 질문 | AI가 판단을 대신하지 않고, 담당기관에 물어봐야 할 질문을 원문 근거와 함께 문장으로 정리한다. |
| 관심 공고 보드 | 여러 공고를 저장해 마감일, 준비상태, 서류 누락 여부를 비교·관리한다. |
| PDF/공유 리포트 | 본인 검토, 동업자 공유, 담당기관 문의에 쓸 수 있는 준비 리포트를 저장한다. |

핵심 가치는 `무엇을 준비해야 하는지 알려준다`에서 끝나지 않고, `어디서 준비하고, 언제까지 처리하고, 어떤 공고가 아직 막혀 있는지 관리하게 해준다`는 데 있다. 본 서비스는 온비드 공식 절차를 대신 수행하거나 결과를 약속하지 않는다. 공고 원문과 공공데이터를 사용자 행동 단위의 준비 보드로 바꾸는 보조 Agent다.

### 1-3. 사용 시나리오

1. 사용자는 온비드에서 본 공고 URL을 붙여 넣거나, 서비스 안에서 관심지역·처분방식·재산유형으로 후보 공고를 검색한다.
2. 서비스는 URL 또는 공공데이터에서 공고번호·물건번호·재산유형·처분방식·입찰기간을 자동 추출한다.
3. 사용자는 개인, 개인사업자, 법인, 예비창업자 중 본인 유형과 `임대/대부 검토`, `매각/공매 검토`, `창업 공간 탐색` 같은 목적만 선택한다.
4. 서비스는 공고 유형과 사용자 목적이 맞는지 먼저 판정하고, 맞지 않으면 다른 유형의 공고를 보도록 안내한다.
5. 맞는 공고라면 `핵심 요약`, `오늘 할 일`, `서류 준비 링크`, `마감 알림 후보`, `담당기관 확인 질문`을 한 화면에 보여준다.
6. 사용자는 여러 공고를 관심 보드에 저장하고, 각 공고별 준비상태를 `미확인`, `준비중`, `완료`, `담당기관 확인 필요`로 관리한다.
7. 최종 입찰 여부는 원문, 첨부문서, 담당기관 확인 후 결정하고, 서비스는 준비 리포트와 체크리스트를 보조 자료로 제공한다.

제출 준비 과정에서는 위 흐름을 심사위원이 실제 화면으로 이해할 수 있도록 로컬 MVP를 구성했다. 공개 온비드 공고 `202605-13728-00 2026년도010회 국유재산 대부입찰 공고`를 샘플로 사용해 `공고 가져오기 -> 공고 유형 판정 및 사용자 목적 비교 -> 준비 보드 -> 서류 준비 링크/체크리스트 -> 원문 근거 -> PDF 미리보기` 화면을 구현했다. 이 화면은 운영 서비스 완성본이 아니라 핵심 사용자 가치 검증용 프로토타입이며, 실제 API 연동 전에도 공개 공고 원문과 공공데이터 명세 기반 fallback으로 준비 보드 품질을 검증할 수 있음을 보여준다.

### 2-2. 시장진입 전략

초기 시장은 `온비드 공고를 실제 준비 행동으로 바꾸지 못하는 개인·소규모 사업자`로 좁힌다. 1차 MVP는 국유재산 임대·매각 공고 중심으로 시작하되, 단순 요약 리포트가 아니라 준비 보드와 공식 준비처 링크를 핵심 산출물로 둔다. 이후 차량, 동산, 압류재산, 입찰결과 비교, 지역별 통계 기반 후보 탐색으로 확장한다.

KAMCO 공공데이터 목록 자체가 온비드 물건·공고·입찰결과·용어사전으로 세분화되어 있다는 점은 반복 사용 가능성을 보여준다. 특히 온비드 월별 입찰참가자 현황 데이터는 2013년부터 2025년까지의 유효 입찰참가자 수를 월별로 제공하고, 캠코 공매물건과 이용기관 공매물건의 참가자를 구분한다. 사용자는 공고 1건을 읽을 때마다 일정, 서류, 보증금, 낙찰 후 의무를 다시 확인해야 하므로, 공고 단위 리포트는 건별 사용과 관심 조건 모니터링 모두로 확장할 수 있다.

시장진입은 다음 순서로 진행한다.

| 단계 | 기간 | 목표 | 산출물 |
| --- | --- | --- | --- |
| 1단계 | 1개월 | 국유재산 임대·매각 공고 3건 샘플 리포트 생성 | 샘플 리포트, 사용자 인터뷰 질문지 |
| 2단계 | 2개월 | 소상공인·예비 창업자 대상 사용성 검증 | 리포트 이해도, 누락 체크 항목, 재사용 의향 |
| 3단계 | 3개월 | 공고 검색·요약·PDF 리포트 MVP 공개 | 웹 MVP, 리포트 생성 로그 |
| 4단계 | 4~6개월 | 창업지원기관/컨설턴트 대상 B2B 사용 검증 | 월간 리포트 패키지, 기관용 관리자 기능 후보 |

초기 획득 채널은 온비드 초보자 대상 검색 콘텐츠, 소상공인·창업자 커뮤니티, 공공자산 활용 창업 사례 콘텐츠, 창업지원기관·컨설턴트 대상 샘플 준비 보드 배포로 잡는다. 1차 검증은 소상공인/예비창업자/컨설턴트 각 1명 이상에게 샘플 보드를 보여주고, `다음 행동 이해도`, `서류 준비 링크 유용성`, `마감·누락 방지 효과`, `여러 공고 관리 필요성`, `유료 사용 의향`을 확인한다. 무료 샘플은 공고 1건 요약과 확인 질문 3개까지만 제공하고, 유료 전환 기준은 전체 실행 체크리스트, 공식 준비처 링크, 관심 공고 보드, PDF 저장 기능의 필요 여부로 검증한다.

### 2-3. 수익모델

| 모델 | 설명 | 초기 적용 |
| --- | --- | --- |
| 건별 준비 보드 | 공고 1건의 실행 체크리스트, 준비 링크, PDF 생성 | 개인·소상공인 대상, 초기 가격 가설 3,000~9,900원 |
| 월 구독 | 관심 지역/재산유형 공고 모니터링, 마감 알림, 관심 공고 보드 | 반복 탐색 사용자, 초기 가격 가설 월 19,000~49,000원 |
| 전문가/기관용 패키지 | 여러 공고를 비교하고 고객별 준비상태와 확인 질문을 관리 | 컨설턴트, 창업지원기관, 초기 가격 가설 월 99,000원 이상 |
| API/화이트라벨 | 공공자산 공고 해석 모듈을 다른 플랫폼에 제공 | 후속 B2B 확장 |

### 2-4. 성장가능성

KAMCO와 온비드가 보유한 공공자산 데이터는 입찰공고, 물건정보, 입찰결과, 용어사전, 통계 데이터로 확장성이 높다. 본 아이템은 특정 공고 1건을 요약하는 데서 끝나지 않고, 공고 탐색, 후보 비교, 공식 서류 준비처 연결, 여러 공고 체크리스트 관리, 낙찰 후 의무 체크, 유사 공고 학습으로 확장할 수 있다.

데일컴퍼니는 기존 문서 Agent PoC에서 공고문·양식·제출서류를 구조화하고 HWPX/PDF 문서로 산출한 경험이 있다. 이 경험을 공공자산 도메인으로 전환하면, 짧은 기간 안에 실제 사용자가 볼 수 있는 리포트 MVP를 만들 수 있다.

### 3-4. 데이터 신뢰성 관리

- API 응답 조회시각을 리포트에 표시한다.
- 공고 원문과 공공데이터 값이 다르면 `원문 우선 확인 필요`로 표시한다.
- 공고 첨부문서의 법적 효력을 AI가 해석하지 않고, 담당기관·전문가 확인 필요 항목으로 분리한다.
- 개인정보와 사용자의 입찰 희망가격은 기본 저장하지 않고, 리포트 생성 세션 내 처리 또는 사용자 로컬 저장을 우선한다.
- 낙찰 가능성, 수익성, 권리관계, 법률 판단은 제공 범위에서 제외한다.

### 4-3. MVP 추진계획

현재 제출 전 단계에서는 신청서 증빙용 로컬 MVP를 먼저 만들어 핵심 흐름을 확인했다. MVP는 실제 온비드 API 운영키에 의존하지 않고, 공개 온비드 공고 1건을 표준 JSON 구조로 옮긴 샘플 데이터를 사용한다. 화면에는 샘플 공고 기반, 원문 확인 필요, 법률·투자 판단 아님을 명시해 과장이나 공식 절차 대체 오해를 피했다. 이번 v03에서는 내부 기술 화면보다 `사용자가 가져가는 준비 보드`를 전면에 둔다.

| 컨설팅/수작업 | 비용이 크고 반복 공고 탐색에 시간이 많이 듦 | 건별 준비 보드와 월간 관심 공고 관리로 접근성 개선 |

### 5-2. 창의성

본 아이템의 창의성은 AI로 공고를 예쁘게 요약하는 데 있지 않다. 공공데이터 API, 공고 원문, 첨부문서, 용어사전, 사용자 유형을 결합해 `공공자산 공고를 실행 가능한 준비 보드로 바꾸는 흐름`에 있다.

즉, 온비드가 제공하는 공고 데이터의 접근성을 높이고, 사용자가 입찰 전 준비해야 할 실제 행동과 준비처를 구조화한다. 이는 KAMCO 공공데이터 활용을 일반 국민 서비스 개선과 창업 서비스 개발로 연결하는 방식이다.

### 5-3. 사회적 가치와 파급효과

| 효과 | 설명 |
| --- | --- |

## 7. 기타사항

### 7-1. 제출 전 샘플 산출물

현재 제출 패키지에는 실제 온비드 공개 공고를 기반으로 만든 샘플 입력, 샘플 분석 리포트, 로컬 MVP 화면 증빙을 포함한다.

- 샘플 입력: 온비드 국유재산 임대 공고 구조화 데이터
- 샘플 출력: 공고 적합성 판정, 핵심 요약, 오늘 할 일, 서류 준비처 링크, 비용 후보, 담당기관 확인 질문, 관심 공고 관리 보드, PDF 리포트
- 평가항목 매핑표: 사업성, 공공데이터 활용성, 실현 가능성, 창의성 대응표
- MVP 화면: 공고 가져오기, 준비 보드, 서류 준비, 문의/근거, PDF 미리보기

MVP 화면은 `2026년도010회 국유재산 대부입찰 공고`를 샘플로 사용했다. 공개 온비드 페이지에서 확인되는 공고명, 공고기관, 재산유형, 입찰방식, 입찰구분, 공고일, 관련문서, 제출서류, 입찰보증금, 대부료 납부 방식, 리스크 문구를 표준 JSON으로 옮겼고, 이를 화면에서 적합성 판정, 오늘 할 일, 서류 준비 링크, 비용 후보, 담당기관 확인 질문으로 변환했다.

### 7-2. MVP 화면 증빙 스토리라인

| 화면 | 심사위원에게 전달할 메시지 |
| --- | --- |
| 공고 가져오기 | 사용자는 온비드 URL만 넣어도 공고번호·물건번호를 다시 입력하지 않고 분석을 시작할 수 있으며, 목적과 공고 유형이 맞는지 먼저 확인한다. |
| 준비 보드 | 일정, 비용 후보, 오늘 할 일, 알림 후보가 한 화면에 모여 사용자의 다음 행동으로 바뀐다. |
| 서류 준비 | 제출서류를 나열하는 데서 끝나지 않고, 각 서류를 어디에서 준비할지 공식 준비처 링크와 상태값으로 관리한다. |
| 관심 공고 관리 | 여러 공고의 마감일, 준비상태, 확인 필요 항목을 비교해 반복 탐색 사용가치를 보여준다. |
| 근거/PDF | AI가 입찰 여부를 판단하지 않고, 담당기관에 확인해야 할 질문과 원문 근거를 공유 가능한 리포트로 제시한다. |

### 7-3. 수상 이력

동일 아이템으로 기존 또는 타 기관 창업경진대회에서 입상한 이력은 없음으로 작성한다. 단, 최종 제출 전 사용자 확인이 필요하다. 기존 Bizketch 관련 제출 이력은 동일 아이템이 아니라 문서 기반 AI Agent 경험으로만 설명하고, 기존 사업명·공고명·수요기업명은 제출 본문 전면에 노출하지 않는다.

### 7-4. 제외 범위

- 낙찰 가능성 보장
- 투자수익률 예측 또는 보장
- 법률·권리관계 판단 대체
- 감정평가 대체
- 현장조사 대체
- 온비드 공식 절차를 대신 수행하는 행위
- 온비드 공식 절차 대체

### 7-5. 최종 요약 문장

`OnBid Public Asset Doc Agent`는 KAMCO와 온비드가 개방한 공공데이터를 AI 문서 Agent로 연결해, 공공자산 공고를 검색 결과가 아니라 사용자가 바로 실행할 수 있는 준비 보드로 바꾸는 GovTech 서비스다. 제출 전 MVP에서는 공개 온비드 공고 1건으로 이 핵심 흐름을 화면화했고, 선정 후에는 실제 API와 샘플 공고 3건을 연결해 준비 보드 품질, 서류 준비 링크 유용성, 여러 공고 관리 필요성을 검증한다.
