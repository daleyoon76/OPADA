## 1. 핵심 요약

### 서비스 한 줄 소개

온비드 공공자산 공고와 한국자산관리공사 공공데이터를 AI로 구조화해, 입찰 초보자와 소규모 사업자가 일정, 제출서류, 비용 후보, 낙찰 후 의무, 유의 리스크를 근거와 함께 이해하도록 돕는 공공자산 공고 해석 리포트 서비스.

### 해결하려는 문제

온비드에는 국유재산, 압류재산, 공공기관 보유 자산의 매각/임대 공고가 공개되어 있지만, 사용자는 공고문, 첨부문서, 물건정보, 입찰정보, 보증금, 제출서류, 낙찰 후 납부/계약 의무를 직접 대조해야 한다. 개인, 소상공인, 공공자산 활용 창업자는 공고를 찾은 뒤에도 `지금 무엇을 준비해야 하는지`, `놓치면 어떤 문제가 생기는지`를 구조화하기 어렵다.

### 대상 고객

- 온비드 입찰 경험이 적은 개인
- 공공기관 임대공간, 국유재산, 매각 물건을 사업 기회로 검토하는 소상공인/자영업자
- 공공자산을 활용해 창업 공간, 장비, 운영 거점을 찾는 예비 창업자/초기 창업자
- 초기기업의 공공자산 활용 기회 탐색을 돕는 창업지원기관, 컨설턴트, 액셀러레이터

### 핵심 차별화 포인트

- 단순 공고 검색이나 일반 요약이 아니라, 공고 원문과 KAMCO/온비드 공공데이터를 `준비 체크리스트`와 `리스크 질문`으로 변환한다.
- 온비드 공고목록, 공고상세, 물건정보, 입찰정보, 입찰결과, 용어사전을 연결해 근거 기반 리포트를 만든다.
- 낙찰 가능성이나 수익률을 예측하지 않고, 사용자가 담당기관/전문가에게 확인해야 할 질문을 분리해 안전한 의사결정을 돕는다.
- 기존 문서 Agent PoC 경험을 활용해 공고문 파싱, 체크리스트 생성, HWPX/PDF 산출, 룰 기반 검증을 빠르게 MVP로 전환할 수 있다.

### 수익 모델 요약

- 개인/소상공인 대상 건별 공고 리포트: 3,000원~9,900원
- 반복 탐색 사용자 대상 월 구독: 월 19,000원~49,000원
- 컨설턴트/창업지원기관 대상 전문가 패키지: 월 99,000원 이상
- 후속 확장: API/화이트라벨, 기관용 공고 모니터링, 지역/유형별 공공자산 기회 리포트

## 2. 시장 트렌드

### 산업/시장 동향

공공기관과 지자체는 국유재산, 공유재산, 공공시설, 차량, 동산, 압류재산 등 다양한 공공자산 정보를 온라인으로 공개하고 있다. 온비드는 공공자산 입찰/공매 정보를 통합 제공하는 대표 플랫폼이며, 일반 국민과 소규모 사업자도 공공자산 임대/매각 기회를 직접 탐색할 수 있는 기반을 제공한다.

다만 정보가 공개되어 있다는 것과 실제 사용자가 공고를 이해하고 입찰 준비를 완료할 수 있다는 것은 다르다. 공고 해석, 제출서류 확인, 비용 항목 확인, 낙찰 후 의무 확인에는 여전히 문서 해석 능력과 행정 절차 이해가 필요하다. 따라서 공공데이터 개방 다음 단계의 수요는 `검색`이 아니라 `이해와 실행 준비`에 있다.

KAMCO 공공데이터에는 온비드 공고, 물건, 입찰정보, 입찰결과, 용어사전, 월별 입찰참가자 현황이 포함되어 있다. 특히 월별 입찰참가자 현황은 2013년부터 2025년까지 장기간의 유효 입찰참가자 수를 제공하므로, 온비드 탐색과 입찰 준비가 반복적으로 발생하는 시장이라는 점을 보여준다.

### 관련 기술 트렌드

- 생성형 AI와 LLM을 활용한 문서 요약, 정보 추출, Q&A, 리포트 생성이 빠르게 상용화되고 있다.
- RAG와 근거 기반 답변 구조가 확산되면서, 단순 생성보다 원문 출처와 데이터 필드 기반 답변의 중요성이 커지고 있다.
- 업무문서 Agent는 사용자가 문서를 처음부터 읽지 않고도 요약, 체크리스트, 리스크, 다음 액션을 파악하도록 돕는 방향으로 발전하고 있다.
- 공공데이터 API와 생성형 AI를 결합하면 공고, 정책, 지원사업, 입찰, 조달 문서를 사용자별 준비 문서로 바꾸는 GovTech SaaS가 가능하다.

### 규제/정책 변화

- 공공데이터 개방 정책은 공공기관 보유 데이터를 민간 서비스와 창업 아이템으로 전환하도록 장려한다.
- AI 서비스는 허위정보, 법률/투자 자문 오해, 개인정보 처리, 원문 근거 누락에 주의해야 한다.
- 본 서비스는 온비드 공식 절차를 대신하지 않고, 공고 원문과 담당기관 확인을 우선하는 준비 보조 서비스로 포지셔닝한다.

## 3. 문제 정의

### 고객이 겪는 핵심 문제

온비드 사용자는 관심 공고를 찾은 뒤 다음 작업을 직접 수행해야 한다.

- 공고문과 첨부문서 열람
- 물건정보, 입찰정보, 공고 본문 비교
- 입찰서 제출, 보증금 납부, 서류 제출, 개찰, 낙찰 후 신청 기한 확인
- 사업자등록증명, 등본/등기부등본, 인감증명서, 국세/지방세 완납증명서 등 제출서류 확인
- 사용료, 부가가치세, 보험료, 물품대부료, 잔대금, 보증보험 등 비용 후보 확인
- 현장조사, 인허가, 영업수익 미보장, 유관기관 허가사항, 사용자 책임 문구 확인

공고문은 법령/계약/입찰 용어가 많고, 일정과 의무가 여러 문단에 흩어져 있다. 경험이 적은 사용자는 공고를 읽어도 실제 준비 순서를 놓치기 쉽다.

### 기존 해결 방식의 한계

| 기존 방식 | 한계 |
| --- | --- |
| 온비드 직접 검색 | 공고 탐색은 가능하지만 일정, 서류, 비용, 리스크를 사용자가 직접 해석해야 한다. |
| 공고문 수작업 정리 | 시간이 많이 들고, 반복 공고 탐색에 적합하지 않다. |
| 범용 LLM 요약 | 최신 공고와 공공데이터 필드를 안정적으로 반영하기 어렵고, 원문 근거가 약할 수 있다. |
| 부동산/투자 정보 서비스 | 공공자산 입찰 절차와 제출서류, 낙찰 후 의무에 특화되어 있지 않다. |
| 전문가 컨설팅 | 비용이 높고, 초보 개인/소상공인이 공고 1건마다 이용하기 어렵다. |

### 미충족 수요

- 공고를 읽기 전에 핵심 조건과 마감 리스크를 빠르게 알고 싶다.
- 내 사용자 유형에 맞는 제출서류와 준비 순서를 알고 싶다.
- 보증금, 사용료, 부가세, 보험료 등 비용 후보를 빠뜨리지 않고 확인하고 싶다.
- 어려운 온비드/공매 용어를 쉬운 말로 이해하고 싶다.
- 낙찰 가능성이나 수익률이 아니라, 담당기관에 확인해야 할 질문 목록이 필요하다.
- 공고 원문과 공공데이터 출처를 함께 보면서 스스로 판단하고 싶다.

## 4. 솔루션

### 제품/서비스 설명

OnBid Public Asset Doc Agent는 사용자가 온비드 공고 URL, 공고번호, 물건번호, 관심 지역/재산유형을 입력하면 KAMCO/온비드 공공데이터와 공고 원문을 함께 분석해 공고 해석 리포트를 생성한다. 리포트에는 공고 한 줄 요약, 핵심 조건, 일정표, 제출서류 체크리스트, 비용 후보, 리스크 카드, 확인 질문, 용어 설명, 원문 근거가 포함된다.

서비스는 온비드 공식 절차를 대체하지 않는다. 최종 입찰 여부, 법률/권리관계, 사업성, 낙찰가, 수익성 판단은 사용자가 원문 공고, 첨부문서, 담당기관, 전문가 확인을 통해 결정하도록 안내한다.

### 핵심 기능

- 기능 1: 공고 입력 및 공공데이터 조회
  - 공고 URL, 공고관리번호, 물건관리번호, 사용자 유형, 관심 목적을 입력받는다.
  - 온비드 공고목록, 공고상세, 물건정보, 입찰정보 API 필드를 표준 입력 스키마로 변환한다.

- 기능 2: 공고 구조화 및 원문 정합성 체크
  - 공고문과 첨부문서에서 일정, 제출서류, 보증금, 낙찰 후 의무, 유의사항을 추출한다.
  - API 값과 공고 원문이 다르면 `원문 우선 확인 필요`로 표시한다.

- 기능 3: 사용자 유형별 체크리스트
  - 개인, 개인사업자, 법인, 창업 준비자별로 제출서류와 준비 순서를 분기한다.
  - 서류 제출 방식, 온라인/오프라인 제출 여부, 마감 시간을 함께 표시한다.

- 기능 4: 비용 후보 및 리스크 카드
  - 사용료, 부가세, 보험료, 보증보험, 물품대부료, 잔대금, 입찰보증금 등 비용 후보를 정리한다.
  - 현장확인, 인허가, 영업수익 미보장, 낙찰 후 기한, 유관기관 허가사항 등 리스크를 질문 형태로 바꾼다.

- 기능 5: 근거 기반 Q&A 및 PDF 리포트
  - 사용자가 `제일 먼저 확인할 것은 무엇인가요?`처럼 질문하면 공고 원문과 공공데이터 근거를 바탕으로 답한다.
  - 요약, 일정, 서류, 비용, 리스크, 다음 액션을 PDF 리포트로 저장한다.

### 기술 스택 / 구현 방식

초기 MVP는 정적 샘플 데이터와 오프라인 캐시를 활용해 빠르게 검증한다. 운영 버전은 아래 구조를 목표로 한다.

- Frontend: Next.js 또는 React 기반 웹 UI
- Backend/API: Node.js API route 또는 서버리스 함수
- Data source: KAMCO/온비드 공공데이터 API, 온비드 공개 공고 원문, 온비드 용어사전
- AI layer: 문서 파서, 체크리스트 Agent, 리스크 Guard Agent, Glossary Agent, Report Agent
- Report output: HTML/PDF 리포트, 추후 HWPX/PDF 산출 확장
- Validation: 수작업 정답지와 항목 일치율 비교, 금지표현/과장표현 스캔, 원문 근거 추적

### MVP Critical Path

1. 샘플 온비드 공고 1건을 표준 입력 JSON으로 만든다.
2. 공고 요약, 핵심 조건, 일정표, 제출서류, 비용 후보, 리스크 질문을 화면에 표시한다.
3. 각 항목에 원문 근거 또는 데이터 출처를 붙인다.
4. 인쇄/PDF 저장 가능한 리포트 화면을 만든다.
5. 샘플 공고 3건까지 확장해 수작업 체크리스트와 비교한다.

#### 강점 (Strengths)

- 공고문/양식/제출서류를 구조화하고 PDF/HWPX 산출물을 만든 기존 문서 Agent PoC 경험이 있다.
- KAMCO/온비드 공공데이터와 공고 원문을 직접 연결하는 도메인 특화 서비스다.
- 법률/투자 판단이 아니라 준비 보조에 집중해 초기 제품 범위를 명확히 제한할 수 있다.
- 1인기업이라 의사결정과 MVP 제작 속도가 빠르다.

#### 약점 (Weaknesses)

- 온비드 공매/입찰 도메인 전문성은 초기 단계에서 외부 자문이 필요할 수 있다.
- 실제 API 연동과 운영키 발급, 트래픽 제한, 데이터 누락 상황에 대비해야 한다.
- 초기에는 국유재산 임대/매각 공고 중심으로 범위가 좁다.

#### 기회 (Opportunities)

- 공공데이터 개방과 생성형 AI 활용 수요가 맞물려 GovTech 문서 Agent 시장이 커질 수 있다.
- 온비드 공고 해석에서 시작해 지자체 공유재산, 공공기관 입찰, 조달/지원사업 문서까지 확장할 수 있다.
- 창업지원기관과 컨설턴트는 여러 고객의 공고 탐색을 반복적으로 수행하므로 B2B 패키지 전환 가능성이 있다.

#### 위협 (Threats)

- 범용 LLM 서비스가 문서 요약 기능을 빠르게 개선할 수 있다.
- 공공데이터 API 정책, 호출 제한, 필드 변경, 공고 원문 접근 방식이 바뀔 수 있다.
- 법률/권리관계/수익성 판단으로 오해되면 서비스 신뢰와 책임 리스크가 생길 수 있다.

## 6. 차별화 전략

### 핵심 경쟁 우위

핵심 경쟁 우위는 `공공자산 공고를 실행 가능한 준비 문서로 바꾸는 도메인 특화 구조`다. 온비드 직접 검색은 정보를 보여주지만 준비 문서로 바꾸지는 않는다. 범용 AI 요약은 문장을 줄여주지만, 공공데이터 필드, 제출서류, 일정, 비용, 리스크, 원문 근거를 일관된 형식으로 관리하기 어렵다.

본 서비스는 다음 방식으로 차별화한다.

- 공고 원문과 API 필드를 표준 스키마로 매핑한다.
- 사용자 유형별 제출서류 체크리스트를 생성한다.
- 비용 후보와 확정 비용을 구분한다.
- 리스크를 단정하지 않고 담당기관 확인 질문으로 변환한다.
- 온비드 용어사전 기반 쉬운 설명을 제공한다.
- 모든 리포트에 조회시각, 원문 URL, 데이터 출처, 원문 우선 원칙을 표시한다.

### 진입 장벽 / 해자

- 공고 유형별 파서와 체크리스트 룰셋 축적
- 샘플 공고별 수작업 정답지와 AI 결과 비교 데이터 축적
- 온비드 용어사전, 입찰결과, 월별 입찰참가자 현황 등 공공데이터 활용 맥락 축적
- 사용자 피드백 기반 리스크 질문 템플릿 축적
- 공공자산 공고 리포트 생성 로그와 품질 검증 체계

## 7. 시장 규모

### TAM (전체 시장)

가장 넓은 시장은 공공데이터 기반 GovTech SaaS와 공공/행정 문서 자동화 시장이다. 공공기관 공고, 입찰, 조달, 지원사업, 인허가, 행정서류는 모두 사용자가 원문을 해석하고 준비 행동으로 바꿔야 하는 문서형 업무다.

### SAM (유효 시장)

초기 유효 시장은 온비드 공공자산 공고를 탐색하고 입찰/임대/매각 참여 가능성을 검토하는 개인, 소상공인, 공공자산 활용 창업자, 컨설턴트 시장이다. KAMCO/온비드 데이터에는 공고, 물건, 입찰결과, 용어사전, 월별 입찰참가자 현황이 포함되어 있어 공고 단위 리포트와 반복 모니터링 수요를 검증할 수 있다.

### SOM (초기 목표 시장)

1~2년 초기 목표는 대규모 플랫폼이 아니라, `공고 해석 리포트가 실제로 돈을 받을 만큼 유용한지`를 검증하는 것이다.

- 1단계 목표: 과거 공개 공고 3건 기반 샘플 리포트와 사용자 인터뷰 확보
- 2단계 목표: 개인/소상공인/컨설턴트 각 1명 이상 사용성 검증
- 3단계 목표: 건별 리포트 결제 의향과 월간 모니터링 수요 검증
- 4단계 목표: 창업지원기관/컨설턴트 대상 기관용 패키지 PoC

정량 가설은 Bizketch가 보완하도록 둔다. 다만 무리한 전체 시장 금액 추정보다, 초기 SOM은 공고 1건당 유료 리포트와 기관용 반복 사용 검증 중심으로 산정하는 것이 적절하다.

## 8. 사업 모델

### 수익 구조

| 모델 | 설명 | 초기 가격 가설 |
| --- | --- | --- |
| 건별 리포트 | 공고 1건 요약, 일정, 제출서류, 비용 후보, 리스크 질문, PDF 저장 | 3,000원~9,900원 |
| 월 구독 | 관심 지역/재산유형 공고 모니터링, 월간 요약 리포트 | 월 19,000원~49,000원 |
| 전문가/기관용 패키지 | 여러 공고 비교, 고객별 확인 질문, 상담용 리포트 관리 | 월 99,000원 이상 |
| API/화이트라벨 | 공공자산 공고 해석 모듈을 다른 플랫폼에 제공 | 후속 협의형 |

무료 샘플은 공고 1건의 요약과 리스크 3개까지만 제공한다. 유료 전환 기준은 전체 제출서류 체크리스트, 비용 후보, 담당기관 확인 질문, PDF 저장 기능의 필요 여부로 검증한다.

### 비용 구조

- AI API 호출 비용
- 공공데이터 API 호출 및 캐시 운영 비용
- 웹 서버/스토리지/로그 인프라 비용
- PDF 생성 및 문서 변환 비용
- 도메인 전문가 자문 비용
- 사용자 인터뷰, 콘텐츠 마케팅, 커뮤니티 테스트 비용

### 손익분기점(BEP) 예상

초기에는 고정비를 낮게 유지하고, MVP 검증 단계에서는 대표자 직접 개발과 샘플 데이터 기반 운영으로 비용을 통제한다. BEP는 Bizketch가 다음 가정으로 보완한다.

- 건별 리포트 평균 단가
- 월 구독 전환율
- AI 호출당 평균 원가
- 월 서버/운영 비용
- 기관용 패키지 판매 가능성

보수적으로는 월간 유료 리포트 수와 기관용 패키지 1~2건 확보 시점을 기준으로 BEP를 산정한다.

## 9. 사업 전략 및 로드맵

### 마케팅 / 성장 전략

- KAMCO/온비드 공공데이터 활용 사례로 포지셔닝해 GovTech 레퍼런스를 확보한다.

### 단계별 마일스톤

- 1단계 (0~1개월): 국유재산 임대/매각 공고 3건 샘플 리포트 생성
  - 산출물: 데이터 매핑표, 샘플 입력 JSON, 공고 분석 리포트, PDF 출력
  - 검증: 수작업 체크리스트와 항목 일치율 비교

- 2단계 (1~2개월): 소상공인/예비 창업자/컨설턴트 사용성 검증
  - 산출물: 사용자 인터뷰 기록, 리포트 이해도, 누락 항목, 재사용 의향
  - 검증: 공고 이해도, 서류 누락 방지 효과, 유료 의향

- 3단계 (2~3개월): 웹 MVP 공개
  - 산출물: 공고 입력 화면, 구조화 화면, 리포트 미리보기, PDF 저장
  - 검증: 리포트 생성 시간, 반복 사용 로그, 오류/누락 사례

- 4단계 (3~6개월): 공고 유형 확장과 B2B 검증
  - 산출물: 차량/동산/압류재산 후보 확장, 기관용 리포트 패키지
  - 검증: 기관용 반복 사용성, 월간 모니터링 수요, API/화이트라벨 가능성

## 10. 리스크 분석

### 리스크 1: 개발 범위 과대

전자입찰, 자동 입찰, 낙찰 가능성 예측, 수익률 예측, 법률/권리관계 판단까지 포함하면 1인기업 MVP 범위를 초과한다.

대응 방안: 1차 MVP는 공고 해석, 제출서류 체크리스트, 비용 후보, 리스크 질문, PDF 리포트 생성으로 제한한다. 입찰 대행, 투자 판단, 법률 판단, 현장조사 대체는 제외 범위로 명시한다.

### 리스크 2: 공공데이터 API 인증키/트래픽/필드 변경

운영키 발급 지연, API 호출 제한, 응답 필드 변경, 공고 원문 접근 제한이 생길 수 있다.

대응 방안: 공공데이터포털 명세, 샘플 응답, 온비드 공개 공고 원문, CSV 캐시를 이용해 오프라인 MVP를 먼저 만든다. 리포트에는 데이터 출처와 조회시각을 표시하고, 운영키 준비 후 동일 스키마에 실제 API 응답을 연결한다.

### 리스크 3: 법률/권리관계/수익성 판단 오해

사용자가 리포트를 법률 자문, 투자 추천, 낙찰 가능성 판단으로 오해하면 책임 리스크가 생긴다.

대응 방안: 모든 화면과 PDF에 `준비 보조 리포트`임을 명시한다. 낙찰 가능성, 수익성, 권리관계, 법률 판단은 제공하지 않고, 담당기관/전문가 확인 질문으로 분리한다.

### 리스크 4: 공고 해석 품질과 누락

공고 유형이 다양해 일정, 서류, 비용, 낙찰 후 의무 추출이 누락될 수 있다.

대응 방안: 샘플 공고별 수작업 정답지를 만들고 AI 결과와 비교한다. 제출서류, 보증금, 납부기한, 현장확인, 인허가, 수익 미보장, 낙찰 후 의무 등 핵심 룰 기반 검증표를 운영한다.

### 리스크 5: 도메인 전문성 부족

공매, 국유재산, 행정서류, 부동산 권리관계는 전문성이 필요한 영역이다.

대응 방안: 1차 서비스는 법률/권리관계 판단을 제외하고, 공고 원문 기반 준비사항 정리에 집중한다. 필요 시 공매/부동산/행정서류 전문가 자문을 월 2회 이내, 총 50만원 이하 범위에서 확보한다.
