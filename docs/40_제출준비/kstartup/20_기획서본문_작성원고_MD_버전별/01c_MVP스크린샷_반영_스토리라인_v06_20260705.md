# OnBid Public Asset Doc Agent 신청서 v06 스토리라인 수정안

작성일: 2026-07-05

## 수정 방향

v05 본문은 `공고 해석 리포트`, `PDF 리포트`, `Q&A` 중심으로 읽힌다. 최신 MVP 화면은 사용자가 온비드 URL을 붙여넣으면 AI가 공고문에서 놓치기 쉬운 준비 빈칸을 찾아 체크리스트 우선순위와 담당기관 문의 문장으로 바꾸는 구조다.

따라서 신청서 본문과 캡션은 다음 메시지로 정렬한다.

> 초보자는 온비드 공고 URL 하나만 붙여넣고, AI는 공고문만으로 놓치기 쉬운 준비 빈칸을 체크리스트와 담당기관 문의 문장으로 바꿉니다.

## 교체 문단 후보: 1. 아이템의 소개

### 아이템 내용

`OnBid Public Asset Doc Agent`는 온비드 공고와 한국자산관리공사 공공데이터를 기반으로 공공자산 공고를 실행 가능한 준비 보드로 바꾸는 AI 서비스다. 사용자가 온비드 공고/물건 URL을 입력하면 공고번호와 물건번호, 재산유형, 처분방식, 입찰기간, 가격/보증금, 제출서류, 담당기관 정보를 자동 추출하고, 사용자의 검토 목적과 비교해 준비 보드를 생성한다.

서비스의 핵심 출력은 PDF 리포트가 아니라 `AI 우선 체크리스트`다. AI는 원문에 이미 보이는 값을 반복 요약하는 대신, 초보 사용자가 놓치기 쉬운 빈칸을 분리한다. 예를 들어 임대/대부 공고에서는 `내 업종으로 실제 사용 가능한지`, `현장 상태와 인수 범위`, `대부료 외 반복 비용`처럼 원문만 읽고 지나치기 쉬운 확인 항목을 체크리스트 상단에 올리고, 담당기관에 바로 물어볼 문장으로 바꾼다.

본 서비스는 온비드 전자입찰 절차를 대신 수행하거나 낙찰 가능성, 법률 판단, 투자수익률을 제공하지 않는다. 공식 공고와 공공데이터를 사용자가 스스로 확인할 수 있도록 구조화하는 준비 보조 Agent다. 사용자는 준비 보드에서 본인의 자격, 서류 발급 가능일, 현장확인 필요사항, 납부 가능 자금, 담당기관 문의사항을 체크하며 공고 검토를 이어갈 수 있다.

1차 MVP는 국유재산·공유재산 임대/대부 및 매각 공고를 중심으로 시작한다. 현재 로컬 실증 MVP는 온비드 short URL과 공고/물건 상세 URL을 실제로 따라가 공개 페이지를 읽고, 분석 미리보기와 준비 보드를 생성한다. 이후 관심 공고 관리, 유사 공고 비교, 기관/컨설턴트용 다중 공고 관리로 확장한다.

### 사용 시나리오

1. 사용자는 온비드에서 관심 공고나 물건 상세 페이지 URL을 복사해 서비스에 붙여넣는다.
2. 서비스는 최종 상세 URL을 따라가 공고번호, 물건번호, 재산유형, 처분방식, 입찰기간, 가격/보증금, 담당기관을 추출한다.
3. 사용자는 `개인사업자`, `개인`, `법인`, `예비창업자` 등 사용자 유형과 `임대/대부`, `매각/공매`, `창업 공간 탐색` 목적을 선택한다.
4. AI는 공고문에 이미 있는 값을 단순 반복하지 않고, 실제 준비 전에 남는 빈칸을 찾는다.
5. 준비 보드는 AI 우선 확인 항목을 체크리스트 상단에 표시하고, 사용자가 담당기관에 물어볼 문장을 접이식 상세에 제공한다.
6. 사용자는 원문 링크를 열어 근거를 확인하고, 체크박스로 준비 진행률을 관리하며, 관심 공고에 저장해 여러 공고의 준비 상태를 이어서 본다.

## 교체 문단 후보: 2. 사업성 및 성장가능성

### 목표 고객과 제공 가치

초기 고객은 온비드 입찰 초보 개인, 소상공인·자영업자, 공공자산 활용 창업자, 창업지원기관·컨설턴트다. 이들은 공공기관 임대공간이나 매각물건을 사업기회로 검토하지만, 공고 검색 이후 `무엇을 언제까지 확인해야 하는가`에서 반복적으로 막힌다.

| 고객군 | 기존 문제 | MVP 제공 가치 |
| --- | --- | --- |
| 온비드 입찰 초보 개인 | 공고문과 전자입찰 절차 이해가 어려움 | URL 하나로 공고 핵심값과 다음 확인 항목을 준비 보드로 확인 |
| 소상공인·자영업자 | 임대공간의 사용 가능 업종, 현장 상태, 반복 비용을 놓치기 쉬움 | AI가 `내 업종으로 실제 사용 가능한지` 같은 빈칸을 우선 체크 항목으로 표시 |
| 공공자산 활용 창업자 | 여러 공고를 비교하면서 준비 상태를 관리하기 어려움 | 관심 공고와 최근 살펴본 공고를 저장하고 다음 액션을 이어서 확인 |
| 창업지원기관·컨설턴트 | 초기기업별 공고 해석과 확인 질문 작성 시간이 큼 | 담당기관에 물어볼 문장을 자동 정리해 상담 준비 시간을 단축 |

### 시장 진입 전략

시장진입은 `국유재산·공유재산 임대/대부 공고 3건 실증`, `초보 사용자 3명 사용성 검증`, `AI 우선 체크리스트 정확도 개선`, `관심 공고 관리와 알림 확장` 순서로 진행한다. 초기 획득 채널은 온비드 초보자 대상 검색 콘텐츠, 소상공인·창업자 커뮤니티, 공공자산 활용 창업 사례 콘텐츠, 창업지원기관·컨설턴트 대상 샘플 준비 보드 제공으로 잡는다.

무료 사용자는 공고 1건 분석과 AI 우선 확인 3개까지 경험하게 하고, 유료 전환은 다중 공고 저장, 관심 지역 모니터링, 문의 문장/검토 메모 관리, 기관용 공고 비교 기능에서 검증한다.

## 교체 문단 후보: 3. AI 및 공공데이터 활용성

### AI Agent 처리 구조

AI는 공고 원문을 임의로 판단하지 않고, 구조화된 공고 필드와 사용자 유형을 입력으로 받아 `확인된 사실`, `미해결 빈칸`, `담당기관 문의 문장`, `안전 경계`를 분리한다.

| 단계 | 처리 내용 | 사용자에게 보이는 결과 |
| --- | --- | --- |
| 원문 수집 | 온비드 공고/물건 URL, short URL을 최종 상세 페이지로 변환 | 현재 분석 페이지, 공고보기, 물건상세 링크 |
| 구조화 | 공고번호, 물건번호, 재산유형, 처분방식, 일정, 가격/보증금, 담당기관 추출 | 분석 미리보기와 공고 요약 |
| 목적 비교 | 사용자의 검토 목적과 공고 유형 비교 | 목적 확인 또는 목적 불일치 표시 |
| AI 누락 점검 | 원문에 값이 있어도 실제 준비 전에 확인해야 하는 빈칸 도출 | `AI 우선 액션`, `AI 우선 확인` 배지 |
| 문의 문장화 | 확인 항목을 담당기관에 물어볼 문장으로 변환 | 체크리스트 상세의 문의 문장 |
| 안전 경계 | 입찰 여부, 법률, 수익성 판단은 제외 | 원문 우선 고지와 근거 표시 |

## 신청서 본문에 넣을 MVP 증빙 문장

제출 준비 과정에서 실제 온비드 공개 공고 URL을 입력해 공고 가져오기, 공고/물건 연결, 분석 미리보기, AI 우선 준비 보드, 담당기관 문의 문장, 관심 공고 관리까지의 핵심 MVP 화면을 구현했다. 현재 실증 MVP는 온비드 short URL과 공고/물건 상세 URL을 따라가 주요 필드를 추출하고, AI가 원문에서 놓치기 쉬운 준비 빈칸을 체크리스트 우선순위로 연결한다.

특히 최신 MVP는 단순 요약 리포트가 아니라 사용자의 다음 행동을 관리하는 준비 도구에 초점을 맞췄다. 사용자는 공고별로 `무엇을 확인해야 하는지`, `어디에서 원문을 볼 수 있는지`, `담당기관에 어떤 문장으로 물어보면 되는지`를 한 화면에서 확인하고 체크할 수 있다. 이는 온비드 초보자와 소상공인이 공고 검색 이후 겪는 해석·서류·마감·문의 준비 부담을 줄이는 방향이다.

## v05에서 낮출 표현

- `PDF 리포트 생성`은 핵심 MVP가 아니라 후속 저장/공유 기능으로 낮춘다.
- `Q&A 챗봇`은 1차 MVP 범위가 아니라 문의 문장 생성 이후 확장 기능으로 둔다.
- `공고 해석 리포트 Agent`보다 `공공자산 공고 준비 보드 Agent` 또는 `온비드 공고 준비 체크리스트 Agent` 표현을 우선한다.
- `Vertex AI`, `Gemini`, 특정 공급자명은 제출 화면/본문에서 전면 노출하지 않고 `AI 누락 점검` 또는 `AI 우선 체크리스트`로 표현한다.
