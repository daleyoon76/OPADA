## 2. 화면 구조·제품 판단이 필요해 제안만 남긴 항목 (구현하지 않음)

### 2-1. 🔴 작업 체크 상태가 공고별로 구분되지 않는다 — 관심 공고의 진행률이 사실과 다르게 보일 수 있다

- **재현**: ① 공고 A(부산 금정구)를 분석하고 체크박스 1개를 체크(0/5→1/5). ② 공고 B(비타민스테이션)를 새로 분석. ③ 공고 A의 체크박스가 전부 초기화된다(1/5→0/5). `localStorage`의 `onbid-public-asset-doc-agent-tasks-v1` 키를 직접 조회해 재확인했다.
- **근거(코드)**: `src/app.js:430` `taskStorageKey`가 공고 ID와 무관한 전역 상수 문자열이고, `getTaskState()`/`saveTaskState()`(`src/app.js:706-729`)도 이 전역 키 하나만 읽고 쓴다. 새 공고를 분석할 때마다 `src/app.js:1614`가 `window.localStorage.removeItem(taskStorageKey)`를 무조건 호출해 **다른 공고의 체크 상태까지 함께 지운다.**
- **부작용 2**: 관심 공고 목록의 "X/5 완료" 배지는 `saveRecentNotice()`(공고를 분석한 직후, `src/app.js:1615`)가 그 순간의 진행률을 스냅샷으로 저장한 것이다. 체크박스를 누르는 `saveTaskState()`(`src/app.js:1682`)는 이 스냅샷을 다시 갱신하지 않는다 — 실측으로 부산 금정구 건에서 체크박스 1개를 체크한 뒤에도 관심 공고 목록에는 계속 "0/5 완료"로 떴다.
- **제안만 남기는 이유**: README의 관심 공고 화면 설명("여러 공고의 준비 상태를 남겨 두고, 다음에 확인해야 할 일을 이어서 보는 화면")과 실제 동작이 어긋나는 핵심 기능 결함이지만, 고치려면 로컬스토리지 스키마를 공고 ID 단위로 재구성해야 하고(`getTaskState`·`saveTaskState`·`resetTaskState`·`saveRecentNotice` 4개 함수와 스토리지 버전 키에 걸침), "다시 분석" 시 같은 공고의 체크 상태를 초기화할지 유지할지도 제품 판단이 필요하다. 작은 결함(오타·조건 분기 누락 수준)의 범위를 넘어서서 직접 고치지 않고 제안으로만 남긴다.
- **참고**: `tests/screen.spec.js`의 P0 위험 목록에 "P0-6 저장하지 않은 관심공고를 「2건」으로 셈"이라는 항목이 이미 등재돼 있으나(`tests/screen.spec.js:791`) "축 없음 — 이 게이트가 보지 못한다"로 표시돼 실제 테스트는 없었다. 같은 영역(관심 공고 진행률 표시)의 문제로 보이며, 이번이 최초의 실측 재현이다.

### 2-4. 🔵 `#report` 화면의 목적 배지가 "일치"와 "확인 필요"를 텍스트로 구분하지 않는다
