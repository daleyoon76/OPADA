- 측정: `python3 tests/measure_answer_set.py` — 현행 추출기와 첨부 모의 경로의 항목 단위 재현율

## 스키마

```json
{
  "idx": 1, "pbancMngNo": "…", "assetType": "…",
  "location": "body | attachment | both | none",
  "readSources": ["noticeBodyText", "04_1.txt"],
  "items":    [{"name", "condition", "stage", "copies", "validity", "evidence": {"source", "quote"}}],
  "excluded": [{"text", "reason", "evidence": {"source", "quote"}}],
  "notes": "…"
}
```

- `condition`: 개인 · 법인 · 대리 · 공동 · 미성년 · 외국인 · 전원 · `기타:<설명>`
- `stage`: 입찰전 · 낙찰후 · 계약시 · 불명
- `location`: **items 의 근거가 어디 있는가**만으로 정한다. excluded 근거는 세지 않는다
- `evidence.quote`: 원문에서 복사한 30~120자. 검증기는 공백을 벗긴 뒤 8자 미만을 무효로 본다

## 기준 (작성자 셋이 갈렸던 자리를 팀장이 하나로 정했다)

| 대상 | 기준 | 이유 |
|---|---|---|
| 인감도장·인장·법인인감(도장) | **items** | 사용자가 챙겨 가야 하는 준비물이고, 계약 단계 목록에서 서류와 나란히 「구비서류」로 적힌다 |
| 공동인증서·휴대폰·우표 | excluded | 온비드 이용 전제 조건이나 발송 수단이다. 공고가 요구하는 준비물이 아니다 |
| 입찰방법 절 공통 도움말의 위임장·대리입찰신청서·공동입찰참가신청서 | excluded | 표본 23/23 에 들어 있는 공통 문구다. 공고 자체가 요구할 때만 items |
| 온비드 제출서류 표의 구분명 행(`공동입찰서류`·`-`) | excluded | 서류명이 아니라 구분명이다(표본 15건 전건) |
| 수의계약 절차 서류 | excluded | 입찰 절차 밖이다 |
| 선택 신청서(차액납부·기일연기·전자보증서) | items | `condition` 에 「(선택)」을 적는다 |
| 한 번호로 묶인 서류(「국세 및 지방세 완납증명서」) | 서류마다 나눈다 | 추출기 어휘가 둘을 따로 가진다 |
| 계약 체결 **뒤**에 내는 서류 | `stage: 낙찰후` | 스키마에 「계약후」가 없다. 기한은 `notes` 에 적는다 |

**이 기준은 되돌릴 수 있다.** 특히 인장을 items 로 둔 것은 「준비서류」를 넓게 본 선택이다.
서류(문서)만 세기로 바꾸면 해당 항목을 excluded 로 옮기고 측정을 다시 돌린다.
